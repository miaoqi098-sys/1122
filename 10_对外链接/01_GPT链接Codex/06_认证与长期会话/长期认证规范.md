# 长期认证规范

## 目标

把“每个任务都重新授权”改成“首次建立可信连接，之后长期续期”。

## 推荐模型

```text
ChatGPT / 自定义 MCP 应用
        ↓
OAuth 2.0 / OIDC
        ↓
Authorization Code + PKCE
        ↓
Access Token（短期）
Refresh Token（长期）
        ↓
GPT-Codex Gateway
```

## 核心要求

- 支持 refresh token；
- 支持长期/离线访问能力（例如 `offline_access` 或提供方等效能力）；
- access token 到期时自动刷新；
- refresh token 轮换时原子更新；
- 正常情况下不因新开 GPT 对话重新认证；
- 不把 token 存在聊天、GitHub、源码或普通日志；
- Gateway 只保存受保护的 token/凭证引用。

## 身份绑定

授权对象应绑定到：

```text
owner_account
+ app_id
+ gateway_instance_id
+ device/node identity
```

这样跨对话复用的是同一个长期授权，不是依赖某条聊天记录。

## 新对话流程

```text
新 GPT 对话
↓
发现“亚马逊智能体 Codex 执行器”
↓
已有有效应用授权
↓
直接调用 codex_status / codex_start_task
```

只有以下情况需要重新认证：

- refresh token 被吊销或失效；
- 用户主动断开连接；
- 身份提供方要求重新登录；
- ChatGPT/工作空间权限发生变化；
- Gateway 设备身份被重置。

## Secret边界

长期认证材料与业务 Secret 分开：

- App OAuth凭证：用于 GPT↔Gateway；
- Codex登录凭证：由本机 Codex Runtime 管理；
- Cloudflare/Amazon等业务凭证：进入独立本机 Secret Store；
- GPT 只能按 Secret ID 请求“使用”，不能读取明文。

## 断线恢复

- 网络断线：自动重连；
- access token 到期：自动刷新；
- Gateway重启：从受保护存储恢复会话；
- App Server重启：恢复项目/thread映射；
- 电脑重启：Gateway随用户会话自动启动。

## 验收

必须完成一次真实验证：首次授权 → 执行任务 → 关闭聊天 → 新开聊天 → 不重新输入密钥/不重新建立 GitHub Issue → 再次成功执行 Codex 任务。
