# 健康检查与恢复

## 运行目标

长期连接不是“配置一次就不管”，而是 Gateway 自己维持可用状态。

## 健康状态

固定状态：

- `ONLINE`：Gateway、认证、Codex App Server均正常；
- `DEGRADED`：可服务但部分能力异常；
- `AUTH_REQUIRED`：长期认证无法刷新，需要人工重新认证；
- `CODEX_UNAVAILABLE`：Gateway在线但Codex执行器不可用；
- `OFFLINE`：Gateway不可达。

## 自动恢复

### Gateway
- 随本机用户登录自动启动；
- 进程异常自动重启；
- 崩溃后保留任务账本与幂等键。

### Codex App Server
- Gateway负责启动与监管；
- 非正常退出自动重启；
- 任务中断时按checkpoint恢复或报告明确失败；
- 不因恢复网络而重复执行已经完成的不可重复动作。

### 认证
- access token自动刷新；
- refresh token轮换自动保存；
- 仅在刷新失败时进入`AUTH_REQUIRED`。

### 网络
- 有界重连与退避；
- 网络恢复后恢复事件通道；
- 已完成任务不能因重连被再次执行。

## 任务账本

每个任务至少保存：

```text
task_id
idempotency_key
project_id
conversation_id
codex_thread_id
status
created_at
started_at
completed_at
last_event_at
result_ref
error_class
```

不把完整 Secret 或认证 Token写入任务账本。

## 本地恢复优先级

```text
Gateway健康
  ↓
长期认证健康
  ↓
Codex App Server健康
  ↓
项目根目录可访问
  ↓
任务继续/新任务
```

## 不依赖项

运行恢复不得依赖：

- AACC；
- AACC CodexBridge；
- AACC LocalOps；
- GitHub Issue；
- 旧 GPT 对话内容。

GitHub不可用时，本地 Gateway 与已经建立的 GPT 应用连接设计上仍应继续运行；只有需要 pull/push 等 GitHub 本身功能时才受 GitHub状态影响。

## 长期验收场景

最终至少做以下真实验收：

1. 正常新对话执行；
2. 关闭对话再新开对话执行；
3. Gateway进程重启后执行；
4. Codex App Server崩溃后自动恢复；
5. 电脑重启后恢复；
6. access token过期后自动刷新；
7. GitHub暂时不可用时执行一个不依赖GitHub的本地任务；
8. AACC完全停止时仍能执行；
9. 真实工程修改、测试、结果回传完成。

只有上述真实运行证据通过后，才能声明 `GPT_CODEX_LONG_TERM_LINK_VERIFIED = true`。
