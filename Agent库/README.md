# Agent库

## 定位
`Agent库/` 保存亚马逊运营体系中的正式业务智能体定义。当前正式业务Agent集中在 `运营组/`，Agent库只描述“每个Agent应该知道什么、判断什么、输出什么、与谁协作以及需要哪些未来工具数据”，不承载真实Runner、API、数据库、调度器或执行器实现。

## 总体结构
当前运营组由13个Agent组成：
- Agent-1｜运营总控智能体：唯一最终经营决策出口；
- Agent-2｜商品状态智能体；
- Agent-3｜竞品情报智能体；
- Agent-4｜广告运营智能体；
- Agent-5｜流量分析智能体；
- Agent-6｜利润财务智能体；
- Agent-7｜库存供应链智能体；
- Agent-8｜市场趋势智能体；
- Agent-9｜内容转化智能体；
- Agent-10｜促销价格智能体；
- Agent-11｜评价体验智能体；
- Agent-12｜风险合规智能体；
- Agent-13｜增长机会智能体。

运营组同时包含 `公共协议/`：用于定义跨Agent统一交接、职责覆盖和协作路由，不属于任何单一专业Agent私有领域模型。

## 决策关系
Agent-2至Agent-13均为专业岗位，输出专业事件、请求响应、证据、约束或机会，不直接形成跨域最终决策。

统一关系：
`专业事实/领域事件/领域响应 → 公共协议规范化 → Agent-1 Canonical输入 → 上下文/冲突/排序/方案/风险 → FinalDecision → Task → 执行/验证/学习`

Agent-12的风险资格门可以阻断、要求审批或要求补证据，但 `eligible` 不等于“应该执行”；最终方案仍由Agent-1按目标系统和经营状态选择。

## 公共协议
正式入口：`运营组/公共协议/README.md`

当前已定义：
- 专业Agent领域事件 → Agent-1标准智能事件包；
- 专业Agent领域响应 → Agent-1专业Agent结构化结果；
- Agent-1至13职责覆盖矩阵；
- 跨Agent协作路由与典型场景；
- L5公共对象、职责与协作静态验收记录。

## 公共原则
1. 所有高影响结论必须保留scope、时间、新鲜度、证据和置信度；
2. 动态平台规则必须版本化，不能把历史经验写成永久常量；
3. 专业Agent不越权执行其他Agent职责；
4. 相同业务事实由主责Agent维护，其他Agent通过引用消费；
5. 领域对象可以不同构，但进入Agent-1前必须满足公共交接协议；
6. 真实运行/API/数据库/调度/执行属于共享基础设施；
7. Agent-1是唯一最终经营决策出口；
8. 静态框架完成不等于生产运行完成。
