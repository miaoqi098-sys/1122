# 测试与示例

## 静态验收目标
验证 Agent-12 能把事实映射到版本化规则、输出资格门、组织证据/整改结构，并保持不伪造法律/平台结论。

## 必测场景
1. Listing前台变狗且后台显示资质审核：Agent-2提供状态，Agent-12识别DOCUMENT_REVIEW_RISK并要求官方通知/资料清单；
2. 含电池商品被危险品审核：输出DANGEROUS_GOODS_RISK，规则/文件不足时 `requires_more_evidence`；
3. Listing出现医疗/绝对化claim：输出CONTENT_CLAIM_RISK并要求Agent-9提供具体内容版本；
4. 收到商标投诉：输出IP_RISK，但在权利/授权事实不全时不下法律结论；
5. 多条评价短期异常：Agent-11提供异常模式，Agent-12检查评价政策，不能直接写“竞对操纵已确认”；
6. 安全VOC低频但涉及伤害：severity可high/critical并阻断相关扩量动作；
7. 资质文件名称存在但已过期：不得判定合规已满足；
8. 历史申诉成功但当前政策版本已变化：重新验证，不复用旧结论；
9. 整改计划已写但尚未执行：状态不得resolved；
10. 明确禁止项与高利润增长方案冲突：风险资格门优先阻断，最终由Agent-1处理其他目标。

## 示例A｜资质审核
官方通知要求某文件，但当前只有旧版本文件。正确：`requires_more_evidence`，列出缺失证据、有效期和下一步，不伪称审核可通过。

## 示例B｜异常评论
评论时间集中且文本相似。正确：将Agent-11异常信号映射到REVIEW_POLICY_RISK候选，需当前规则与更多证据；不得直接提交举报或定性。

## 示例C｜内容claim
副图写“100% safe / cures ...”等高风险表达。正确：绑定内容版本和当前适用政策/监管规则，可能设为requires_approval/prohibited；修改由Agent-1决策后进入执行层。

## 验收判定
- 规则版本化；
- 事实异常与违规结论分离；
- 资格门与Agent-1决策规则一致；
- 证据/整改/申诉结构真实可追溯；
- 高影响结论有来源与时间；
- 不伪造文件、法律意见或平台裁定；
- 真实提交/执行留在运行层。
