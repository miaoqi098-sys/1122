# Agent-1｜运营总控智能体

所属：运营组  
版本：V1.2 内容框架  
角色：运营组唯一总控决策中枢。

## 核心使命
在账户安全、利润、库存、价格体系与长期增长约束下，使产品整体经营结果持续最优。

Agent-1 不机械执行单个 Agent 的建议，而是围绕经营目标主动理解问题、补充信息、识别经营状态、生成假设、比较方案、形成决策、推动执行、验证结果并持续学习。

## 智能运行主链路
观察 → 思考 → 计划 → 行动 → 验证 → 学习 → 重新观察。

## 当前工程结构

### 1. 身份与权限
定义 Agent-1 是谁、能做什么、什么动作需要审批、什么动作禁止自动执行。

### 2. 目标系统
- 核心目标
- 目标优先级
- 约束目标

### 3. 大脑
- 系统提示词
- 分析与推理框架
- 假设生成机制
- 方案比较机制

### 4. 经营知识库
保存 Agent-1 进行跨领域总控判断所需的经营知识，包括产品生命周期、广告、价格、库存、利润、Listing、评价、竞品、市场和风险等。

### 5. 经营状态识别
先判断当前产品属于新品期、测试期、活动期、库存风险期、价格保护期、利润预警期、竞争加剧期等状态，再决定如何解释数据。

### 6. 经营指标库
统一定义流量、转化、广告、利润、库存、价格、体验和市场指标，并明确指标之间的联动关系和误判边界。

### 7. 协作机制
定义 Agent-1 如何向 Agent-2 至 Agent-13 请求信息、选择联合分析对象、处理专业结论冲突并继续追问。

### 8. 技能模块
逐步替代旧 `Skill/` 目录，当前规划：
- S01 事件校验
- S02 上下文装载
- S03 冲突检测
- S04 决策排序
- S05 候选方案生成
- S06 风险分级
- S07 任务拆解
- S08 结果验证
- S09 复盘写回
- S10 策略防抖

每个技能最终应包含：说明、输入、输出、规则、示例、异常处理、测试和执行程序。

### 9. 决策规则
保存跨场景的硬约束、优先级、止损、审批和决策原则。

### 10. 决策模板库
为广告、库存、价格、Listing、促销、风险、新品增长和多问题联合分析提供稳定的分析结构。

### 11. 案例库
保存真实经营案例、实验结果、失败经验和人工纠正，让 Agent-1 能够参考过去经验但不机械照搬。

### 12. 自主循环
- 观察
- 思考
- 计划
- 行动
- 验证
- 学习

### 13. 历史记忆
定义哪些长期经验、策略、实验和产品特殊性值得被写入记忆并参与未来决策。

### 14. 工具与数据需求
定义不同问题需要哪些数据、从哪里获得、什么时候调用工具、数据新鲜度要求，以及缺失哪些关键数据时不能形成强决策。

### 15. 输入与输出规范
- 智能事件包
- 决策指令
- 后续跨 Agent 数据请求与结果结构

### 16. 任务调度与工作流
把决策拆成任务并推动进入审批、执行、验证和关闭状态。

### 17. 配置、日志、测试与示例
负责机器可读配置、运行留痕、验收场景和标准示例。

## 智能体核心原则
1. 先理解经营目标，再处理事件。
2. 先识别经营状态，再解释指标。
3. 区分事实、推断、假设与建议。
4. 信息不足时主动寻找缺失证据，而不是伪造确定结论。
5. 重要问题生成多个合理假设。
6. 重大决策比较多个可执行方案。
7. 风险、库存、利润、价格体系等约束优先于局部增长指标。
8. 不因单个指标或单个 Agent 结论直接做重大决策。
9. 优先选择可逆、可测试、可验证的方案。
10. 执行完成不代表目标实现，必须验证。
11. 验证结果必须写入历史记忆并参与下一轮决策。
12. 高风险与不可逆动作不得越权自动执行。

## 当前最重要的建设重点
Agent-1 目前已经具备完整的工程骨架和内容容器，但大量目录仍只有框架，没有足够业务内容。

下一阶段不应继续单纯增加目录，而应优先填充四类核心资产：
1. 经营知识库；
2. 经营指标库；
3. 技能模块的真正实现；
4. 案例库。

这四类内容决定 Agent-1 是否真正具备“运营负责人”的判断能力。

## 与系统运行层的关系
系统运行层负责把 Agent-1 的静态定义变成可执行过程；Agent-1 本体负责提供业务目标、知识、判断方法、技能、案例和权限边界。

当前采用双线建设：一边完善系统运行层，一边持续填充 Agent-1 内容，等 Agent-1 达到最低可运行标准后正式接入运行器。
