# Agent-1 事件优先级

## 1. severity定位
Event 的 P0-P3 表示事件信号的严重度/紧迫度，用于事件处理、升级与响应时效；它不等同于 S04 对 DecisionItem 输出的 `business_priority`。

### P0｜紧急事件
典型：账户安全、商品不可售、重大合规、严重价格错误、完全断货、关键系统/数据异常直接影响经营安全。

处理：
- 快速进入总控事件链；
- 必要时触发Priority Gate blocked/escalated；
- 请求缺失的专业证据；
- 审批是否需要由S06/FinalDecision.approval决定，不再使用旧“默认L2/L3审批”表述。

### P1｜高严重度
明显影响销售、利润、库存、价格体系、客户体验或核心流量资产，延迟处理可能造成实质损失。

### P2｜常规
需要分析或优化，但短期不构成经营底线风险。

### P3｜观察
趋势、弱信号、机会、尚未达到行动门槛的变化。

## 2. severity升级/降级触发
可基于：
- 新证据强度变化；
- 影响范围扩大/缩小；
- deadline/opportunity window接近；
- 从单对象扩散到账户/店铺；
- guardrail/stop condition触发；
- 原事件被证伪或影响解除。

变化必须记录 previous_severity / current_severity / change_reason / evidence_refs。

## 3. 与S04 business_priority边界
对应DecisionItem的业务优先级由S04决定，综合：目标层级、经营状态、风险窗口、依赖、机会、证据、资源等。

因此：
- P0 Event 通常产生高优先处理，但若是重复、已解决或证据不足，可以被去重/降级/补证据；
- P3 Event 可能因机会窗口、战略目标或依赖关系形成P1/P2 DecisionItem；
- 不允许直接复制 Event severity 为 business_priority 而跳过S04。

## 4. 来源建议与最终确认
专业Agent可以建议severity；S01可做一致性警告；事件处理模块可依据证据调整事件severity。真正经营待决事项的最终业务优先级仍由S04形成。

## 5. 禁止
- severity=P0就自动执行高影响动作；
- 用severity替代eligibility/approval；
- 无新证据频繁升降级；
- 把重复上报次数直接当作严重度证据。
