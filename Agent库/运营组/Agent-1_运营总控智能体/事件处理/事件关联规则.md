# 事件关联规则

## 1. 目的
当事件不能去重或合并，但存在明确业务关系时，通过关联保持上下文连续性。

## 2. 关联类型
- `same_scope`：同一业务对象；
- `parent_child_scope`：父体/子体、账户/商品等层级关系；
- `temporal`：时间上连续或相邻；
- `causal_candidate`：可能存在因果但尚未证实；
- `same_strategy_chain`：影响同一StrategyChain；
- `same_decision_item`：共同支撑同一待决事项；
- `conflicting_evidence`：事实/结论相互冲突；
- `dependency`：一个事件影响另一个事件的处理条件；
- `follow_up`：后续验证/结果事件。

## 3. 关联记录
每条关系至少保留：
- source_event_id；
- target_event_id；
- relation_type；
- reason；
- evidence_refs；
- confidence（适用时）；
- created_at。

## 4. 因果谨慎
`causal_candidate` 只表示待验证因果假设，不能因为两个事件先后发生就直接标记“由A导致B”。

## 5. StrategyChain关系
事件若与运行中策略有关，应保留strategy_chain_id或可追溯到相关decision/task；但事件本身不直接修改StrategyChain状态。

## 6. 冲突关系
不同来源给出相反事实时，优先建立conflicting_evidence关系并交S03/后续证据判断，不得通过合并删除一方。

## 7. 禁止
- 只因同一ASIN就认为事件因果相关；
- 把相关性直接当因果；
- 关联后删除独立event_id；
- 用related_events数组替代真正需要的冲突处理。
