# 事件去重规则

## 1. 目的
防止同一事实被不同时间、不同来源或重复上报无限生成事件与决策链，同时保留完整来源和证据历史。

## 2. 去重判断维度
至少比较：
- scope / 业务对象；
- event_type；
- 核心事实；
- occurred_at 与时间窗口；
- source/evidence refs；
- severity；
- 关键指标变化方向；
- 是否属于同一 StrategyChain/DecisionItem。

## 3. 结果分类
- `exact_duplicate`：同一事实重复上报；
- `near_duplicate`：核心问题相同但来源/窗口略有差异；
- `update_existing`：同一事件出现新证据或状态变化，应更新已有事件；
- `related_not_duplicate`：相关但不能合并；
- `new_event`：独立新事件。

## 4. exact_duplicate
处理：
- 不创建新canonical事件；
- 新event_id保留在source/duplicate记录；
- 指向 `duplicate_of=canonical_event_id`；
- 追加source/evidence refs；
- 不重复触发DecisionItem，除非新上报包含会改变判断的证据。

## 5. near_duplicate
必须判断差异是否会改变：
- severity；
- scope；
- root problem；
- deadline/opportunity window；
- eligibility/风险；
- 当前策略方向。

若不会改变，归入已有事件；若会改变，使用update_existing或独立相关事件。

## 6. 新证据不是重复
同一问题但出现：
- critical_new_fact；
- scope扩散；
- severity实质变化；
- 新时间窗口；
- 原事件resolved后再次真实发生；
不能仅因event_type相同就压成重复。

## 7. S01 duplicate_signal
S01只提供初筛信号。事件处理必须重新结合上下文确认最终去重状态，不能把S01 possible duplicate自动当作exact_duplicate。

## 8. 禁止
- 删除重复事件历史记录；
- 用summary文本相同作为唯一去重条件；
- 多来源重复上报次数直接提高severity；
- 已经有同类事件就拒绝所有后续新证据。
