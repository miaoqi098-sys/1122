# 事件处理示例与静态验收

## 示例A｜同一广告异常重复上报
Agent-4在10分钟内重复上报同一关键词、同一窗口、同一事实。

正确处理：第二条标记exact_duplicate，保留新event_id/source_ref并指向canonical_event_id；无新证据则不重复触发DecisionItem。

## 示例B｜同一问题出现新证据
原事件P2，后续发现scope从单ASIN扩散到整个店铺。

正确处理：update_existing或建立强关联新事件；severity可升级并记录change_reason/evidence_refs，不得压成普通重复。

## 示例C｜合规风险与增长机会同时发生
两事件同ASIN但目标层级和动作方向不同。

正确处理：保持独立并建立same_scope/可能冲突关系，不合并成单一平均事件；后续由S03/S04处理冲突和优先级。

## 示例D｜已关闭事件再次发生
前一周期库存风险已关闭，一个月后再次发生。

正确处理：若是新周期独立事实，创建new_event并建立follow_up关系，而不是无限reopened旧event_id。

## 示例E｜P0事件与DecisionItem优先级
账户风险Event severity=P0。

正确处理：快速进入事件链并可能触发Priority Gate；但对应DecisionItem仍由S04形成business_priority，不能简单复制severity字段。

## 静态验收
- [x] event severity与S04 business_priority分离。
- [x] S01 duplicate_signal只作为初筛，不直接决定exact_duplicate。
- [x] 去重保留原event_id和证据引用。
- [x] 合并保留差异与来源，不粗暴平均severity。
- [x] 关联支持scope/时间/策略链/冲突证据/follow_up。
- [x] 生命周期覆盖open/updated/resolved/closed/reopened与duplicate/merged。
- [x] resolved/closed事件无新证据不得重复触发相同DecisionItem。
- [x] 异常路径覆盖来源冲突、延迟、对象缺失、无法标准化和升级/降级。
- [x] 事件处理不越权形成FinalDecision或执行动作。
