# Agent-1 任务生命周期

## 1. 正式状态机

```text
created
↓
pending_approval
↓
ready
↓
running
├─ blocked
├─ failed
├─ cancelled
└─ awaiting_validation
       ↓
   completed
   rolled_back
```

说明：
- 不需要审批的任务可从 `created` 直接进入 `ready`；
- `blocked` 可在阻塞条件解除后返回 `ready` 或 `running`；
- `failed` 不等于 `blocked`，表示已经尝试执行但失败；
- `awaiting_validation` 表示动作已完成但经营结果尚未完成验证；
- `completed` 只有在规定验证通过后成立；
- `rolled_back` 表示回滚动作已完成并有结果证据，不是“计划回滚”。

## 2. created
S07完成任务编排后创建Task。此时只代表任务定义存在，不代表已获得审批、已调度或可执行。

至少应保留：
- task_id
- task_plan_id
- decision_id
- decision_item_id
- scope
- task_type
- owner / executor / approver / validator
- source_action_id / option_id（可用时）
- priority引用
- dependencies
- start_condition / stop_condition
- success_criteria
- rollback_condition
- observation_window / validation_requirements（适用时）

## 3. pending_approval
存在FinalDecision.approval或Task级审批要求且尚未满足时进入。

审批通过 → ready；审批拒绝 → cancelled或回到上游重新决策，不得自动越权执行。

## 4. ready
所有前置条件、依赖、审批、required_controls均满足，且执行能力已确认，才可ready。

ready不等于已经开始执行。

## 5. running
Executor或人工流程已开始执行。

running期间若出现条件不满足、外部依赖中断，可进入blocked；已实际尝试但动作失败则进入failed。

## 6. blocked
尚未满足执行条件或运行中被外部条件阻断，例如：
- 前置Task未完成；
- 审批/权限上下文临时缺失；
- 必须数据未到；
- 互斥任务占用；
- stop/guardrail要求暂停。

必须记录blocked_reason和release_condition。

## 7. failed
任务已经真实尝试执行但失败。

必须记录：
- failure_reason；
- execution_result_ref；
- retry_eligibility；
- 是否需要重新审批/重新决策；
- 是否触发rollback。

## 8. cancelled
任务在完成前被明确取消，不代表执行失败。取消必须有原因和来源决策/审批/策略替代引用。

## 9. awaiting_validation
动作执行完成，但尚未通过S08或定义的验证要求。

例如广告竞价已调整，只能说明动作成功提交；经营效果需经过观察窗口验证后才能completed。

## 10. completed
满足success_criteria和必要ValidationResult后进入。若只完成动作但未验证结果，不得completed。

## 11. rolled_back
回滚任务/回滚动作已真实完成，并保留rollback_reference与执行结果。

## 12. 状态变化追溯
每次状态变化应保留：
- previous_status
- current_status
- changed_at
- change_reason
- actor/executor/system_ref
- evidence/execution_result/validation refs

## 13. 禁止
- 强制所有任务绑定产品/ASIN；正式作用域使用scope。
- 把owner同时当executor/approver/validator而不区分职责。
- Executor返回成功后直接completed。
- blocked与failed混用。
- cancelled覆盖历史记录。
- rolled_back只记录“建议回滚”而没有实际回滚结果。
