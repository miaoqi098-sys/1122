# 共享调度与执行边界

## 1. Agent-1 当前负责
Agent-1 / S07 / 任务调度模块负责定义：
- TaskPlan与TaskGraph；
- 任务业务优先级引用；
- depends_on / blocks / parallel_with / mutex_with；
- 审批、control、monitoring、validation、rollback需求；
- start/stop/success/rollback条件；
- owner/executor/approver/validator角色要求；
- 何时理论上可以ready、blocked、awaiting_validation。

## 2. R07 Scheduler未来负责
真实共享调度器未来负责：
- 保存并推进任务队列；
- 定时器/事件触发；
- 唤醒ready任务；
- 根据资源/并发能力实际安排运行；
- 持久化运行状态；
- 运行层重试、超时、心跳与调度日志；
- 按TaskGraph执行依赖约束。

Scheduler不得修改FinalDecision的业务方向或自行换Option。

## 3. R08 Executor未来负责
真实执行器未来负责：
- 调用Amazon API或其他工具；
- 进入人工执行流程；
- 做权限/幂等/参数校验；
- 返回真实执行回执；
- 不伪造经营结果。

Executor不得把“API成功”解释为“业务目标达成”。

## 4. R09 ExecutionResultNormalizer
不同执行器回执未来应归一为ExecutionResult，再进入S08。Agent-1任务规则不直接解析每种API的私有返回结构。

## 5. 状态所有权
框架定义状态语义；真实运行状态由未来共享运行层维护。Agent-1不能仅依据计划文本声称任务已running/completed/rolled_back。

## 6. 优先级所有权
Task应继承/引用FinalDecision与DecisionItem业务优先级，但Scheduler可根据资源、互斥、deadline做运行排序；这种运行排序不得修改S04的业务优先级事实。

## 7. 禁止
- 在Agent库实现真实定时器/队列/API执行；
- Scheduler自行进行经营决策；
- Executor自行选择替代Option；
- 运行层状态覆盖业务历史；
- Agent-1在无ExecutionResult情况下宣称执行成功。
