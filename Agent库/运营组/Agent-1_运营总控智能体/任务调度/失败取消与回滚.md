# 失败、取消与回滚

## 1. blocked 与 failed
- `blocked`：尚未满足执行条件，或运行中被外部条件临时阻断；不表示已经执行失败。
- `failed`：已发生真实执行尝试，且执行未成功。

两者必须分开记录，避免把“等审批/等数据”误算成执行失败。

## 2. failed记录
至少保留：
- failure_reason；
- execution_result_ref；
- failed_at；
- executor/system_ref；
- retry_eligibility；
- retry_constraints；
- rollback_required；
- escalation_required。

## 3. retry边界
是否重试由运行层未来执行，但框架必须定义：
- 是否幂等；
- 是否需要重新审批；
- 是否上下文已变化；
- 是否会重复产生经营副作用；
- 最大尝试限制应由运行配置管理。

禁止Agent-1在框架层假装自动无限重试。

## 4. cancelled
cancelled表示任务在完成前被明确终止。典型原因：
- FinalDecision被supersede；
- S10 override后旧Task不再适用；
- 审批拒绝；
- 目标/状态变化导致任务失效；
- 依赖项取消且无替代路径。

取消必须保留cancel_reason、source_decision/approval/stabilization引用。

## 5. rollback触发
回滚可由：
- rollback_condition；
- stop_condition；
- guardrail；
- critical risk；
- ValidationResult显示不可接受结果；
- 新FinalDecision明确要求。

触发回滚不等于已经rolled_back。

## 6. rollback Task
S07应在适用时生成rollback Task或rollback计划引用。真实回滚由Executor执行。

只有真实回滚动作完成、有ExecutionResult，并完成必要验证后，原任务/策略才能标记rolled_back。

## 7. 验证失败与回滚
S08验证失败时可能产生：
- 继续观察；
- 新诊断；
- 新Decision；
- rollback建议/任务。

不应无条件自动回滚，除非原FinalDecision已定义明确stop/rollback条件且触发证据充分。

## 8. 禁止
- blocked当failed；
- failed后无限重试；
- cancelled删除历史；
- “建议回滚”直接标记rolled_back；
- rollback绕过审批/权限或新的安全条件。
