# 任务调度示例与静态验收

## 示例A｜带审批与控制的执行Task
FinalDecision选择 `eligible_with_controls` 方案，并要求预算上限与人工审批。

正确编排：
```text
approval task
↓ blocks
control task（设置预算上限）
↓ depends_on
execution task
↓
monitoring task
↓
validation task
```
执行Task在审批与control完成前不得ready。

## 示例B｜互斥价格动作
Task-A降低价格，Task-B恢复原价格，目标对象相同且不能同时执行。

正确处理：建立 `mutex_with`；若新FinalDecision明确supersede旧方向，由S07根据新决策生成旧Task取消/替代安排，而不是Scheduler自行删除Task。

## 示例C｜blocked与failed
- 等审批：blocked/pending_approval，不是failed；
- API已经调用但返回错误：failed，并引用ExecutionResult。

## 示例D｜动作成功但效果待验证
广告竞价修改API成功后：Task进入awaiting_validation，而非completed；观察窗口结束后由S08判断经营效果。

## 示例E｜验证触发回滚
观察期间guardrail触发。

正确处理：进入复核/rollback路径；只有真实rollback Task执行完成并有ExecutionResult后才能rolled_back。

## 示例F｜循环依赖
A depends_on B，B depends_on C，C depends_on A。

正确处理：TaskPlan不能ready，标记dependency_error并回S07修订；Scheduler不得自行猜测删除依赖。
