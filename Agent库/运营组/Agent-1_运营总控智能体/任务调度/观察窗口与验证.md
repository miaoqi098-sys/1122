# 观察窗口与验证

## 1. 定位
本规则定义执行任务之后何时进入观察、需要什么证据才能完成，以及如何衔接S08验证。它不实现定时器或真实验证程序。

## 2. 观察窗口
Task可定义：
- observation_window；
- review_at / review_trigger；
- minimum_data_requirement；
- success_criteria；
- stop_condition；
- guardrail；
- validation_requirements。

观察窗口必须与业务动作特性匹配，不应所有任务统一固定天数。

## 3. monitoring Task
当经营结果需要时间才能显现时，S07应生成monitoring Task或明确观察条件。

例如：
- 广告竞价调整后观察点击/转化；
- 价格变更后观察转化和价格体系；
- 内容改版后观察流量/转化；
- 库存动作后观察可售/在途变化。

## 4. awaiting_validation
执行动作完成后，如果仍需经营结果验证，Task进入awaiting_validation，而非completed。

S08验证需要至少消费：
- task/execution_result引用；
- success_criteria；
- observation_window；
- actual_outcome；
- guardrail/stop condition结果。

## 5. 提前终止观察
出现以下条件可提前结束正常观察并进入复核/回滚/新决策：
- stop_condition触发；
- guardrail触发；
- critical risk；
- 数据源确认失效；
- 目标或经营状态发生重大变化。

不能因为单日噪声任意提前反向操作。

## 6. completed条件
只有：
- 必要执行动作完成；
- 观察要求满足；
- success_criteria通过，或ValidationResult明确允许完成；
- 未触发必须回滚/继续观察条件；
才可completed。

## 7. 验证失败
验证失败不直接等价Task failed。执行动作可能成功但经营结果未达标，此时应：
- 记录ValidationResult；
- 判断继续观察、rollback、重新诊断或新Decision；
- 保留原Task执行事实。

## 8. 禁止
- ExecutionResult success = Task completed；
- 未到最小观察窗口且无stop/guardrail就频繁反向；
- 缺数据时把“没有效果”当作验证失败；
- 为所有业务动作使用同一个固定观察期。
