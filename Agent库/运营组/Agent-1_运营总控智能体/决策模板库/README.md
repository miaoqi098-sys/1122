# 决策模板库

## 1. 定位

决策模板库用于沉淀 **Agent-1 在高频经营决策场景中的标准决策组织结构**。

它解决的不是“算法怎么做”，而是：

> 当 Agent-1 面对某一类经营问题时，应按什么稳定结构组织事实、目标、状态、约束、方案、风险、审批、任务、观察与回滚，才能形成可追溯、可复核、可复用的最终决策。

模板是 **场景化决策骨架**，不是固定答案、固定动作或固定优先级。

---

## 2. 与技能模块的关系

决策模板库不重复 S04/S05/S06 等技能职责：

- S04 决策排序：决定 DecisionItem 的业务优先级；
- S05 方案生成：生成可执行候选方案；
- S06 风险评估：评估方案风险、资格与审批要求；
- DecisionSelector：在上下文、方案和风险结果基础上形成 FinalDecision；
- 决策模板库：为不同经营场景规定上述对象应该关注哪些事实、约束、比较维度、观察与回滚要求。

因此模板不能自建另一套“决策算法”，也不能绕开 canonical 对象链。

---

## 3. Canonical 对象链

模板统一围绕以下主链工作：

```text
DecisionItem
+ ContextPackage
+ Options
+ RiskAssessment
+ StrategyChain / ActiveTasks（需要时）
↓
DecisionSelector
↓
FinalDecision
↓
S07 Task / TaskGraph
↓
ExecutionResult
↓
ValidationResult
↓
LearningRecord
```

关键引用链：

```text
decision_item_id
→ option_id
→ decision_id
→ task_plan_id
→ task_id
→ execution_result_id
→ validation_id
→ learning_id
```

`strategy_chain_id` 跨策略生命周期使用。

模板不得另造与 `FinalDecision` 并行的最终决策对象。

---

## 4. 模板解决什么

每个模板至少规定：
- 适用经营问题；
- 典型触发信号；
- 必须读取的上下文；
- 关键经营状态；
- 关键指标与证据；
- 必须检查的约束；
- 缺失信息与降级路径；
- 需要参与的专业 Agent；
- 候选方案最低结构；
- 方案比较维度；
- 风险与审批关注点；
- 形成 FinalDecision 时必须说明的决策依据；
- S07 任务编排要求；
- 观察窗口；
- 成功标准；
- 停止/止损/回滚条件；
- 复核与学习触发条件。

---

## 5. 模板不解决什么

模板库不负责：
- 代替目标系统决定当前业务目标；
- 代替 S04 做统一优先级排序；
- 代替 S05 直接产出唯一方案；
- 代替 S06 判断风险资格；
- 代替经营知识库保存领域知识；
- 代替经营指标库定义指标口径；
- 代替历史记忆保存事实历史；
- 代替案例库保存完整历史案例；
- 代替专业 Agent 做领域监控与分析；
- 直接执行广告、价格、库存或 Listing 动作。

## 6. 当前正式模板域

计划按经营问题建立以下模板域；对应目录只在各域任务开始、确认职责后创建：

1. 广告决策模板
2. 库存决策模板
3. 价格促销决策模板
4. 利润决策模板
5. Listing与转化决策模板
6. 风险合规决策模板
7. 评价体验决策模板
8. 竞品与市场决策模板
9. 多Agent冲突决策模板
10. 综合经营决策模板

模板域之间允许组合，但不得复制同一规则形成多份事实来源。

## 8. 使用原则

- 模板是分析结构，不是固定结论；
- 当前目标、经营状态、风险与证据优先于模板惯例；
- 模板只能约束“必须检查什么”，不能强行规定“最后必须做什么”；
- 缺失关键证据时必须进入 `request_more_evidence / hold_for_review` 等降级路径，而不是填空式得出结论；
- 正在运行的策略发生明显改变时，应对齐 S10 策略防抖；
- 重大动作必须有观察窗口、成功标准和回滚条件；
- 模板更新必须保留版本与替代关系，避免历史决策无法解释。
