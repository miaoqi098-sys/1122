# 决策模板统一字段

## 1. 目的

本文件定义所有决策模板共同遵守的字段语义，解决不同经营模板各自命名、各自引用、各自扩展导致的长期分叉问题。

模板字段分为两类：

1. **模板治理字段**：描述“这个模板是什么、何时可用、版本如何治理”；
2. **业务对象引用字段**：描述“这个模板在一次决策中需要读取哪些 canonical 对象和引用”。

模板不得复制 canonical 业务对象的完整字段定义。

---

## 2. 模板治理字段

| 字段 | 必填 | 语义 |
|---|---:|---|
| template_id | 是 | 模板稳定唯一ID，不随文件名变化 |
| template_name | 是 | 人类可读名称 |
| template_version | 是 | 模板版本，例如 `1.0.0` |
| template_status | 是 | `draft / active / deprecated / retired` |
| domain | 是 | 广告、库存、价格促销等模板域 |
| description | 是 | 模板解决的经营问题 |
| owner_agent | 是 | 当前固定为 `Agent-1`，表示最终决策模板归属 |
| supported_item_types | 是 | 可处理的 DecisionItem.item_type 集合 |
| supported_scopes | 是 | 支持的 Scope 类型集合 |
| trigger_patterns | 否 | 常见触发模式，不等于固定阈值 |
| applicable_states | 否 | 可适用经营状态 |
| exclusion_conditions | 否 | 明确不能使用的条件 |
| required_context | 是 | 必须存在的上下文语义 |
| required_metrics | 否 | 必须读取的指标语义/引用 |
| required_evidence | 是 | 最低证据要求 |
| required_agent_inputs | 否 | 需要哪些专业Agent输入 |
| required_constraints | 否 | 必须检查的约束类型 |
| key_questions | 是 | 本模板必须回答的关键问题 |
| option_comparison_dimensions | 是 | 方案比较维度 |
| risk_focus | 是 | 风险关注点 |
| approval_focus | 否 | 审批关注点 |
| task_requirements | 是 | 进入S07前必须表达的任务化要求 |
| observation_requirements | 是 | 观察窗口和验证要求 |
| rollback_requirements | 是 | 停止/回滚要求 |
| review_triggers | 否 | 触发重新决策的条件 |
| learning_focus | 否 | S09应重点沉淀的经验主题 |
| supersedes | 否 | 被本模板替代的模板版本 |
| tags | 否 | 检索标签 |

## 3. Canonical 业务引用

模板只声明“需要什么”，不复制对象本体。

### DecisionItem
必须引用：
- `decision_item_id`
- `item_type`
- `problem_definition`
- `objective`
- `goal_layer`

按需读取：severity、urgency、state_relevance、target_deviation、conflict_refs、constraint_refs、evidence_refs、source_event_refs、context_refs、reversibility、evidence_strength、opportunity_window。

### ContextPackage
模板通过上下文需求声明读取：
- 目标；
- 当前经营状态；
- 约束；
- 知识；
- 历史；
- 当前活动/任务；
- 时间与新鲜度信息。

模板不应自行保存 ContextPackage 副本。

### Options
模板声明：
- 方案至少应覆盖哪些动作维度；
- 方案比较必须关注哪些维度；
- 哪些方案类型在本场景被禁用。

具体候选方案仍由 S05 生成。

### RiskAssessment
模板声明本场景必须重点检查的风险类别、资格条件和审批条件；风险结论仍由 S06 产生。

### FinalDecision
模板必须保证最终可映射到：
- `decision_id`
- `decision_item_id`
- `business_priority`
- `selected_option`
- `risk_assessment`
- `decision_basis`
- `approval`
- `strategy_chain_id`
- `supersedes_decision_id`
- `rollback_reference`
- `decision_confidence`
- `created_at`
- `valid_until`
- `review_trigger`

---

## 4. decision_basis 最低要求

每个模板必须引导最终决策至少说明：
- `why_selected`：为什么选择该方案；
- `why_not_others`：为什么不选择主要替代方案；
- `goal_alignment`：与当前目标如何一致；
- `state_alignment`：与当前经营状态如何一致；
- `conflict_refs`：关键冲突引用；
- `evidence_refs`：关键事实证据；
- `knowledge_refs`：使用了哪些经营知识；
- `historical_refs`：使用了哪些历史经验/决策。

模板可以增加场景化解释要求，但不能减少 canonical 最低语义。

---

## 5. Scope 规则

模板不得把“产品模板”理解成只适用于 ASIN。

`supported_scopes` 应从系统统一 Scope 语义中选择，例如：
- account
- store
- global
- parent_product
- product
- sku
- campaign
- ad_group
- keyword
- task
- decision
- other

一个模板可以支持多个 Scope，但必须说明其对象边界。

---

## 6. 证据字段规则

模板只能声明证据要求，不得伪造证据值。

最低区分：
- required：没有则不能形成稳定结论；
- preferred：缺失时可降低置信度继续；
- optional：用于增强判断，不阻塞。

证据必须尽量保留引用，而不是把事实复制成无法追溯的文本。

---

## 7. 状态字段规则

`applicable_states` 用于声明模板与生命周期/情境/风险/机会状态的适配关系。

禁止在模板中重新定义一套产品生命周期或风险状态枚举。

模板只引用 `经营状态识别` 的正式状态语义。

---

## 8. 指标字段规则

`required_metrics` 只保存指标ID/名称/用途/最低新鲜度要求等引用信息。

指标口径、公式、阈值、基线、异常定义统一由 `经营指标库` 管理。

禁止在每个模板里复制一套 ACOS、CVR、库存覆盖天数等指标定义。

---

## 9. 专业Agent输入规则

`required_agent_inputs` 描述所需专业Agent角色及输入目的，例如：
- Agent-4：广告数据与广告结构分析；
- Agent-7：库存与供应链约束；
- Agent-10：价格/促销环境；
- Agent-12：合规风险。

专业Agent只提供事实、分析、事件和建议，不成为最终决策出口。

---

## 10. 模板扩展字段

单一模板允许在 `extensions` 下增加领域字段，但必须满足：
- 不复制 canonical 字段；
- 不改变统一字段语义；
- 不生成新的最终决策对象；
- 可被忽略而不破坏基础模板读取；
- 在模板版本升级记录中说明。

---

## 11. 命名约束

机器字段统一使用英文 snake_case；中文文件可使用中文标题和说明。

禁止同义多名，例如：
- 不同时使用 `rollback_rule / rollback_condition / rollback_trigger` 表达同一治理字段；
- 不同时使用 `agent_inputs / related_agents / participating_agents` 表达同一模板要求。

统一术语以本文件为准。

---

## 12. 静态验收

任一正式模板进入 active 前必须确认：
- 没有复制 DecisionItem/FinalDecision 的完整Schema；
- required_context、required_evidence、key_questions 非空；
- option_comparison_dimensions 非空；
- observation_requirements 与 rollback_requirements 非空；
- supported_item_types / supported_scopes 与实际场景一致；
- 所有领域扩展都在 extensions 下；
- 没有私自定义新的业务优先级、经营状态或最终决策对象。
