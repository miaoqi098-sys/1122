# 信息不足、审批与降级

## 1. 定位
本规则处理“现在不能安全形成正常执行型 FinalDecision”的情况，包括证据不足、来源冲突、必须审批、上下文缺失和关键对象无法确认。

## 2. 信息不足类型
- 关键 ContextPackage 字段缺失；
- evidence_refs 不足或过期；
- 多来源事实冲突且无法判断可信度；
- Option 缺少必要成本/影响/回滚信息；
- RiskAssessment 为 `requires_more_evidence`；
- 决策会改变 StrategyChain，但缺少策略历史；
- 需要审批但审批对象/权限上下文不完整。

## 3. 处理优先级
信息不足时，Agent-1 不得为了保持流程畅通而强行输出确定结论。应按最小风险原则选择：
1. 请求补充证据；
2. 降低决策置信度；
3. 缩小动作范围；
4. 选择可逆观察/试验；
5. 转审批；
6. hold_for_review；
7. 若仍无法安全判断，保持未决状态。

## 4. 数据冲突
发现证据冲突时必须：
- 保留冲突来源引用；
- 标明 freshness / evidence_strength / source reliability；
- 不静默覆盖旧值；
- 必要时回到 S02 补上下文或请求专业 Agent 复核；
- 若冲突影响 eligibility 或主导风险，停止正常最终选择。

## 5. 审批门
requires_approval 场景必须明确：
- approval_required；
- approval_reason；
- approval_scope；
- approval_before_action；
- 审批前哪些 Task 禁止进入执行；
- 审批拒绝后的降级/替代路径。

审批规则只定义框架，不实现真实审批系统。

## 6. 置信度与动作幅度
- `high`：关键事实一致、风险边界清楚、方案比较充分；
- `medium`：存在可控不确定性，应保留观察与控制；
- `low`：不得直接承载高影响/不可逆动作，应补证据、缩小动作或转人工复核。

低置信度不是禁止任何动作，但动作必须与证据强度匹配。

## 7. 降级路径
典型降级：
- 全量动作 → 小范围测试；
- 不可逆动作 → 可逆替代；
- 立即执行 → 观察窗口；
- 自动执行 → 审批后执行；
- 长周期资源投入 → 短周期验证；
- 确定结论 → 待证据确认的假设。

## 8. 禁止
- 缺数据时用常识补成“事实”；
- 证据冲突时只挑支持当前方案的一方；
- 需要审批时把审批当作备注；
- low confidence 仍直接执行高影响不可逆动作；
- 把 request_more_evidence 当成失败而强行跳过。
