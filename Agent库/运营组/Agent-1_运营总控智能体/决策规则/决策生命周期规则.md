# 决策生命周期规则

## 1. 定位
本规则定义 FinalDecision 从形成、等待、激活、执行、失效到被替代的完整状态机。它不执行 Task，也不替代 S07/S08，而是确保 Agent-1 的决策不会被“原地覆盖”。

## 2. Canonical 状态
- `draft`：候选决策已形成，但尚未满足发布条件。
- `pending_evidence`：缺少关键证据，等待补证。
- `pending_approval`：已形成方案，但审批未完成。
- `approved`：审批条件已满足，可进入激活/编排。
- `active`：当前有效经营决策，允许 S07 编排或继续任务。
- `partially_executed`：部分 Task 已执行，仍存在未完成动作。
- `completed`：本轮决策目标已完成并进入结果验证。
- `invalidated`：关键事实/资格/约束变化导致原决策不再有效。
- `superseded`：被新的 FinalDecision 正式替代。
- `cancelled`：因人工、约束或上游条件撤销，且不再继续。
- `expired`：超过 `valid_until` 且未被复核延长。

## 3. 允许的核心迁移
```text
draft
├─→ pending_evidence
├─→ pending_approval
└─→ approved → active → partially_executed → completed

pending_evidence → draft / cancelled
pending_approval → approved / cancelled
active / partially_executed → invalidated / superseded / cancelled / completed
active → expired
expired → draft（仅通过重新评估生成新版本，不原地复活）
```

## 4. 不允许原地覆盖
任何会改变业务方向、主要动作、风险资格、审批要求或 StrategyChain 关系的变化，必须：
1. 保留旧 `decision_id`；
2. 生成新 Decision 或明确状态迁移；
3. 使用 `supersedes_decision_id` / `invalidated_by_ref` 形成追溯；
4. 不得直接覆盖旧决策正文后继续沿用同一 `decision_id`。

## 5. 失效触发
典型包括：
- eligibility 从可执行变为 prohibited/requires_more_evidence；
- 关键 ContextPackage 事实被新证据推翻；
- 目标系统正式变化；
- 经营状态/生命周期变化使原策略前提失效；
- guardrail/stop_condition 触发；
- 审批被撤回；
- `valid_until` 到期；
- 新 FinalDecision 已正式取代旧决策。

## 6. 部分执行后的处理
若已部分执行：
- 必须记录 `executed_task_ids` 与 `remaining_task_ids`；
- 新决策不得假设旧动作“未发生”；
- S07 需针对剩余任务给出 continue/pause/cancel/replace/rollback 建议；
- 若存在不可逆结果，必须进入新的 ContextPackage 作为事实。

## 7. 复核规则
`active` 决策必须至少具有：
- `valid_until` 或 `review_trigger`；
- 成功标准；
- stop/guardrail 条件；
- 与 StrategyChain 的关系；
- 下一次复核所需证据。

## 8. 禁止
- 复用同一 decision_id 表示两个不同方向；
- 旧决策失效后删除历史；
- expired 决策未经重新评估直接恢复 active；
- 部分执行后按“全新起点”重新决策；
- superseded 后仍由旧决策产生新执行任务。
