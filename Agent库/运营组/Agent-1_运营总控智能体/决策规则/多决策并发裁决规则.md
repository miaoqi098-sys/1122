# 多决策并发裁决规则

## 1. 定位
当同一 scope 或相互依赖 scope 同时出现多个 DecisionItem、多个 P0/P1 或多个专业 Agent 结论时，本规则定义如何裁决先后、并行、合并、阻断与资源冲突。

## 2. 先判断是否真的冲突
多个 DecisionItem 同时存在时，先分类：
- `independent`：资源、对象、动作互不冲突，可并行；
- `shared_resource`：争用预算、库存、时间、人力或审批容量；
- `action_conflict`：一个动作会削弱/抵消另一个动作；
- `dependency`：A 必须先于 B；
- `same_root_cause`：多个问题来自同一根因，优先合并；
- `same_action`：一个动作可同时解决多个 DecisionItem，优先形成联合方案。

## 3. 多 P0 裁决顺序
多个 P0 不允许简单按创建时间排序。至少比较：
- hard constraint / eligibility；
- goal_layer；
- impact_scope / impact_breadth；
- urgency / deadline；
- delay_cost / time_to_irreversibility；
- dependency_impact；
- reversibility；
- evidence_strength；
- execution_capacity。

## 4. 并行条件
满足以下条件可并行：
- 不争用同一关键资源；
- 动作方向不冲突；
- 不会使另一决策失效；
- 各自控制条件能独立满足；
- 观察窗口不会互相污染关键因果判断。

## 5. 必须合并的场景
- 一个根因导致多个表象问题；
- 同一动作可同时解决多个 DecisionItem；
- 分开执行会造成重复任务或互相覆盖；
- 多 Agent 对同一对象给出可兼容建议。

合并后必须保留所有来源 `decision_item_ids`，不得丢失原问题追溯。

## 6. 必须串行的场景
- B 的资格依赖 A 的结果；
- 两个动作互相影响，无法解释独立效果；
- 使用同一不可分割预算/库存资源；
- 前一决策可能改变后一决策的 ContextPackage。

## 7. 资源冲突
当多个高优先级事项争用资源时，应形成显式 `resource_allocation_decision`，而不是让先到任务先占资源。至少说明：
- 总可用资源；
- 各事项最低需求；
- 边际收益/风险；
- 不分配资源的 delay_cost；
- 分配后的保护边界。

## 8. 冲突无法安全裁决
若证据或目标不足以决定：
- 保留多个候选；
- request_more_evidence；
- 缩小并行范围；
- 人工审批；
- 不得随机选择或按 Agent 编号排序。

## 9. 禁止
- 多个 P0 默认全部同时执行；
- 按事件到达时间机械抢占资源；
- 同根因拆成多个互相打架的策略；
- 为了“并行效率”污染实验和观察窗口；
- 合并后删除原始 DecisionItem 引用。
