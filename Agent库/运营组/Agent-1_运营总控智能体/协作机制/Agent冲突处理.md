# Agent冲突处理

## 目的
定义多个专业 Agent 结论不一致时，Agent-1 如何处理，避免投票、平均或简单服从某一个 Agent。

## 一、常见冲突类型
### 1. 事实冲突
不同 Agent 使用的数据或事实不一致。

处理：
- 检查数据来源；
- 检查时间窗口；
- 检查口径；
- 检查数据新鲜度；
- 优先回到原始数据或更高质量证据。

### 2. 解释冲突
事实一致，但对原因解释不同。

处理：
- 明确每个 Agent 的假设；
- 找出能够区分假设的关键证据；
- 允许多个原因同时成立。

### 3. 目标冲突
各 Agent 从各自专业目标出发得出不同建议。

例如：
- Agent-4建议加预算；
- Agent-7建议收缩流量保护库存。

处理：回到 `目标系统/`，根据当前主目标、风险和约束重新排序。

### 4. 时间尺度冲突
一个 Agent 优化短期结果，另一个关注中长期价值。

处理：
- 明确短/中/长期影响；
- 判断机会窗口与风险发生时间；
- 不把不同时间尺度的建议强行当作互斥。

### 5. 风险偏好冲突
一个方案激进增长，另一个方案偏防守。

处理：结合经营状态、证据强度、可逆性、审批等级和当前风险容忍。

## 二、冲突处理顺序
```text
先确认事实是否一致
↓
再确认口径和时间窗口
↓
再确认目标是否一致
↓
再确认假设是否不同
↓
寻找能改变结论的关键证据
↓
必要时追加专业Agent或工具
↓
Agent-1结合目标和约束做最终取舍
```

## 三、禁止做法
- 不用“多数Agent同意”作为最终理由；
- 不对相反建议简单取平均；
- 不默认高编号或某个固定Agent优先；
- 不因为Agent-1拥有最终决策权就忽略专业反证；
- 不把尚未解决的事实冲突伪装成高置信度结论。

## 四、风险优先处理
若冲突涉及：
- 合规；
- 商品不可售；
- 库存断货；
- 现金/利润底线；
- 不可逆动作；

应先处理硬约束和高优先级风险，再比较增长收益。

## 五、无法完全解决时
如果冲突仍无法消除，Agent-1应：
- 降低结论置信度；
- 选择更可逆、更小范围的方案；
- 延长或设定观察窗口；
- 请求人工审批；
- 明确记录未解决冲突。

## 六、冲突记录模板
- conflict_id；
- involved_agents；
- conflict_type；
- shared_facts；
- disputed_facts_or_interpretations；
- evidence_used；
- current_goal；
- resolution；
- unresolved_points；
- final_confidence；
- review_time。

## 示例
现象：核心词自然排名上涨，但Exact广告持续亏损。

Agent-4：建议暂停Exact降低ACOS。
Agent-5：认为该词仍可能承担自然排名和防守价值。
Agent-6：指出当前广告亏损已接近利润容忍边界。

Agent-1不应投票，而应进一步判断：
- Exact是否还有增量或防守价值；
- 自然排名是否已经稳定到可以减少广告；
- 当前亏损是否可承受；
- 降竞价是否比直接暂停更可逆。

最终可能选择“先降竞价并设7天观察窗口”，而不是简单听某一个Agent。

## 核心原则
专业 Agent 的冲突本身不是系统故障，很多时候它说明真实经营目标之间存在张力。Agent-1的价值正是在这些局部正确但彼此冲突的结论之间做整体最优取舍。
