# Agent追问规则

## 目的
定义 Agent-1 在收到专业 Agent 结论后，什么时候应该继续追问，什么时候应该停止，避免协作链无限延长。

## 一、需要追问的情况
### 1. 关键事实缺失
结论依赖的重要数据没有提供，例如：
- 时间窗口缺失；
- 样本量缺失；
- 数据来源不明；
- 结论没有对应事实支持。

### 2. 结论无法支持决策
例如 Agent 只说“建议优化广告”，但没有说明：
- 为什么；
- 优化什么；
- 对哪些关键词/活动；
- 预期影响；
- 风险和置信度。

### 3. 与其他证据冲突
需要追问冲突原因、口径或补充证据。

### 4. 结论置信度低，但当前动作影响较大
高影响动作需要更强证据，应要求补充验证。

### 5. 专业Agent提出新的关键风险
如果新风险会改变目标或方案排序，应继续补充对应事实或调用其他Agent。

### 6. 结论超出该Agent专业边界
例如广告Agent直接建议长期大幅降价，应追问其广告侧依据，同时把价格判断路由给 Agent-10，而不是直接采纳。

## 二、不需要追问的情况
- 已满足当前决策所需字段；
- 结论证据充分且与其他高质量证据一致；
- 剩余信息不会改变方案排序；
- 当前动作低风险、可逆、可测试；
- 已达到大脑定义的决策充分条件。

## 三、追问必须具体
不推荐：
> 再深入分析一下。

推荐：
> 请补充该Search Term过去14天的CPC、广告位、转化、历史订单，并说明30点击0订单是否已超过当前样本可接受范围，以及降竞价和暂停两种方案各自风险。

## 四、追问优先级
优先追问：
1. 能排除高风险误判的信息；
2. 能解决Agent冲突的信息；
3. 能明显改变候选方案排序的信息；
4. 获取成本低、速度快的关键事实。

低优先级：
- 只增加背景但不改变行动；
- 已有其他高质量证据覆盖；
- 为追求“更完整”而重复同类数据。

## 五、最大追问原则
未来运行器应允许为协作设置最大追问轮次或成本预算。

如果在合理轮次后仍无法形成高置信度结论，应：
- 明确证据不足；
- 降低动作规模；
- 继续观察；
- 或升级人工审批。

不得无限循环。

## 六、追问对象变化
追问不一定继续问同一个Agent。

例如：
- Agent-4发现广告转化下降可能来自价格；
- Agent-1可停止追问Agent-4价格问题，改为调用Agent-10；
- Agent-10发现活动价格正常，再返回Agent-1综合。

Agent-1负责控制协作范围，避免专业Agent互相无限转发。

## 七、追问记录
正式追问应保留：
- original_request_id；
- followup_id；
- target_agent；
- missing_information；
- why_needed；
- expected_decision_impact；
- response；
- whether_resolved。

## 核心原则
追问的目的不是得到“完美答案”，而是以最低必要成本获得足以改变或稳定经营决策的关键证据。
