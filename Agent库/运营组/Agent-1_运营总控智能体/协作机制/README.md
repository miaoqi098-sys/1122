# Agent-1 协作机制

## 模块定位
本目录定义 Agent-1 如何调用 Agent-2 至 Agent-13、请求专业分析、组合多方结论、处理冲突、复用已有结果并决定是否继续追问。

它回答的是：**Agent-1 什么时候该找谁、问什么、拿回什么、不同 Agent 说法不一致时怎么办。**

本模块不重新定义组织权限。组织关系、职责边界和最终决策权以 `身份与权限/` 为准；本目录只负责协作规则和输入质量要求。

## 标准协作流程
```text
Agent-1识别问题/证据缺口
↓
判断是否需要专业Agent
↓
根据问题路由到1个或多个Agent
↓
生成标准请求
↓
专业Agent返回结构化结果/智能事件包
↓
检查scope、新鲜度、证据和适用范围
↓
必要时追问或联合分析
↓
处理Agent之间的冲突
↓
结果进入Event/ContextPackage等canonical链
↓
Agent-1经S04-S06/DecisionSelector形成最终经营决策
```

专业Agent返回的recommendation是来源意见，不自动成为FinalDecision。

## 什么时候不需要调用其他Agent
以下情况可以直接使用已有信息：
- 已有专业分析仍在有效期内；
- 数据和经营状态没有实质变化；
- 当前问题没有超出原分析适用范围；
- 不存在会改变决策的新风险/约束；
- 复用旧结果不会影响决策可靠性。

Agent-1 不应为了“显得严谨”而重复调用所有 Agent。

## 什么时候必须调用专业Agent
以下情况原则上应调用对应专业Agent：
- 关键专业事实缺失；
- 问题明显属于专业领域且当前没有新鲜结论；
- 重大决策需要跨域验证；
- 现有结论存在冲突；
- 高风险或不可逆动作需要专业复核；
- 当前经营状态重大变化使旧结论失效。

## 协作原则
1. Agent-1 是唯一最终经营决策出口，但不替代专业Agent的专业分析职责。
2. 每条专业结论必须保留来源、时间、scope、数据范围和置信度。
3. 不默认“多叫几个Agent = 更可靠”，调用应有明确目的。
4. 重大跨域决策不能只依赖一个专业Agent的局部结论。
5. 冲突优先查证据、口径、时间窗口和目标差异，不做简单投票或平均。
6. 旧结论可以复用，但必须经过新鲜度和适用性检查。
7. 追问必须针对会改变决策的缺失信息，不做无止境的信息收集。
8. Agent-1 不得把专业Agent建议直接当成已批准执行指令。
9. 协作请求/结果应保留业务引用，运行run_id/trace_id只做调用追踪。

## 与其他模块关系
- `身份与权限/Agent协作关系.md`：组织关系、最终决策权和职责边界。
- `输入规范/`：专业Agent结果、智能事件与统一scope/引用结构。
- `大脑/证据判断机制.md`：判断专业结论的证据质量。
- `经营状态识别/`：提供经营状态上下文。
- `目标系统/`：提供动态目标与约束。
- `技能模块/`：S02/S03等消费协作结果并进入canonical决策链。
- `工具与数据需求/`：定义未来专业Agent调用所需工具/数据合同。

## 当前阶段
本模块 V1.x 框架已阶段性封板。真实 Agent-1 → 专业Agent → Agent-1 调用由未来 Agent Runner / Skill Runner 实现并已挂运行依赖；当前不因此转向运行层施工，也不在本目录伪造已运行闭环。

Agent库建设继续按任务总表推进；后续若Agent-2至Agent-13正式接口建设发现不兼容，再以跨Agent任务回到本模块修订。
