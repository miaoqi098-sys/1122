# Agent-1 协作机制

## 模块定位
本目录定义 Agent-1 如何在真实运行中调用 Agent-2 至 Agent-13、请求专业分析、组合多方结论、处理冲突、复用已有结果并决定是否继续追问。

它回答的是：**Agent-1 什么时候该找谁、问什么、拿回什么、不同 Agent 说法不一致时怎么办。**

本模块不重新定义组织权限。组织关系、职责边界和最终决策权以 `身份与权限/` 为准；本目录只负责协作的执行规则。

## 标准协作流程
```text
Agent-1识别问题
↓
判断是否需要专业Agent
↓
根据问题路由到1个或多个Agent
↓
生成标准请求
↓
专业Agent返回结构化结论/智能事件包
↓
检查新鲜度、证据、适用范围
↓
必要时追问或联合分析
↓
处理Agent之间的冲突
↓
Agent-1综合目标、状态、指标、历史和风险
↓
形成最终经营决策
```

## 什么时候不需要调用其他Agent
以下情况可以直接使用已有信息：
- 已有专业分析仍在有效期内；
- 数据和经营状态没有实质变化；
- 当前问题没有超出原分析适用范围；
- 不存在新的高优先级风险；
- 复用旧结果不会影响决策可靠性。

Agent-1 不应为了“显得严谨”而重复调用所有 Agent。

## 什么时候必须调用专业Agent
以下情况原则上应调用对应专业 Agent：
- 关键事实缺失；
- 问题明显属于专业领域且当前没有新鲜结论；
- 重大决策需要跨域验证；
- 现有结论存在冲突；
- 高风险或不可逆动作需要专业复核；
- 当前经营状态发生重大变化，使旧结论失效。

## 协作原则
1. Agent-1 是最终经营决策出口，但不替代专业 Agent 的专业分析职责。
2. 每条专业结论必须保留来源、时间、数据范围和置信度。
3. 不默认“多叫几个 Agent = 更可靠”，调用应有明确目的。
4. 重大跨域决策不能只依赖一个专业 Agent 的局部结论。
5. 冲突优先查证据、口径、时间窗口和目标差异，不做简单投票或平均。
6. 旧结论可以复用，但必须经过新鲜度和适用性检查。
7. 追问必须针对会改变决策的缺失信息，不做无止境的信息收集。
8. Agent-1 不得把专业 Agent 的建议直接当成已批准执行指令。

## 与其他模块关系
- `身份与权限/Agent协作关系.md`：组织关系、最终决策权和职责边界。
- `输入规范/智能事件包.schema.json`：专业 Agent 向 Agent-1 上报事件的标准结构。
- `大脑/证据判断机制.md`：判断专业结论的证据质量。
- `经营状态识别/`：决定当前需要优先关注哪些专业领域。
- `目标系统/`：决定跨 Agent 冲突时当前什么目标更重要。
- `技能模块/`：未来将“Agent路由、冲突检测、上下文装载”等实现为可执行技能。
- `系统运行层/`：未来负责真正发起 Agent 调用和接收结果。
