# 任务与执行历史

## 1. 定位
保存TaskPlan、Task生命周期与真实ExecutionResult历史，区分“计划做什么”“实际尝试做了什么”和“执行回执是什么”。

## 2. Task历史
至少保留：
- task_plan_id
- task_id
- decision_id
- decision_item_id
- scope
- task_type
- owner / executor / approver / validator
- dependencies
- previous_status / current_status
- status_changed_at / reason
- start/stop/success/rollback条件
- observation_window
- strategy_chain_id（适用时）

## 3. ExecutionResult历史
真实执行回执至少应能追溯：
- execution_result_id
- task_id / task_plan_id
- executor/system_ref
- attempted_at / completed_at
- execution_status
- request/response refs
- error/failure refs
- actual_changes
- idempotency/ref信息（运行层有值时）

## 4. 状态语义
- blocked：未满足执行条件；
- failed：已经尝试执行但失败；
- cancelled：明确终止；
- awaiting_validation：动作完成，经营结果待验证；
- completed：必要验证已通过；
- rolled_back：真实回滚完成。

历史层必须保留状态变化，不只保存最终状态。

## 5. 读取原则
未来分析相似任务时应区分：
- 策略方向问题；
- 执行失败；
- 数据失败；
- 审批/权限阻塞；
- 动作成功但经营结果失败。

不能把执行失败误学习为“策略无效”。

## 6. 禁止
- 没有ExecutionResult就记录“执行成功”；
- 只保存最后completed状态而丢失failed/blocked过程；
- rollback建议直接记为rolled_back；
- Task被supersede后删除历史。
