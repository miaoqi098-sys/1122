# 新鲜度与复用

## 1. 核心原则
历史记录能否用于当前决策，取决于其对象、时间、经营状态、数据窗口、证据质量和适用边界，而不是“以前发生过”就永久有效。

## 2. freshness判断
至少检查：
- occurred_at / validated_at / created_at；
- valid_until / review_at；
- data_window；
- 当前scope是否一致；
- 当前生命周期/经营状态是否改变；
- 活动期与正常期是否可比；
- 价格、库存、Listing、变体、市场等关键背景是否改变；
- 是否有后续更强证据或superseding记录。

## 3. 复用等级
可将历史候选区分为：
- `current_relevant`：可直接作为当前上下文证据之一；
- `background_only`：仅作背景，不应直接驱动当前决策；
- `needs_refresh`：可能重要，但必须刷新数据/状态；
- `conflicted`：与新证据冲突，必须保留并进一步判断；
- `expired`：不再适合当前决策，但保留历史价值。

## 4. 同类历史不机械套用
即使同一ASIN、同一关键词或同一广告问题，也必须比较：
- 当前目标；
- 当前状态；
- 库存/价格/活动背景；
- 当前证据强度；
- 动作可逆性；
- 过去结果的归因质量。

## 5. 冲突历史
旧记录与新记录冲突时：
- 不删除旧记录；
- 标记supports/contradicts/refines/supersedes/coexists等关系；
- 比较freshness与evidence_quality；
- 若可能改变当前决策，S02应装载冲突双方供S03/后续判断。

## 6. 失败历史
失败记录尤其不能删除，但复用时必须区分：执行失败、数据失败、策略失败、验证过早、外部状态变化等不同原因。

## 7. 禁止
- valid_until过期仍当当前结论；
- 历史成功方案机械复制；
- 用旧活动期数据解释当前正常期而不标背景差异；
- 因新结论更方便就删除相反历史。
