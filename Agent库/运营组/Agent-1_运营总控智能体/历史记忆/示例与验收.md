# 历史记忆示例与静态验收

## 示例A｜旧促销历史与当前正常期
历史记录显示大促期间转化率上升，但当前没有活动。

正确处理：历史可作为background_only；不得直接用活动期表现预测当前正常期，必要时刷新当前窗口数据。

## 示例B｜执行失败不等于策略失败
FinalDecision方向合理，但API调用失败。

正确处理：Task/ExecutionResult历史记录execution_failure；Validation/Learning不得写成“该经营策略无效”。

## 示例C｜旧Decision被新Decision替代
同一StrategyChain中旧Decision在新库存风险出现后被override。

正确处理：生成新decision_id，保留旧decision与supersedes/strategy_chain关系，不覆盖旧决策文本。

## 示例D｜经验冲突
旧LearningRecord认为“该关键词降价后效率提升”，新验证显示在当前阶段降价导致流量损失。

正确处理：保留两条LearningRecord，建立contradicts/refines关系；比较当前状态、数据窗口和attribution，不直接删除旧经验。

## 示例E｜Case复用
案例库检索到相似广告案例。

正确处理：Case提供参考和历史引用，S02仍装载当前ContextPackage，S06仍做当前风险资格，DecisionSelector不能直接复制案例结论。

## 静态验收
- [x] 历史记录从单一产品/ASIN扩展到统一scope。
- [x] 事实、Decision、Task/ExecutionResult、ValidationResult、LearningRecord分层。
- [x] 旧Decision/失败记录不会被新记录覆盖删除。
- [x] StrategyChain/supersedes关系可保留。
- [x] freshness/valid_until/data_window/状态可比性进入复用判断。
- [x] S09经验等级与promotion gate被保留。
- [x] S09不自行宣称written。
- [x] 历史记忆与案例库保持单一事实源边界。
- [x] 执行失败、数据失败、弱归因不会被错误学习成强策略结论。
