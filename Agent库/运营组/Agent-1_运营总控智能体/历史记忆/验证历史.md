# 验证历史

## 1. 定位
验证历史保存S08对ExecutionResult和经营结果的正式ValidationResult，回答“动作实际产生了什么结果、是否达到success criteria、归因有多强、是否需要继续观察或回滚”。

## 2. 关键引用
至少应保留：
- validation_id
- execution_result_id
- task_id / task_plan_id
- decision_id / decision_item_id
- option_id（如有）
- strategy_chain_id（如有）
- observation_window
- success_criteria
- actual_outcome
- validation_status/result
- evidence_refs
- attribution_strength
- confounders
- confidence
- validated_at
- next_recommendation/route（如有）

## 3. 与执行历史分离
ExecutionResult说明动作是否被执行；ValidationResult说明经营结果是否达到目标。API成功、任务完成提交或人工确认动作已做，均不自动等于验证成功。

## 4. 早期/失败验证
- premature_evaluation：记录为过早评估，不形成强结论；
- data_failure：记录数据问题，不学习“策略无效”；
- execution_failure：记录执行链问题，不直接否定业务策略；
- weak/confounded attribution：保留不确定性，不生成强因果经验。

## 5. 读取原则
未来复用验证历史必须检查：
- 数据窗口和经营状态是否可比；
- attribution_strength；
- confounders；
- evidence_quality；
- 是否已有后续ValidationResult修正旧判断。

## 6. 禁止
- 用Task completed替代ValidationResult；
- 删除失败或无效验证；
- 单次弱归因结果直接写成可复用强规律；
- 新验证覆盖旧validation_id。
