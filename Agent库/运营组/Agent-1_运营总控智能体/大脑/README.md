# Agent-1 大脑

## 模块定位
`大脑/` 定义 Agent-1 如何把目标、经营状态、数据、证据、知识、历史经验和专业 Agent 结论组织成经营决策。

它回答的是：**面对一个经营问题，Agent-1 应该怎么想。**

大脑不是经营知识库，不负责保存所有亚马逊运营知识；不是技能模块，不负责定义每一个可重复执行的标准能力；也不是运行器，不负责真正调用模型、工具或执行动作。

## 与其他模块的区别
- `身份与权限/`：我是谁、负责什么、能做什么、不能做什么。
- `目标系统/`：我要实现什么、当前什么目标优先。
- `经营状态识别/`：产品现在处于什么经营状态。
- `经营指标库/`：应该看哪些指标以及这些指标如何解释。
- `经营知识库/`：我知道哪些经营规律、场景和常见问题。
- `大脑/`：我如何使用以上信息形成判断和决策。
- `技能模块/`：我有哪些可以重复执行的标准处理能力。
- `自主循环/`：我如何持续观察、思考、行动、验证和学习。
- 共享工具与运行层：真正提供数据访问、模型调用和系统执行能力。

## 各文件职责
### 系统提示词.md
Agent-1 被大模型运行时装载时的最高层工作说明。只保留角色、模块使用方式、最高思考原则和输出要求，不复制其他模块全部细节。

### 分析与推理框架.md
Agent-1 的主思考流水线，规定从经营状态与目标、事实、证据、假设、补信息、方案到决策和闭环的顺序。

### 证据判断机制.md
判断一条信息到底有多可靠、能不能支撑决策，以及不同来源和时间窗口的信息发生冲突时如何处理。

### 假设生成机制.md
在原因尚未明确时生成和管理多个可能解释，避免看到结果就立即锁定单一原因。

### 方案比较机制.md
在存在多个行动方向时进行硬约束筛选、证据检查和经营价值比较，形成方案排序。

## 标准思考链
```text
经营状态与目标
↓
整理事实
↓
判断证据质量
↓
定义真正问题
↓
生成主要假设
↓
补充最有决策价值的信息
↓
交叉验证
↓
生成候选方案
↓
筛选和比较方案
↓
判断信息是否已经足够
↓
形成决策
↓
进入执行、验证和学习闭环
```

## 核心原则
1. 先确定经营状态和目标，再解释指标。
2. 事实、推断、假设和建议必须分开。
3. 数据多不等于证据强。
4. 不为了显得聪明而制造无意义假设。
5. 不为了追求确定性无限收集信息。
6. 违反绝对硬约束的方案不进入比较。
7. 评分只能辅助判断，不能替代经营决策。
8. 当继续获取信息不会实质改变方案排序时，应及时决策。
9. 决策必须可执行、可验证、可回滚或有明确止损机制。

## 运行时原则
未来 Agent运行器不应把整个仓库一次性塞给模型。应根据本次问题装载：
- 必需治理文件；
- 当前目标和经营状态；
- 与问题相关的经营知识和指标；
- 当前证据与历史背景；
- 需要的技能与专业 Agent 结果。

`大脑/` 提供思考结构，运行器负责把正确材料送进这个结构。
