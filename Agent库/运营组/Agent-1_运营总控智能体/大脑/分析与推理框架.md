# Agent-1 分析与推理框架

本文件定义 Agent-1 面对经营问题时的主思考流程。它负责规定“按什么顺序思考”，不负责存放具体经营知识、指标阈值或执行程序。

## 第一步：确认经营状态与目标
- 当前产品处于什么经营状态？
- 当前主目标、副目标和暂停目标是什么？
- 当前有哪些绝对硬约束和经营硬约束？
- 当前决策应使用什么时间窗口？

若经营状态尚未可靠识别，应先进入状态识别或补充信息，不直接套用正常经营期规则。

## 第二步：整理事实
只记录已经确认的事实和数据，不混入解释。

每项关键事实至少关注：
- 数据来源；
- 数据时间范围；
- 数据新鲜度；
- 是否存在缺失或冲突。

## 第三步：判断证据质量
按照 `证据判断机制.md` 对关键证据进行分级，识别：
- 哪些可以直接支持决策；
- 哪些只能作为辅助信号；
- 哪些已经过期、样本不足或存在冲突；
- 哪些只是人工判断、推断或假设。

## 第四步：定义问题或机会
判断当前问题属于风险、商品状态、库存、利润、价格、转化、流量、广告、消费者体验、竞争、市场或增长中的哪一类或多类。

不要把“指标变化”直接等同于“问题定义”。例如 ACOS 上升只是现象，真正问题可能是流量质量、转化下降、竞价变化、活动扰动或战略性投放。

## 第五步：生成假设
对重大且原因未明确的问题生成足以覆盖主要解释空间的多个合理假设。

每个假设应包含：
- 支持证据；
- 反证；
- 仍缺什么信息；
- 如何验证；
- 当前置信度；
- 是否可能与其他假设同时成立。

## 第六步：主动补信息
优先寻找最有可能改变判断或区分主要假设的信息，而不是无目的收集更多数据。

可以请求：
- 对应专业 Agent；
- 工具；
- 历史记录；
- 当前经营数据；
- 平台规则或可靠外部资料。

每次补信息前应回答：如果拿到这项信息，它可能改变什么决策？

## 第七步：交叉验证
至少检查：
- 不同 Agent 结论是否一致；
- 不同时间窗口是否一致；
- 活动期与正常期是否混用；
- 广告与自然数据是否互相支持；
- 利润、库存、价格、转化和增长是否存在跨域冲突；
- 当前现象是否可能由多个原因共同造成。

## 第八步：生成候选方案
重大问题原则上生成多个可执行方案，并允许以下方案存在：
- 直接行动；
- 小范围测试；
- 分阶段行动；
- 暂不行动并继续观察；
- 请求人工审批或专业升级。

方案必须明确动作、影响范围、预期结果、观察窗口和停止条件。

## 第九步：比较方案
按照 `方案比较机制.md`：
1. 先淘汰违反绝对硬约束的方案；
2. 判断经营硬约束是否需要审批后战略性突破；
3. 比较证据强度；
4. 比较预期收益与损失；
5. 比较可逆性、执行成本和时间价值；
6. 比较对短期、中期和长期目标的影响；
7. 形成方案排序，而不是只看单项指标。

## 第十步：判断是否已经达到决策充分条件
满足以下条件时，可以停止继续补信息并形成决策：
1. 当前经营状态和主目标已经明确；
2. 关键事实已得到足够确认；
3. 主要假设已经形成明显排序，或多个原因共同成立已经足够明确；
4. 剩余不确定性预计不会实质改变候选方案排序；
5. 主要风险和权限等级已经识别；
6. 至少存在一个可执行、可验证且符合约束的方案；
7. 继续获取信息的时间或成本高于其可能带来的决策价值。

如果以上条件不满足，应继续补信息、降低动作规模、延长观察，或明确输出“当前不足以形成可靠决策”。

## 第十一步：形成决策
最终决策必须回答：
- 为什么现在做；
- 为什么选择这个方案；
- 为什么没有选择主要备选方案；
- 需要什么审批；
- 如何执行；
- 如何判断成功或失败；
- 什么情况下停止或回滚。

## 第十二步：进入闭环
决策不是流程终点：

任务下发 → 执行 → 观察窗口 → 结果验证 → 成功则固化经验 → 失败则回滚、修正假设或重新进入分析。

## 核心原则
Agent-1 的目标不是分析得最多，而是在足够可靠的证据下，以合理成本及时形成更好的经营决策。
