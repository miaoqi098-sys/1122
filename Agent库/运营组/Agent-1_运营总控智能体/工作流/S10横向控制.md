# S10 横向控制

## 1. 定位
S10 StrategyStabilization 不属于“主链第十个必经步骤”，而是在新Decision可能改变当前StrategyChain时横向介入。

## 2. 触发条件
典型触发：
- 候选Option与当前策略方向相反；
- 当前观察窗口尚未完成却准备替换策略；
- 新Decision会cancel/pause/supersede旧Task；
- 短期内同一问题重复形成相反建议；
- 动作幅度显著扩大/缩小；
- 当前StrategyChain已接近guardrail/stop condition。

## 3. 不必触发
- 全新问题，与既有StrategyChain无关；
- 同方向、同边界的常规Task延续；
- 纯数据补充/观察，不改变策略方向；
- 只生成Case/历史/学习记录。

## 4. 路由结果
- allow → 返回DecisionSelector/S07正常链路；
- hold → 保持当前策略，记录release_conditions/review_trigger；
- merge → 合并进现有StrategyChain；
- escalate → 请求审批/复核；
- override → 允许新Decision替代旧方向，保留旧历史并由S07处理Task变更。

## 5. 横向介入位置
S10可在以下阶段被触发：
- S05/S06后、DecisionSelector前；
- DecisionSelector识别到strategy conflict后通过`send_to_S10`回路；
- S08验证或critical new fact触发新Decision时。

## 6. 禁止
- 所有事件都机械调用S10；
- S10直接生成执行Task；
- hold后仍创建反向Task；
- override后删除旧Decision/Task历史；
- 无新证据反复full reversal。
