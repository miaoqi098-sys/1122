# 工具与数据需求

## 1. 定位

本目录定义 Agent-1 为了完成经营判断、决策、任务化、验证和学习，**需要什么数据与工具条件**。

它回答：
- 需要什么业务事实；
- 需要哪个Scope与时间窗口；
- 允许从哪些来源取得；
- 数据多新才可用；
- 证据质量达到什么程度才能支持强决策；
- 什么时候需要调用专业Agent或共享工具；
- 数据缺失、延迟、冲突、工具失败时如何降级；
- 哪些动作只允许读取、哪些需要审批、哪些必须交执行层。

本模块不实现任何真实API、数据库、Runner或执行器。

---

## 2. 核心边界

### 不替代经营指标库
经营指标库定义指标含义、口径、公式、基线与阈值；本模块只声明某个决策“需要哪些指标以及最低数据条件”。

### 不替代专业Agent
专业Agent负责领域监控、分析、解释和建议；本模块规定 Agent-1 什么时候需要这些输入以及返回质量要求。

### 不替代技能统一接口
Event、ContextPackage、DecisionItem、FinalDecision、Task等canonical对象仍由技能统一接口治理。

### 不替代共享基础设施
SP-API、Ads API、记忆数据库、Scheduler、Executor等未来由对应共享层实现；本模块只给出需求合同。

## 3. 需求链

```text
经营问题 / DecisionItem
↓
识别所需业务事实
↓
DataRequirement
↓
选择可接受数据源 / 专业Agent
↓
检查Scope + 时间窗口 + freshness + evidence quality
↓
满足 → 装入ContextPackage
不满足 → 补数据 / 调Agent / 降级 / hold
↓
需要动作时形成 ToolRequirement
↓
只读工具 / 验证工具 / 调度需求 / 执行需求
↓
权限与审批检查
↓
未来共享层实际执行
```

## 5. 数据来源类别

正式来源类别：
- `specialist_agent`：Agent-2至Agent-13标准结果；
- `shared_data_interface`：未来统一数据接口层；
- `memory_data_layer`：历史、Learning、Case、StrategyChain；
- `official_platform_source`：平台通知、政策、资格等官方事实；
- `human_input`：人工确认、审批、业务目标或不可自动获得事实；
- `derived_metric`：由已批准指标规则计算出的派生指标；
- `system_state`：任务、执行、配置、权限等系统状态。

同一需求可以有多个候选来源，但必须声明主来源和降级来源。

## 6. 工具能力类别

Agent-1需要的是抽象能力，不在本目录绑定具体API：
- 数据读取/搜索
- 历史/案例检索
- 指标计算与比较
- Schema/结构验证
- 专业Agent调用
- 证据新鲜度/一致性检查
- 决策模板/知识检索
- 任务/策略状态读取
- 审批请求
- 调度请求
- 执行动作请求
- 结果标准化与验证
- 学习/记忆写入请求

---

## 7. 质量原则

1. 数据必须带来源、Scope、时间窗口、采集时间和新鲜度。
2. 原始事实与派生解释分开。
3. 数据缺失不得由模型“合理猜值”补齐。
4. 数据冲突先查口径、Scope、时间窗口和来源版本。
5. 活动期与常态期数据不可机械比较。
6. 强决策要求的required证据不满足时必须降级。
7. 平台规则/资格等高时效事实优先官方来源。
8. 专业Agent的分析必须保留其数据范围与证据引用。
9. 工具失败和“业务没有结果”必须区分。
10. 所有写动作必须走权限、审批、S07任务与执行层边界。
