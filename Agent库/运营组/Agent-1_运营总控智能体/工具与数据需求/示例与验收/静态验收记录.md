# 工具与数据需求静态验收记录

## 1. 验收范围
覆盖：README、需求总则、DataRequirement.schema.json、ToolRequirement.schema.json、数据需求地图、数据源映射、工具能力地图、新鲜度与证据要求、缺失冲突与降级规则、权限与动作边界、运行依赖映射及两个标准示例。

## 2. 数据需求结构
`DataRequirement.schema.json` 已明确：
- 业务目的；
- required/preferred/optional；
- raw_fact/derived_metric/specialist_interpretation等数据类型；
- Scope；
- freshness/window；
- 可接受来源与fallback；
- 最低证据质量；
- missing/stale/conflict降级行为。

示例 `DataRequirement_库存覆盖.example.json` 展示资格型required数据缺失时必须阻塞高影响放量，而不是用历史平均值猜测。

结论：**通过。**

## 3. 工具需求结构
`ToolRequirement.schema.json` 已明确：
- capability / purpose；
- operation_class；
- 输入输出；
- 权限级别；
- 审批、幂等、审计；
- tool error / permission / incomplete result降级；
- runtime dependency refs；
- canonical输入输出引用。

示例 `ToolRequirement_广告数据读取.example.json` 明确“只读广告数据”不等于“拥有广告修改权限”。

结论：**通过。**

## 4. 职责边界
通过以下边界：
- 指标口径/公式仍归经营指标库；
- 专业分析归Agent-2至Agent-13；
- canonical对象归技能统一接口；
- 工具与数据需求只定义能力合同；
- 真实数据接入、存储、Runner、Scheduler、Executor归共享层。

## 5. 数据质量
已覆盖：
- Scope mismatch；
- window mismatch；
- freshness；
- attribution delay；
- source conflict；
- raw/derived/interpretation分层；
- 强决策证据门禁；
- 专业Agent结论新鲜度；
- 历史/Case/Learning复用新鲜度。

结论：**通过。**

## 6. 异常降级
已明确区分：no_data、stale_data、incomplete_result、source_conflict、scope_mismatch、window_mismatch、quality_below_minimum、attribution_delay、permission_denied、tool_error、unsupported。

并明确required/preferred数据不同降级策略，防止无限收集和模型补值。

结论：**通过。**

## 7. 权限与执行边界
通过：
- read_only / internal_compute / approval_required / execution_layer_only / human_only / context_dependent 六级；
- 读写能力分离；
- Agent-1只形成FinalDecision与Task要求；
- 外部动作结果必须返回ExecutionResult；
- 审批请求不等于批准。
