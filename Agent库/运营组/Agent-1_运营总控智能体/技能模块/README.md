# 技能模块

本目录是 Agent-1 唯一正式技能承载目录。旧 `Skill/` 目录中的定义已经合并到这里，后续不再维护两套技能体系。

## 技能模块的定位
技能模块是 Agent-1 可以在运行过程中重复调用的标准能力。它不同于经营知识：
- 经营知识库告诉 Agent-1“应该知道什么、如何理解问题”。
- 技能模块告诉 Agent-1“面对任务具体执行哪套标准处理能力”。
- 工具层提供技能执行过程中真正访问数据、系统和外部能力的工具。

因此：知识 ≠ 技能 ≠ 工具。

## 技能调用链
典型总控任务并不是只调用一个技能，而是按需要组合：

收到智能事件包
→ S01 事件校验
→ S02 上下文装载
→ 匹配经营状态、指标和经营知识
→ S03 冲突检测
→ S04 决策排序
→ S05 候选方案生成
→ S06 风险分级
→ 形成总控决策
→ S07 任务拆解
→ 执行
→ S08 结果验证
→ S09 复盘写回

S10 策略防抖贯穿计划、执行、观察和验证阶段。

## 每个正式技能的标准结构
后续每个技能建立独立目录，至少包含：
1. `README.md`：技能目的、适用场景、边界和调用条件。
2. `输入规范.json`：技能需要的数据字段。
3. `输出规范.json`：技能必须返回的结构化结果。
4. `判断规则.md`：技能内部业务规则和处理流程。
5. `异常处理.md`：缺数据、数据冲突、调用失败等处理方式。
6. `示例/`：真实输入输出示例。
7. `测试/`：验收与边界测试。
8. `执行程序/`：后续真正可运行的程序实现。

## 技能与其他模块的关系
### 与大脑
大脑负责推理和方案比较；技能负责把高频处理过程标准化，减少每次从零推理。

### 与经营知识库
技能可以检索经营知识库。例如 S05 候选方案生成可以根据异常诊断卡和场景知识生成候选动作。

### 与经营状态识别和经营指标库
S02、S04、S05等技能需要读取经营状态和相关指标，不能脱离产品阶段直接运行。

### 与协作机制
S03、S07等技能需要知道不同 Agent 的职责和能力边界。

### 与工具层
技能本身定义“需要做什么”，工具层提供“实际怎么获取数据、怎么执行动作”。

### 与自主循环
观察、思考、计划、行动、验证、学习是 Agent-1 的运行循环；技能是循环各阶段可以调用的标准能力。

## 建设原则
- 一个技能解决一种可重复能力，不把整个 Agent-1 写成一个超级技能。
- 技能优先结构化输入和输出，便于 Agent运行器调用。
- 业务阈值不应散落硬编码在技能文档中，优先从经营指标库和配置读取。
- 技能必须允许“信息不足”作为合法输出，并指出需要补什么数据。
- 高风险技能输出必须经过权限矩阵和审批机制。
- 技能实现后必须有测试，不能只存在说明文档。
