# S01｜事件校验

## 技能定位
S01 是 Agent-1 接收智能事件后的第一道标准处理能力。

它不负责判断“该怎么经营”，只负责回答：
- 这个事件包结构是否合法；
- 关键字段是否齐全；
- 来源是否明确；
- 时间、对象、严重级别等基础信息是否可用；
- 是否存在明显重复、过期、矛盾或无法解释的字段；
- 当前事件是否具备进入后续分析链路的最低条件。

## 调用位置
```text
收到智能事件包
↓
S01 事件校验
↓
通过？
├─ 是 → S02 上下文装载
└─ 否 → 返回补充/拒绝/降级处理
```

## 适用输入
主要输入为：
`输入规范/智能事件包.schema.json`
定义的专业 Agent 事件包。

也允许未来接收由系统监控、人工录入或工具层产生的标准化事件，但进入 S01 前必须被转换为统一事件结构。

## 核心职责
1. 结构校验；
2. 必填字段校验；
3. 字段类型与枚举校验；
4. 来源校验；
5. 产品对象校验；
6. 时间有效性校验；
7. 基础事实质量检查；
8. 严重级别与事件内容一致性检查；
9. 重复/近重复事件初筛；
10. 输出标准化校验结果。

## 不负责
S01 不负责：
- 判断事件是否值得采取经营动作；
- 判断根因；
- 判断当前经营状态；
- 生成候选方案；
- 调整广告、价格、库存等策略；
- 决定是否批准执行。

这些属于后续技能、大脑和决策模块。

## 输出状态
S01 统一输出四种状态：
- `passed`：通过，可继续进入后续流程；
- `passed_with_warnings`：可继续，但存在非阻断问题；
- `needs_information`：关键数据缺失，需要补充后再进入后续流程；
- `rejected`：结构、来源或对象等存在严重问题，当前事件不应进入决策链。

## 阻断错误示例
- 缺失 event_id；
- 缺失 source_agent；
- 缺失 product_id；
- occurred_at 无法解析；
- event_type 为空；
- facts 完全为空且 summary 也无法支持事件内容；
- source_agent 不在允许来源中且没有人工/系统来源标识；
- 事件对象无法关联到任何有效产品对象。

## 非阻断警告示例
- recommendation 缺失；
- facts 数量过少但仍存在可验证事实；
- severity 可能与事件内容不匹配；
- 事件时间较旧但仍可能具有历史价值；
- 与已有事件高度相似，需要后续去重确认。

## 与其他模块关系
- `输入规范/智能事件包.schema.json`：基础事件结构标准；
- `事件处理/`：后续负责事件优先级、合并、关联和生命周期；
- `经营状态识别/`：只有校验通过后才进行状态判断；
- `协作机制/`：来源 Agent 和专业边界用于来源合理性检查；
- `历史记忆/`：用于辅助判断重复或过期事件；
- `配置/`：未来存放允许来源、最大事件年龄等机器参数。

## 成功标准
S01 的成功不是“尽可能拒绝事件”，而是：
1. 阻止明显脏数据进入决策链；
2. 不因为非关键字段缺失而误伤有效事件；
3. 明确告诉上游缺什么；
4. 输出可被运行器和后续 Skill 直接消费的结构化结果。
