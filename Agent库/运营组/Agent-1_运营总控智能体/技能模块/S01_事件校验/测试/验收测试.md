# S01 事件校验验收测试

## T01 正常事件通过
输入：字段完整、来源合法、对象存在、时间有效、facts可验证。
期望：`passed` + `continue_to_S02`。

## T02 缺失event_id
输入：无event_id。
期望：`rejected`，错误码 `EVENT_ID_MISSING`。

## T03 缺失recommendation
输入：其余字段完整，但无recommendation。
期望：不阻断；可 `passed` 或 `passed_with_warnings`。

## T04 facts为空但summary明确
输入：summary含“过去14天61点击0订单”，facts为空。
期望：`needs_information`，要求补充可验证事实字段；不得直接判定关键词无价值。

## T05 来源越界
输入：Agent-4上报“已确认知识产权侵权”。
期望：事件不必直接丢弃，但产生 `SOURCE_SCOPE_MISMATCH`，建议Agent-12复核。

## T06 产品无法识别
输入：product_id不存在于已知产品集合，且无其他可解析标识。
期望：`needs_information` 或 `rejected`，不得自动绑定其他ASIN。

## T07 时间不可解析
输入：occurred_at = "昨天晚上"。
期望：`rejected` 或 `needs_information`，错误码 `TIME_INVALID`。

## T08 severity明显不匹配
输入：Listing已冻结，severity=low。
期望：保留来源severity但给出 `SEVERITY_MISMATCH`，后续重新分级。

## T09 相同event_id重复
输入：existing_events已存在相同event_id。
期望：duplicate_signal=true，不在S01直接删除或合并。

## T10 近重复事件
输入：不同event_id，但相同产品、事件类型、时间窗口和几乎相同facts。
期望：`POSSIBLE_DUPLICATE`，交事件处理模块进一步判断。

## T11 摘要与事实冲突
输入：summary=“库存已断货”，facts=“当前可售库存200件”。
期望：不得passed；输出冲突并要求复核。

## T12 历史事件仍有价值
输入：事件较旧，但明确作为历史复盘输入。
期望：允许 `passed_with_warnings`，不能机械按时间删除。

## T13 外部产品库不可用
输入结构完整，但无法访问known_product_ids数据源。
期望：不把“查不到”当成“产品不存在”；标记依赖不可用并保守处理。

## T14 账户级风险事件
输入：账户级合规事件无法自然填写product_id。
期望：标记当前统一Schema存在 `SCHEMA_GAP`，不得伪造ASIN；为未来事件Schema升级保留测试。

## 验收标准
S01 V1.0 至少应满足：
1. 阻断错误不会误放行；
2. 非阻断字段缺失不会被一律拒绝；
3. 不修改来源事实来“修好”事件；
4. 所有异常都有明确状态和下一动作；
5. 校验结果能被S02直接消费。
