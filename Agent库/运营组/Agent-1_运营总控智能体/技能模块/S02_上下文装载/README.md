# S02｜上下文装载

## 技能定位
S02 是 Agent-1 在事件通过 S01 后，用来决定“这次到底需要知道什么”的标准能力。

它不把所有历史、指标、知识和 Agent 结论全部塞给大模型，而是围绕当前问题建立一份**最小充分上下文（Minimum Sufficient Context）**。

## 调用位置
```text
S01 事件校验通过
↓
S02 上下文装载
↓
识别当前问题与决策对象
↓
生成上下文需求计划
↓
读取已有数据/历史/状态/知识/专业结论
↓
检查新鲜度、完整性与冲突
↓
形成上下文包
↓
信息充分？
├─ 是 → 进入状态识别 / S03 冲突检测 / 后续推理
└─ 否 → 输出缺失信息与建议数据来源
```

## 核心目标
1. 只加载与当前决策有关的信息；
2. 优先加载高价值、强时效、会改变决策的信息；
3. 区分当前事实、历史事实、旧结论、知识和假设；
4. 检查旧结论是否仍可复用；
5. 不把活动期、正常期、断货期等不同背景的数据混在一起；
6. 信息不足时明确指出缺什么，而不是用常识补齐；
7. 控制上下文体积、模型成本和噪声。

## 标准上下文域
S02 将上下文分为 10 个域：

### C01 产品身份
ASIN、SKU、父子体、站点、类目、产品版本等。

### C02 当前经营状态
生命周期、经营情境、风险、机会，以及状态证据和置信度。

### C03 当前经营目标
当前主目标、副目标、暂停目标、硬约束。

### C04 当前核心指标
与问题相关的流量、转化、广告、利润、库存、价格、体验、市场竞争指标。

### C05 经营事件与活动
Coupon、BD、LD、Prime Deal、站外活动、广告重大调整、Listing改版、补货等。

### C06 产品历史
历史策略、历史异常、过去决策、观察窗口、结果和经验。

### C07 专业Agent结论
Agent-2 至 Agent-13 已有且仍有效的专业分析、智能事件和建议。

### C08 市场与竞品
仅在当前问题需要时加载竞争价格、排名、促销、趋势、竞争动作等。

### C09 经营知识
只检索与当前问题匹配的诊断卡、场景知识和经营原则，不加载整个知识库。

### C10 当前任务与限制
正在执行的任务、观察窗口、审批状态、资源限制、禁止动作、回滚条件。

## 不负责
S02 不负责：
- 最终判断经营状态；
- 解决 Agent 冲突；
- 生成经营方案；
- 评估方案风险；
- 做最终决策；
- 执行广告、价格、库存等动作。

它只负责给后续推理准备正确、相关、足够新鲜的上下文。

## 最小充分上下文原则
“上下文越多越好”是错误的。

S02 应优先回答：
1. 当前要解决的具体问题是什么？
2. 哪些信息会改变这个问题的判断？
3. 哪些信息已经存在且仍有效？
4. 哪些信息已经过期？
5. 哪些信息缺失但值得获取？
6. 哪些信息虽然存在，但与当前问题无关，不应加载？

## 输出状态
- `ready`：上下文足以进入后续分析；
- `ready_with_gaps`：存在缺口，但不足以阻断后续分析；
- `needs_information`：缺少会显著改变决策的关键上下文；
- `blocked`：关键对象、核心数据源或上下文依赖不可用，当前无法可靠继续。

## 与其他模块关系
- `S01_事件校验/`：提供已校验事件；
- `历史记忆/`：提供产品历史和旧决策；
- `经营状态识别/`：提供已有状态画像，并接收S02装载的数据用于重新识别；
- `经营指标库/`：告诉S02不同问题需要哪些指标；
- `经营知识库/`：按问题检索知识，不全量加载；
- `协作机制/`：判断专业Agent旧结论是否可复用、缺失信息应找谁；
- `目标系统/`：提供当前经营目标和硬约束；
- `任务调度/`：提供当前任务、观察窗口和执行状态；
- `记忆与数据层/数据接口层/工具层`：未来提供真实数据读取能力。

## 成功标准
S02 成功不是“搜到最多资料”，而是形成一份：
- 对当前问题足够；
- 数据来源清楚；
- 新鲜度可判断；
- 没有明显时间背景混淆；
- 不含大量无关噪声；
- 后续 Agent 可以直接消费的结构化上下文包。
