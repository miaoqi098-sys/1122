# S02 上下文装载异常处理

## 一、产品历史不存在
新品或首次进入系统时可能没有历史。

处理：
- 不视为系统错误；
- 标记 `NO_PRODUCT_HISTORY`；
- 降低历史比较能力；
- 依赖当前数据、类目基线和后续观察建立第一版历史。

## 二、关键数据缺失
例如判断库存风险却没有可售库存或补货周期。

处理：
- 标记为 blocking/high impact missing_context；
- 输出建议数据来源；
- 不使用常识猜数字；
- 必要时 status=`needs_information`。

## 三、数据源不可用
区分：
- 数据不存在；
- 数据源暂时不可访问；
- 权限不足；
- 接口超时；
- 数据尚未同步。

不得把“接口失败”解释成“指标为0”。

## 四、数据时间不一致
例如广告数据截至昨天，但订单数据截至今天。

处理：
- 标记各自 as_of；
- 对需要直接计算/比较的指标进行窗口对齐；
- 无法对齐时给出 warning；
- 不直接计算误导性ACOS、TACOS、CVR等组合指标。

## 五、活动期与正常期混合
如果历史窗口跨越BD/Coupon/断货/改版：
- 分段；
- 标记经营背景；
- 必要时分别计算；
- 不把不同背景直接平均后作为唯一基线。

## 六、旧Agent结论已过期
处理：
- 保留为历史参考；
- 不放入“当前有效结论”；
- 加入 stale_context；
- 若其内容对当前决策重要，建议重新调用对应Agent。

## 七、多个来源同一指标不一致
例如两个来源的库存、销售额、价格不同。

处理：
- 不静默选一个；
- 标记来源、时间和口径；
- 优先权由数据治理/配置决定；
- 无法解决且影响决策时 status=`needs_information` 或 `blocked`。

## 八、上下文过大
处理顺序：
1. 去掉P3；
2. 去掉重复信息；
3. 用摘要替代原始长文本；
4. 缩短无关历史窗口；
5. 保留关键异常点和决策节点；
6. 最后才压缩P1/P0。

不得为了节省Token删除硬约束。

## 九、知识检索无匹配
没有合适诊断卡/案例并不阻断。

处理：
- 标记 `NO_KNOWLEDGE_MATCH`；
- 允许大脑基于事实和一般原则推理；
- 不强行套用最相似但不适用的案例。

## 十、经营状态缺失或过期
S02可以装载用于重新识别状态的数据，但不得自己伪造最终状态。

处理：
- 标记需要重新运行经营状态识别；
- 如果状态是当前决策关键条件，先更新状态再继续。

## 十一、当前任务与新事件冲突
例如已有“7天观察窗口”，第2天又出现同类轻微波动。

处理：
- 必须装载当前任务和观察窗口；
- 标记给S10策略防抖和S03冲突检测；
- S02不直接取消旧任务。

## 十二、未知异常
- 记录未成功装载的域；
- 保留已成功装载的上下文；
- 明确失败原因；
- 不返回伪造的完整上下文。

## 核心原则
S02 可以带着已知缺口继续，但绝不能把“未知”包装成“已知”。
