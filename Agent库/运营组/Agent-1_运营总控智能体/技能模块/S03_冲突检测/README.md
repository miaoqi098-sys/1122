# S03｜冲突检测

## 定位
识别 S02 上下文中会影响 Agent-1 决策的冲突，并把“哪里冲突、为什么冲突、需要什么证据”结构化输出。

## 检测对象
- 事实冲突：同一指标/事件的值、来源、时间或口径不一致；
- 解释冲突：事实一致但原因假设不同；
- 目标冲突：增长、利润、库存、安全等目标互相拉扯；
- Agent结论冲突：专业Agent建议互斥；
- 任务冲突：新任务与执行中/观察中的任务互斥；
- 策略冲突：新建议推翻旧策略但没有新证据；
- 时间尺度冲突：短期收益与中长期资产冲突；
- 权限/约束冲突：方案触碰审批、合规或硬约束。

## 流程
```text
读取S02上下文包 → 提取事实/结论/目标/任务/约束 → 成对及跨域检测 → 归类 → 判断严重度 → 找决定性证据 → 输出冲突清单
```

## 严重度
- `critical`：涉及合规、不可售、硬约束、不可逆动作或核心事实无法确认；
- `high`：可能改变最终方案或任务方向；
- `medium`：影响置信度但可继续；
- `low`：可记录但不阻断。

## 输出
每个冲突至少包含：`conflict_id`、`type`、`parties`、`shared_facts`、`disputed_points`、`evidence_needed`、`severity`、`resolution_status`。

状态：`clear / conflicts_found / needs_evidence / blocked`。

## 边界
S03负责发现和结构化冲突，不用投票解决冲突，也不直接选择经营方案。最终取舍由目标系统、大脑、S04-S06完成。

## 核心原则
冲突不是系统故障。真正危险的是系统没有发现冲突，却把局部正确当成整体正确。
