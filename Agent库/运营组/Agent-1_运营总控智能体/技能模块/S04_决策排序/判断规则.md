# S04 判断规则 V1.1

## 一、标准排序链
```text
1. 标准化decision_items
2. Priority Gate硬约束检查
3. 目标层级判断
4. 当前经营状态修正
5. 风险/机会时间窗口
6. 目标偏离程度
7. 依赖与阻塞影响
8. 可逆性与证据强度
9. 资源容量
10. 形成business_priority与rank
11. 与历史优先级比较并记录change_trigger
```

## 二、Priority Gate优先于P0-P3
- 合规、不可售、明确禁止行为、重大不可逆风险等可进入blocked/escalated。
- protected表示仍可继续经营，但增长动作受到库存、利润、现金、价格等保护约束。
- Gate不得被机会型任务绕过。
- blocked不等于“所有事情都停止”，而是与阻断对象相关的事项不能进入正常优化竞争。

## 三、目标层级
采用目标系统四层：
1. safety_sellability：安全与可售底线；
2. survival_operations：生存与经营底线；
3. business_quality：经营质量；
4. growth_expansion：增长与扩张。

先保证更高层目标处于可接受区间，再优化下一层。同层目标不设永久固定顺序。

## 四、状态动态修正
生命周期、经营情境、风险和机会状态可改变同层事项权重。

例如新品测试期可提高有效学习事项优先级；库存紧张状态可提高补货/控量事项优先级。

任何动态修正都必须记录到priority_factors/change_trigger。

## 五、风险与机会窗口
- 风险越接近发生点，urgency越高；
- 机会窗口即将关闭也可提高优先级；
- 机会不得突破上层硬约束；
- 不因“潜在收益很高”自动给P0。

## 六、依赖影响
阻塞多个重要事项的前置问题应提高优先级。

S04只记录 `blocked_by / must_resolve_before / dependency_impact`，不在此处完成完整执行DAG；具体编排交S07。

## 七、证据与可逆性
- 证据弱 + 动作不可逆：降低排序确定性，优先补证据；
- 证据弱 + 动作高度可逆：可允许小范围后续测试，但不等于自动提高业务优先级；
- 关键事实被S03标记blocks_decision时，相关事项不得获得虚假高置信度排序。

## 八、资源约束
当P0/P1事项超过执行容量：
- 不静默丢弃；
- 根据依赖、紧迫度、影响范围继续细排rank；
- 无法执行的事项标记defer/block；
- 资源不足本身可形成新的经营待决事项。

## 九、业务优先级与执行顺序分离
S04回答“哪个经营问题更重要”，不是“鼠标先点哪个按钮”。

一个P1保护动作可能在执行层先于P0问题的某个后续步骤执行，这不改变P0问题的business_priority。S07负责最终任务顺序。

## 十、优先级变化
比较previous_priority与current_priority：
- promoted：优先级提高；
- demoted：优先级降低；
- unchanged：不变；
- new：首次进入排序。

change_trigger至少应引用一种真实变化：新事实、状态切换、目标切换、风险窗口、机会窗口、依赖变化、资源变化、冲突解决/升级。

禁止没有触发原因地频繁重排。

## 十一、观察窗口
已进入观察窗口的策略默认不因为普通短期波动产生同级反向待决事项；如确有反转建议，应参考S03冲突结果并交S10判断是否提前覆盖。

## 十二、排序不是方案选择
S04不得决定具体降价多少、预算加多少、暂停哪个词等方案内容。S04确定待解决问题顺序，S05才生成候选方案。

## 核心原则
Priority Engine不是固定打分表。它是“目标层级 + 当前状态 + 时效 + 依赖 + 证据 + 资源”的动态排序器，而且每次变化都必须可解释。
