# S04 异常处理 V1.1

- 当前目标缺失：不能可靠排序，回S02补目标上下文；不得用历史固定优先级代替当前目标。
- 状态画像过期：降低confidence，并请求重新识别状态；状态高度影响排序时暂停相关事项最终定级。
- decision_item字段不完整：允许先标准化；缺失goal_layer/urgency等关键字段且无法推断时进入unranked_items并请求信息。
- Priority Gate触发blocked：相关增长/优化事项不得继续正常竞争，next_action=resolve_blocker。
- Priority Gate触发escalated：next_action=escalate_review，不伪装成普通P0即可解决。
- 多个P0：按紧迫度、影响范围、依赖、时间窗口、证据和可逆性进一步细排rank；仍无法区分时允许同级并行升级。
- 资源不足：不静默丢弃事项；标记defer/block，并记录资源不足对rank的影响。
- 优先级规则冲突：回到目标系统四层框架，不使用旧固定排序覆盖。
- S03存在blocks_decision冲突：相关事项不得输出高confidence；优先解决决定性证据。
- 证据不足：降低排序确定性；若补证据本身会改变排序，将其作为前置调查事项。
- previous_priority缺失：priority_change=new/unknown，不虚构历史。
- previous_priority与当前差异但无change_trigger：视为排序异常，不允许静默升降级。
- deadline未知：允许使用风险/机会窗口描述，不伪造具体日期。
- 观察窗口内出现反向事项：交S10判断，不因短期波动直接重排为P0。
- 执行顺序与业务优先级看似矛盾：保留business_priority，将具体执行依赖交S07，不为迎合执行顺序篡改业务优先级。

## 核心原则
异常情况下宁可明确“无法可靠排序”，也不能生成看起来精确、实际上没有依据的P0-P3。
