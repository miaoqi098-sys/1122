# S04 验收测试 V1.1

- T01 商品不可售与广告扩量同时出现：先处理可售问题，增长事项不得绕过Priority Gate。
- T02 库存覆盖时间很短但广告效率很好：库存保护事项提高优先级，并记录promotion_reason。
- T03 新品测试与短期利润目标并存：底线安全时允许学习目标优先，不机械固定利润顺序。
- T04 多个P0：继续按紧迫度、影响范围、依赖和时间窗口细排；无法区分时允许同级并行升级。
- T05 机会窗口很短但经营底线已触发：机会不得突破上层约束。
- T06 状态或目标缺失：不得机械排序，相关事项进入unranked_items或请求补充信息。
- T07 输入风险、机会、调查等不同decision_item：输出goal_layer、urgency、priority_basis等结构字段。
- T08 出现硬阻断：使用gate_status=blocked/escalated，而不是只给P0后继续正常增长排序。
- T09 业务问题为P0但保护动作需要先做：P0保持business_priority，具体执行顺序交S07。
- T10 经营事实明显变化导致优先级升级：必须输出previous_priority、current_priority、promoted和change_trigger。
- T11 事实、状态、目标、资源都未变化却试图大幅重排：不得无change_trigger静默升降级。
- T12 S03对关键事实标记blocks_decision：依赖该事实的事项不得输出high confidence。
- T13 潜在收益高但证据弱且动作不可逆：不得仅因收益高直接排P0。
- T14 某前置问题阻塞多个重要事项：dependency_impact=blocks_many，并作为提升依据。
- T15 执行资源不足：继续细排rank，其余事项明确defer/block，不静默丢弃。
- T16 观察窗口内出现普通短期波动和反向建议：结合S03并交S10，不直接重排为高优先级反向策略。
- T17 机会窗口明显缩短且经营底线安全：允许提高优先级，并把窗口变化写入change_trigger。
- T18 某约束只影响部分事项：只阻断相关decision_items，不冻结全部事项。

## 验收总要求
1. 每个rank必须有结构化priority_basis；
2. business_priority与具体执行顺序不得混淆；
3. priority变化必须可追溯到change_trigger；
4. Priority Gate必须先于正常排序；
5. 不得用固定权重或单指标机械决定优先级；
6. 信息不足时允许不排序，而不是伪造精确结果。
