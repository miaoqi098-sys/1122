# S06 异常处理 V1.1

- 无法估计概率：likelihood=unknown，不伪造百分比，并增加data_uncertainty风险。
- 缺权限矩阵：可评估风险，但eligibility不得因权限未知直接宣称可自动执行；需要审批时标记requires_approval/unknown approval。
- 关键阈值缺失：优先使用产品基线、当前状态和相对变化；仍不足则提升不确定性。
- 风险维度看似互相抵消：不得简单平均，保留dominant_risk和主要risk_drivers。
- 缓解措施依赖尚未完成：不得用于降低controlled_risk，按未缓解状态处理。
- 缓解措施没有明确动作/触发条件：视为无效mitigation。
- 方案触碰禁止项：eligibility=prohibited，不使用“高风险但可以试”的表述。
- 合规/账户状态未知且动作依赖该状态：eligibility可为requires_more_evidence，不默认安全。
- S05方案字段不完整：能评估的部分继续评估；缺失字段会改变风险结论时请求补充，不凭空补方案细节。
- known_risk_signals为空：不代表无风险，S06仍需独立扫描所有风险维度。
- inherent_risk低于某单项关键风险：视为聚合异常，重新检查dominant-risk规则。
- controlled_risk在没有有效control时低于inherent_risk：视为异常，不允许无依据降级。
- residual_risk高于inherent_risk：若因新发现风险导致必须说明原因；否则视为评估异常。
- worst_case无法可靠描述：允许unknown/说明证据不足，不制造极端情景。
- 多个R3/R4风险：保留所有关键风险，不只显示一个dominant_risk后丢弃其他风险。
- 风险无法在执行后及时发现且不可逆：提高关注度，不能因发生概率低就降为低风险。

## 核心原则
风险不确定时要暴露不确定性；控制措施不可信时按未控制风险处理；任何风险降级都必须有真实保护依据。
