# S06 验收测试 V1.1

- T01 高预算放量但库存7天：识别inventory风险，worst_case包含提前断货/增长中断，不得只看广告收益。
- T02 大幅降价：识别profit、price_system、irreversibility等风险，并分别结构化。
- T03 小范围降竞价测试：风险画像应体现高可逆性和有限exposure，而不是简单写“低风险”。
- T04 合规状态未知：增加data_uncertainty/compliance风险，不能默认安全。
- T05 有真实回滚方案：保留inherent_risk，同时评估controlled_risk和residual_risk。
- T06 触碰明确禁止项：eligibility=prohibited。
- T07 S05 option完整承接：能够读取option_type、actions、assumptions、known_risk_signals、stop_conditions等。
- T08 单条risk结构：必须输出risk_id、category、likelihood、impact、inherent/residual level等关键字段。
- T09 R4 + 多个R1：总体不得平均成R2；R4可成为dominant_risk。
- T10 低概率高损失：仍允许R3/R4，不得只由likelihood决定。
- T11 mitigation尚未执行：controlled_risk不得假设已经降低。
- T12 mitigation没有明确动作：不得作为风险降级依据。
- T13 inherent→controlled→residual：三层风险必须逻辑可解释，不能无保护措施自动下降。
- T14 eligible_with_controls：方案只有落实预算上限/停止线后才安全时使用该状态，并列required_controls。
- T15 requires_approval：高风险但非禁止动作需要审批时，不得简单eligible=true。
- T16 requires_more_evidence：关键风险取决于未知事实时，不强行给执行资格。
- T17 worst_case：描述合理最大经营后果，不夸大成无依据灾难。
- T18 缺权限矩阵：允许完成风险判断，但不得宣称可自动执行。
- T19 stop_conditions有效：可作为风险控制证据；若无法监测则不得视为有效保护。
- T20 known_risk_signals为空：S06仍必须独立扫描风险维度，不能输出“无风险”。
- T21 多个关键风险：dominant_risk可以只有一个，但risk_drivers和risks不得丢掉其他重要项。
- T22 不可逆且detectability低：即使likelihood较低也应提高风险关注度。
- T23 高收益高风险方案：S06不得因为风险高直接宣称“不是最佳方案”，只判断资格和风险画像。
- T24 controlled_risk异常低于inherent_risk但无controls：验收失败。

## 验收总要求
1. 不得简单平均掩盖关键高风险；
2. 每个方案必须形成结构化风险画像；
3. inherent、controlled、residual必须分离；
4. eligibility必须表达条件/审批/证据状态，而非简单true/false；
5. 风险降级必须有真实mitigation依据；
6. S06不得越权替Agent-1选择最终方案。
