# S07｜任务编排

## 定位
把Agent-1已经选择的经营决策转成可执行、可审批、可观察、可回滚、可验证的任务网络。

## 每个任务必须定义
`task_id`、`decision_id`、`product_id`、`owner`、`action`、`priority`、`dependencies`、`approval_level`、`start_condition`、`deadline_or_window`、`success_criteria`、`stop_conditions`、`rollback`、`validator`。

## 编排能力
- 拆任务；
- 指定责任Agent/执行器/人工；
- 建立前后依赖；
- 识别可并行任务；
- 设置审批节点；
- 设置观察窗口；
- 设置成功、停止和回滚条件；
- 防止互斥任务同时执行。

## 生命周期
待创建 → 待审批 → 待执行 → 执行中 → 待验证 → 已完成 / 已回滚 / 已取消。

## 规则
- “优化广告”不是任务，必须拆成明确动作；
- 任务完成不等于经营成功，必须进入S08；
- 有依赖的任务不得抢跑；
- 高风险动作必须匹配审批；
- 同产品互斥任务不能同时执行；
- 观察窗口必须写入任务，而不是存在于聊天记忆里。

## 核心原则
一个好决策如果无法被拆成清楚的任务、负责人和验证条件，就还不是可执行决策。
