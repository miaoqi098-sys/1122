# S08｜结果验证

## 定位
判断任务执行后是否真正达到经营目标。区分“动作执行成功”和“经营结果成功”。

## 验证层级
1. 执行验证：动作是否按计划完成；
2. 数据验证：数据是否进入可比较窗口；
3. 目标验证：success_criteria是否达成；
4. 副作用验证：是否触发库存、利润、价格、体验等新问题；
5. 因果可信度：结果是否可能被活动、季节、竞品或其他同时动作干扰。

## 结果状态
`success / partial_success / no_effect / failed / inconclusive / rollback_triggered`。

## 输出
基线、观察窗口、实际结果、目标差异、副作用、置信度、下一动作。

## 规则
- 未到观察窗口不得过早判失败；
- 执行完成不等于success；
- 指标改善但触发更高层风险时不能判整体成功；
- 同期多个动作导致归因困难时输出inconclusive；
- 验证失败要区分方案错误、执行错误、数据不足和外部变化。

## 核心原则
Agent-1必须知道“我们做了什么”与“这件事有没有用”是两回事。
