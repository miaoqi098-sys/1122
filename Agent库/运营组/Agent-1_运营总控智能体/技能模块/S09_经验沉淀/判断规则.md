# S09 判断规则

1. 先写产品历史事实，再提炼lesson，避免经验脱离原始记录。
2. success/failed/inconclusive都可以产生经验，但证据强度不同。
3. 单产品单次结果默认最高只到product_lesson或knowledge_candidate，不直接变validated_knowledge。
4. 经验必须写适用场景和invalid_when。
5. 归因置信度低时，不生成强因果规律。
6. 新经验与旧经验冲突时使用supersedes/版本关系，不删除旧记录。
7. 失败经验必须保存失败原因类别：假设错误/执行错误/数据不足/外部变化/保护条件触发。
8. 可复用模式进入经营知识库前应经过知识治理或更多案例验证。
