# V1.x 变更提案规则

## 目的
技能模块进入阶段性冻结后，避免因为临时想法继续无边界扩张规则、字段和路由，同时允许必要的修复、兼容和测试完善。

## 一、冻结范围
V1.x阶段冻结以下内容：
- S01-S10业务职责边界；
- 主调用链与S10横向介入方式；
- Canonical核心对象及正式主键；
- ContextPackage唯一事实源原则；
- FinalDecision→S07原则；
- Task→ExecutionResult→ValidationResult→LearningRecord引用链；
- DecisionItemBuilder与DecisionSelector桥接职责；
- 权限、审批、风险、学习与策略防抖的核心业务语义。

## 二、冻结后可直接修复的内容
以下属于维护，不要求提出重大版本升级：
1. 拼写、排版、链接、目录引用错误；
2. JSON Schema语法错误；
3. 示例与已批准Schema不一致；
4. 测试补充，但不改变业务语义；
5. description、注释和说明性文字完善；
6. 明确的重复字段清理；
7. 旧历史数据Adapter兼容实现；
8. 运行时实现缺陷修复，只要不改变业务规则。

## 三、必须提交变更提案的内容
以下变更不得直接修改正式规则：
- 新增业务Skill；
- 删除或合并现有Skill；
- 新增必填业务字段；
- 删除正式主键或改变主键含义；
- 改变枚举值语义；
- 改变S03→DecisionItemBuilder→S04等正式路由；
- 改变S06→DecisionSelector→FinalDecision→S07边界；
- 改变审批/禁止/风险等级含义；
- 允许S09自行写数据库等职责越界；
- 改变S10 hold/override核心语义；
- 改变ContextPackage或FinalDecision唯一事实源原则。

## 四、变更提案最小内容
每个提案至少说明：
- change_id
- 提案内容
- 为什么现有V1.x不足
- 受影响Skill/Schema/对象
- 是否破坏兼容
- 数据迁移影响
- Runner/执行层影响
- 新增风险
- 回滚方案
- 需要新增/修改的验收测试
- 建议版本：V1.x patch / V1.x minor / V2

## 五、版本判断
### V1.x patch
只修实现、说明、测试或无语义的Schema错误。

### V1.x minor
增加向后兼容的可选字段/辅助能力，且不改变主流程语义。仍需记录提案。

### V2
以下通常应进入V2：
- 破坏性字段重构；
- 核心对象语义变化；
- Skill职责重划；
- 主调用链改变；
- 风险/审批/知识治理原则改变。

## 六、原则
冻结不是“不准进步”，而是从“边想边改”进入“有版本、有提案、有测试、有迁移”的工程状态。

## 当前状态
V1.x规则层进入阶段性冻结。下一阶段重点转向系统运行层实现；只有真实运行暴露出的结构性问题，才通过本规则重新进入规则层变更。
