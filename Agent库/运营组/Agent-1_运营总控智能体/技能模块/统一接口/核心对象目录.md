# S01-S10 核心对象目录 V1.1

## 目的
统一十个Skill之间反复出现的业务对象，避免同一含义在不同Skill中出现不同字段名、不同层级和不同解释。

## 单一事实源原则
### ContextPackage
S02 `context_package`是当前决策上下文唯一事实源。S03-S06不得再建立第二套current_goals/business_state/constraints/agent_analyses权威字段。

### FinalDecision
S06之后必须先由DecisionSelector形成FinalDecision，再进入S07。S07不得自行选择方案或重算风险。

### ExecutionResult
工具/API/人工执行返回值必须先标准化为ExecutionResult，再交S08；HTTP/API success不能直接当业务成功。

### ValidationResult
S08负责生成正式validation_id。S09必须直接消费validation_result，不再使用verification_result别名。

### LearningRecord
S09产生LearningRecord和memory write plan；真实数据库written状态由共享记忆与数据层返回。

## 桥接组件
### DecisionItemBuilder
正式输入/输出：
- `DecisionItemBuilder.input.schema.json`
- `DecisionItemBuilder.output.schema.json`

负责：
`Event refs + ContextPackage + Conflict → DecisionItem[]`

### DecisionSelector
正式输入/输出：
- `DecisionSelector.input.schema.json`
- `DecisionSelector.output.schema.json`

负责：
`Ranked DecisionItem + Options + RiskAssessments + ContextPackage → FinalDecision`

### ExecutionResultNormalizer
负责把API/工具/人工执行结果转为Canonical ExecutionResult。

### LearningWriteExecutor
负责执行S09 memory_writes计划，并返回真实写入状态。

### StrategyChainBuilder
负责维护跨决策、任务、验证的StrategyChain，S10只做稳定性判断，不凭空生成历史链。

## 对象转换原则
1. 不允许静默重命名造成语义漂移。
2. 新接口禁止继续新增`item_id / problem / actual_execution / verification_result`等旧别名。
3. 转换组件必须保留上游主键与source refs。
4. 一个对象升级为下一对象时，关键业务主键不能丢失。
5. 业务字段与运行字段分离；run_id/trace_id属于Skill Invocation Envelope。
6. 历史旧数据兼容由未来Adapter处理，不污染Canonical Schema。
