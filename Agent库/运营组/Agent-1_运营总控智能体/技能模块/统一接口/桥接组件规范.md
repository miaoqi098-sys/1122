# Skill桥接组件规范

## 目的
桥接组件不是新的业务Skill，而是负责把一个阶段的标准对象转换成下一个阶段的标准对象，避免转换逻辑散落在提示词、Runner或各Skill内部。

# 1. DecisionItemBuilder

## 定位
把已验证事件、上下文和冲突，转成 Agent-1 真正需要处理的标准待决事项。

## 输入
- `Event`
- `ContextPackage`
- `Conflict[]`
- `ConflictGroup[]`
- current business state
- current goals
- constraints
- active tasks

## 输出
`DecisionItem[]`

## 核心规则
1. 不直接复制某个Agent recommendation作为problem_definition。
2. 同一底层问题的多个事件/冲突应合并为一个DecisionItem，并保留source_event_refs/conflict_refs。
3. 一个事件可以产生多个DecisionItem，例如“销量下降”同时暴露库存风险与转化问题。
4. 多个事件也可以合并成一个DecisionItem，例如广告、库存、利润共同指向“放量超出资源承受能力”。
5. objective必须来自目标系统，不由Builder自创目标。
6. item_type只能描述待处理事项性质，不等于优先级。
7. Builder不排序；排序属于S04。

## 典型输出
```json
{
  "decision_item_id": "DI-001",
  "item_type": "problem",
  "subject": "travel mahjong set广告效率",
  "problem_definition": "目标词过去14天61点击0订单，但是否应停止投放仍受搜索词质量、历史转化和关键词资产价值影响。",
  "objective": "降低无效广告消耗，同时避免过早放弃潜在有效关键词资产。",
  "goal_layer": "business_quality",
  "conflict_refs": ["CONFLICT-001"],
  "source_event_refs": ["EVT-AD-0001"]
}
```

# 2. DecisionSelector

## 定位
S06之后由Agent-1大脑完成候选方案综合比较，并产出唯一正式FinalDecision。

## 输入
- ranked `DecisionItem`
- `Option[]`
- `RiskAssessment[]`
- goals
- business state
- hard constraints
- conflicts
- current strategy chain
- historical lessons

## 输出
`FinalDecision`

## 核心规则
1. 只能从S05已生成且S06已评估的option中选择，除非返回上游重新生成。
2. `prohibited` option不可选。
3. `requires_more_evidence`原则上不能直接进入正常执行，可选择information_first方案或回补证据。
4. `eligible_with_controls`被选择时，required_controls必须原样传给S07。
5. `requires_approval`被选择时，FinalDecision.approval必须标为pending。
6. 不能只按最低风险选方案，也不能只按最高收益选方案；必须综合目标、状态、优先级、风险、证据与时间窗口。
7. why_not_others必须保留主要落选原因，避免未来无法复盘。
8. 如果新FinalDecision会改变正在运行的策略，必须先经过S10或引用已完成的S10结果。

# 3. ExecutionResultNormalizer

## 定位
执行层把Amazon API、广告API、人工执行、工具调用等不同返回格式统一为ExecutionResult，再交S08。

## 最小字段
- execution_result_id
- task_id
- execution_status
- requested_action
- actual_action
- executor
- started_at
- finished_at
- logs
- errors
- observed_state_change
- source_response_refs

## 核心规则
- HTTP/API success不能自动等于actual business state changed。
- partial execution必须明确哪些部分成功、哪些失败。
- unknown不能包装成success。
- 人工执行同样必须形成ExecutionResult。

# 4. LearningWriteExecutor

## 定位
接收S09 memory_writes计划，并由共享记忆与数据层完成真正写入。

## 原则
- S09只计划写什么；
- LearningWriteExecutor返回真实written/failed状态；
- 写入失败不改变S09原始学习判断；
- 所有写入保留learning_id、decision_id、task_id、validation_id等追溯链。

# 5. StrategyChainBuilder

## 定位
从FinalDecision、Task、ExecutionResult、ValidationResult与历史变更中维护StrategyChain，供S10使用。

## 原则
- 同一目标/对象的一系列微调不能被拆成互不相关的孤立任务；
- 每次调整与反转累计adjustment_count/reversal_count；
- override后旧链不删除，形成版本/替代关系；
- StrategyChain是历史聚合对象，不由S10凭空生成。
