# Skill桥接组件规范 V1.1

## 目的
桥接组件不是新的业务Skill，而是负责把一个阶段的标准对象转换成下一个阶段的标准对象，避免转换逻辑散落在提示词、Runner或各Skill内部。

# 1. DecisionItemBuilder

## 定位
把已验证事件、ContextPackage和S03冲突转成Agent-1真正需要处理的Canonical DecisionItem。

## 正式输入
见：`DecisionItemBuilder.input.schema.json`

核心输入：
- `scope`
- `source_event_refs`
- `context_package`
- `context_refs`
- `conflicts`
- `conflict_groups`

目标、状态、约束、Agent结论均从ContextPackage读取，不再接收第二套并列事实源。

## 正式输出
见：`DecisionItemBuilder.output.schema.json`

输出：
- builder_id
- DecisionItem[]
- merged_source_groups
- builder_notes
- next_action

## 核心规则
1. 不直接复制某个Agent recommendation作为problem_definition。
2. 同一底层问题的多个事件/冲突应合并并保留source_event_refs/conflict_refs。
3. 一个事件可产生多个DecisionItem；多个事件也可合并为一个DecisionItem。
4. objective必须来自ContextPackage中的目标系统结果，不由Builder自创目标。
5. Builder不排序；排序属于S04。
6. 新输出只使用decision_item_id/problem_definition等Canonical字段，不输出item_id/problem旧别名。

# 2. DecisionSelector

## 定位
S06之后由Agent-1大脑完成候选方案综合比较，并产出唯一正式FinalDecision。

## 正式输入
见：`DecisionSelector.input.schema.json`

核心输入：
- scope
- ranked_decision_item
- options
- option_risks
- context_package
- strategy_chain（如有）
- active_tasks（如有）
- s10_result（策略反转场景需要）

## 正式输出
见：`DecisionSelector.output.schema.json`

输出：
- selector_id
- final_decision
- rejected_option_ids
- selection_notes
- next_action

## 核心规则
1. 只能从S05已生成且S06已评估的Option中选择，除非明确返回上游重新生成。
2. prohibited Option不可选。
3. requires_more_evidence原则上不能直接进入正常执行。
4. eligible_with_controls被选择时required_controls必须进入FinalDecision.risk_assessment。
5. requires_approval被选择时FinalDecision.approval必须反映审批要求。
6. 不能只按最低风险或最高收益选方案；综合目标、状态、优先级、风险、证据与时间窗口。
7. why_selected / why_not_others是正式审计字段。
8. 若新FinalDecision会改变正在运行的StrategyChain，必须先有S10判断或next_action=send_to_S10。

# 3. ExecutionResultNormalizer

## 定位
执行层把Amazon API、广告API、人工执行、工具调用等不同返回格式统一为ExecutionResult，再交S08。

## 正式输出Schema
`ExecutionResult.schema.json`

至少保留：
- execution_result_id
- task_id
- task_plan_id
- decision_id
- decision_item_id
- option_id / strategy_chain_id（如有）
- requested_action
- actual_action
- execution_status
- executor
- logs/errors/source_response_refs

## 核心规则
- HTTP/API success不能自动等于真实状态改变。
- partial execution必须明确哪些部分成功、哪些失败。
- unknown不能包装成success。
- 人工执行同样形成ExecutionResult。

# 4. LearningWriteExecutor

## 定位
接收S09 memory_writes计划，并由共享记忆与数据层完成真正写入。

## 原则
- S09只计划写什么；
- S09不得输出written；
- LearningWriteExecutor/记忆层返回真实written/failed状态；
- 写入失败不改变S09原始学习判断；
- 写入保留learning_id、validation_id、execution_result_id、task_id、decision_id等追溯链。

# 5. StrategyChainBuilder

## 定位
从FinalDecision、Task、ExecutionResult、ValidationResult与历史变更中维护StrategyChain，供S10使用。

## 正式对象Schema
`StrategyChain.schema.json`

## 原则
- 同一目标/对象的一系列微调不能被拆成互不相关的孤立任务；
- decision_ids表达整条策略历史，不再只保存单一decision_id；
- 每次调整与反转累计adjustment_count/reversal_count；
- override后旧链不删除，保留版本/替代关系；
- StrategyChain是历史聚合对象，不由S10凭空生成。

# 6. 桥接组件与Runner边界
Runner只负责：
- 调用桥接组件；
- 校验Schema；
- 路由；
- 保留trace/run关系。

Runner不得：
- 自己写problem_definition；
- 自己选择Option；
- 自己判断风险；
- 静默补齐关键业务字段。

## 当前状态
DecisionItemBuilder和DecisionSelector已从“说明性组件”升级为具有正式input/output Schema的可实现组件。下一阶段由系统运行层编码实现。
