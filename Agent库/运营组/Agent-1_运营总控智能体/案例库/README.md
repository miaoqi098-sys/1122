# 案例库

## 1. 定位

案例库保存 Agent-1 可复用的 **完整经营决策事件包（Case/Episode）**。

一个案例不是一条知识，也不是一条历史记录，而是把某次真实经营问题从“发生 → 判断 → 决策 → 执行 → 验证 → 学习”串成可回放对象，用于：
- 相似场景检索与对比；
- 成功/失败复盘；
- 人工纠正留档；
- 模板与策略的历史验证；
- 训练未来判断，但不机械照抄历史动作。

---

## 2. 案例与其他模块的边界

### 经营知识库
保存可泛化的经营知识、诊断原则与场景理解。

### 历史记忆
保存时间序列事实、动作、状态变化和历史引用。

### S09 / LearningRecord
保存验证后形成的原子事实、解释和经验，带证据质量、归因强度、适用范围和失效条件。

### 决策模板库
保存“面对某类问题应按什么结构决策”。

### 案例库
保存“一次真实问题实际上发生了什么、用了哪个模板、怎么决策、怎么执行、结果怎样、最终学到了什么”的完整episode。

案例以引用连接 canonical 对象，不复制 DecisionItem、FinalDecision、Task、ValidationResult、LearningRecord 的完整内容作为第二事实源。

---

## 3. Canonical 案例链

```text
Case
├── source_event_refs
├── decision_item_refs
├── context_snapshot_refs
├── conflict_refs
├── template_refs (template_id + version)
├── option_refs
├── decision_refs
├── task_refs
├── execution_result_refs
├── validation_refs
├── learning_refs
├── evidence_refs
└── historical_refs
```

案例负责组织这些引用形成完整叙事，不重定义上游对象。

---

## 4. 一个案例至少回答

- 当时经营背景是什么；
- Scope、生命周期/情境/风险/机会状态是什么；
- 核心 DecisionItem 是什么；
- 当时有哪些关键证据与缺失信息；
- 使用了什么决策模板及版本；
- 有哪些关键候选方案；
- Agent-1 最终为什么做该决策；
- 实际执行了什么；
- 观察窗口和成功/失败标准是什么；
- 实际结果是什么；
- S08 如何验证；
- S09 形成了哪些 LearningRecord；
- 哪些结论可复用、哪些只适用于本产品/阶段；
- 什么条件下该案例不应再被参考。

---

## 5. 案例不是规则

历史案例只能作为证据与参考。

禁止：
- 因“上次这样做成功”就直接重复动作；
- 忽略当前目标、状态、库存、价格、利润、风险和市场差异；
- 用单一案例提升为 validated_knowledge；
- 把失败案例删除；
- 用案例正文覆盖 canonical 历史对象的正式版本。

## 6. 当前治理文件

- `案例总则.md`：案例生命周期、职责和引用规则；
- `Case.schema.json`：案例统一结构；
- `案例分类.md`：成功、失败、冲突、异常、实验、人工纠正等分类；
- `案例复用规则.md`：相似度、新鲜度、适用边界和禁止机械套用；
- `案例索引.md`：case_id、版本、状态、分类和主引用；
- `示例与验收/`：标准示例、反例和静态验收；
- `总验收记录.md`：L3模块门禁结果。
