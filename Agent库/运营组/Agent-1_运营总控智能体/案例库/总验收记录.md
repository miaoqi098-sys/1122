## 3. 职责边界

### 对经营知识库
案例保存具体episode；知识库保存可泛化知识、诊断原则和经营理解。

### 对历史记忆
历史记忆保存时间序列事实；案例通过 historical_refs 组织与当前episode有关的历史，而不是复制历史数据库。

### 对 S09 / LearningRecord
S09保存验证后的原子学习记录；案例只引用 learning_id 并做叙事摘要，不改变 evidence_quality / attribution_strength / promotion_gate。

### 对决策模板库
案例记录当时使用的 template_id + template_version，用于复盘模板有效性，但不能改变模板治理状态。

结论：**边界通过。**

## 4. Canonical 引用链

Case 可以串联：

`Event → DecisionItem → Template → Option → FinalDecision → Task → ExecutionResult → ValidationResult → LearningRecord`

并支持：Context、Conflict、History、StrategyChain 引用。

案例本体不复制 canonical 对象作为第二事实源。

结论：**通过。**

## 7. 版本与治理

已区分：
- case_id：同一episode；
- case_version：案例整理版本；
- case_status：draft / complete / reviewed / archived / invalidated / superseded。

历史版本不得静默覆盖；模板升级也不得重写历史案例当时的模板版本引用。

结论：**通过。**

---

## 8. 示例与静态验收

标准示例明确标记 `example_only / not_real_business_record`，不会被误认为真实经营历史。

示例覆盖：多Agent冲突、广告机会、库存约束、模板引用、任务执行、验证、学习、适用和失效边界。

静态反例覆盖：
- 无验证却声称成功；
- 多变量干扰却强因果；
- 过期案例直接复用；
- 人工纠正无证据；
- Case直接升级validated_knowledge；
- 复制FinalDecision造成双事实源。

结论：**通过。**
