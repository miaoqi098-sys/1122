# 案例索引

## 1. 作用

本文件定义案例登记、版本、状态和关系治理。真实案例增长后，索引可由未来记忆与数据层生成；当前先固定框架语义。

## 2. Case ID

推荐格式：

`CASE-A1-YYYYMM-序号`

例如：`CASE-A1-202608-001`

规则：
- case_id 标识同一经营episode；
- case_version 标识案例整理版本；
- 修改摘要、补验证结果、补Learning引用时提升版本，不创建新的case_id；
- 完全不同episode必须创建新case_id。

## 3. 索引字段

案例索引至少保存：
- case_id
- case_version
- title
- case_status
- case_type
- domain_tags
- scope_summary
- primary_decision_item_ref
- primary_decision_ref
- template_refs
- outcome_status
- attribution_strength
- last_reviewed_at
- valid_until
- relationship_refs
- formal_path / storage_ref

## 4. 状态治理

`draft → complete → reviewed → archived`

异常状态：
- invalidated
- superseded

只有 `reviewed` 默认进入高优先级相似案例检索。

`complete` 可以用于复盘，但应标注尚未通过案例质量门禁。

## 5. 关系类型

案例之间允许记录：
- similar_to
- contrasts_with
- repeats
- follows
- supersedes
- refines
- contradicts
- same_strategy_chain
- same_product_different_stage
- same_pattern_different_product

关系只帮助检索和解释，不等于因果关系。

## 6. 模板引用

案例必须保存当时使用的：
`template_id + template_version + role`

模板后续升级不修改历史案例的原版本引用。
