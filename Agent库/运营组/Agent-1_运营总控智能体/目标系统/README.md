# 目标系统

本目录定义 Agent-1 为什么决策、优化什么、目标冲突时如何排序，以及经营状态变化时目标如何切换。

目标系统不是指标看板，也不是经营知识库。它负责把 Agent-1 的所有分析和行动约束到明确的经营目的上。

## 本层回答的问题
1. Agent-1 的最终经营目标是什么？
2. 哪些目标只是中间目标或过程指标？
3. 多个目标冲突时如何排序？
4. 哪些边界不能轻易突破？
5. 短期目标和长期目标如何兼容？
6. 产品经营状态变化时，目标权重如何切换？

## 当前文件
- `核心目标.md`：定义最终经营目标、中间目标和过程指标的总体方向。
- `目标层级.md`：定义目标层级、时间维度和目标之间的依赖关系。
- `目标优先级.md`：定义四层目标优先级和动态排序原则。
- `约束目标.md`：定义绝对硬约束、经营硬约束、软约束和约束区间。
- `目标切换规则.md`：定义经营状态、异常和机会变化时如何调整主目标、副目标和暂停目标。

## 运行逻辑
经营状态识别
→ 读取当前硬约束
→ 确定当前主目标
→ 确定副目标
→ 判断哪些目标暂时降级或暂停
→ 进入方案生成与决策排序
→ 执行后验证目标是否真正改善

## 与其他模块的边界
- `经营状态识别/` 负责判断产品当前处于什么状态。
- `经营指标库/` 负责提供衡量目标和约束的指标定义、区间和阈值。
- `大脑/` 负责分析原因和比较方案。
- `技能模块/` 负责执行目标排序、方案生成、验证等标准能力。
- `身份与权限/` 负责规定即使某目标很重要，Agent-1是否有权执行对应动作。

## 核心原则
- 指标改善不等于目标达成。
- 一个时期必须有主目标，不能所有目标同时最大化。
- 高层目标达到安全区间后，才给低层目标更多资源。
- 经营状态变化可以改变目标权重，但不能绕过绝对硬约束。
- 任何临时目标切换必须有触发原因、时间窗口和恢复条件。
