# 经营状态共存与优先级

## 目的
真实经营中多个状态经常同时存在。本文件规定哪些状态可以共存、如何处理冲突，以及什么状态应优先影响 Agent-1 的目标和决策。

## 一、基本共存原则
### 生命周期状态
原则上只有一个主要生命周期状态：新品冷启动 / 成长期 / 成熟稳定期 / 衰退调整期。

如果证据处于两个阶段之间，可以标记“过渡中”，但必须指定当前主要阶段和候选下一阶段。

### 经营情境状态
允许多个共存，例如：
- 活动准备 + 价格保护；
- 活动进行 + 广告测试；
- 活动恢复 + Listing测试。

### 风险状态
允许多个共存，例如：
- 库存预警 + 利润承压；
- 商品状态风险 + 合规风险；
- 竞争加剧 + 异常待诊断。

### 机会状态
允许多个共存，也允许与风险同时存在。

## 二、状态优先级不是“只保留一个状态”
优先级决定的是：
- 哪个状态优先改变主目标；
- 哪个状态优先占用资源；
- 哪个状态限制其他行动；
- 哪个状态需要更快处理。

低优先级状态仍然保留在状态画像中。

## 三、默认影响优先级
默认从高到低：
1. 账户级合规风险；
2. 商品不可售或严重商品状态风险；
3. 断货临界、现金底线等生存风险；
4. 其他高等级库存、利润、价格与经营风险；
5. 明确的活动和测试约束；
6. 生命周期阶段；
7. 一般经营优化状态；
8. 增长机会。

该顺序用于冲突处理，不替代 `目标系统/目标优先级.md`。

## 四、风险压制机会
当机会与高优先级风险冲突时：
- 保留机会标签；
- 降低或暂停机会对应行动；
- 优先处理风险；
- 风险解除后重新评估机会是否仍存在。

示例：
```text
O1 核心关键词自然排名快速上涨
+
R2 库存仅能覆盖短期销售
```

不能因为存在增长机会就直接放量。Agent-1 应先判断库存承接能力，必要时采取保护性增长或暂缓扩量。

## 五、活动与正常经营冲突
处于活动准备、活动进行或活动恢复状态时，不应同时把产品解释为完全正常经营。

`正常经营` 是默认经营情境。当存在会显著改变数据解释和策略的特殊情境时，正常经营标签应退出或降为背景状态。

## 六、测试与其他状态共存
测试可以与生命周期、活动、风险和机会共存，但必须检查：
- 测试是否会干扰活动；
- 风险是否已经使测试条件失效；
- 是否有其他动作同时改变同一关键变量；
- 是否仍能可靠判断测试结果。

如果测试条件被破坏，应暂停、终止或重新设计测试，而不是继续等待原观察窗口。

## 七、异常待诊断与具体风险共存
R6 异常待诊断可以与已经确认的风险共存。

例如已确认库存风险，同时订单突然异常下降但原因未知，则可以同时存在：
- R2 库存风险；
- R6 异常待诊断。

当异常根因确认后，应退出 R6 或把它转成更具体状态。

## 八、状态冲突处理
如果两个状态判断互相矛盾：
1. 检查数据时间窗口；
2. 检查指标口径；
3. 检查是否其实属于不同维度；
4. 比较证据质量；
5. 必要时请求专业 Agent 补充；
6. 无法确定时保留“状态不确定”并降低置信度。

不得为了输出一个整齐答案强行删除真实冲突。

## 九、状态画像输出建议
```text
主要生命周期：L2 成长期｜置信度：高
经营情境：C4 活动进行期、C2 Exact测试
高优先级风险：R2 库存预警
其他风险：无
机会：O1 自然关键词增长机会
当前主导状态：R2 库存预警
主导原因：库存风险将限制活动期和增长期的放量空间
```

“主导状态”只表示当前最需要影响目标与行动的状态，不代表其他状态不存在。

## 十、核心原则
经营状态识别的目标不是给产品贴一个标签，而是构建足够准确的经营上下文，让 Agent-1 知道现在应该优先保护什么、利用什么，以及哪些指标不能按平时解释。
