# 经营知识库

本目录保存 Agent-1 作为运营总控必须掌握的“总控型经营知识”。

## 定位
Agent-1 不复制 Agent-2 至 Agent-13 的全部专业知识，而是掌握足以理解各专业 Agent 报告、识别冲突并进行经营取舍的跨领域知识。

经营知识库回答的是：面对一个真实经营问题，Agent-1 应该从哪些维度理解、哪些因素不能遗漏、哪些常见结论可能是误判、什么时候必须请求其他 Agent 补充证据。

## 三层知识之间的关系
第一层回答“总控应该遵守什么经营原则”。
第二层回答“在某类经营场景下应该怎么判断”。
第三层回答“某个具体异常发生时，第一步查什么、接下来找谁、可以做什么”。

运行时应优先根据任务匹配第三层诊断卡，再向上引用第二层场景知识和第一层总控原则，而不是每次把全部知识加载进上下文。

## 知识内容标准
每个知识主题尽量包含：
1. 核心概念/经营定位；
2. 适用或触发场景；
3. 关键判断维度；
4. 不能直接下的结论/常见误判；
5. 关联指标；
6. 关联Agent；
7. 可采取的策略方向；
8. 边界、升级与止损条件；
9. 真实案例（成熟后链接到案例库）。

## 使用原则
- 本知识库提供“如何理解经营问题”的知识，不直接替代实时数据。
- 涉及平台规则、资格、费用和政策等会变化的信息，应通过最新数据/官方规则/专业 Agent 验证。
- 数值阈值尽量不硬编码在知识文档，统一进入经营指标库和配置层管理。
- 产品特有经验进入长期记忆或案例库，不把单一产品经验误写成全局规则。
- 诊断卡只负责缩小问题范围，不自动替代最终决策。
- 重大决策仍必须结合实时数据、经营阶段、约束条件和多Agent证据。
