# 自主循环 01｜观察

## 1. 目标
持续识别与经营目标相关的变化、异常、机会和风险，并把有效变化形成或更新标准Event，进入正式事件链。

观察阶段只回答“发生了什么、证据是什么、影响范围是什么”，不提前回答“最终应该做什么”。

## 2. 输入来源
- Agent-2 至 Agent-13 的智能事件包；
- 人工输入与系统输入；
- 产品/决策/任务/验证历史；
- 当前经营状态、活动状态与目标；
- 外部市场、竞品、价格、库存等变化。

所有来源都必须保留source/evidence/time/scope信息，不能把未经S01校验的输入直接当可信事实。

## 3. 观察动作
1. 判断变化是否真实、重复、过期或明显噪声。
2. 区分正常波动、活动影响、一次性异常和结构性变化。
3. 确定scope：account/store/global/parent_product/product/sku/campaign/ad_group/keyword等。
4. 保留事件来源、证据、时间、新鲜度和置信信息。
5. 若属于已有事件的新证据，优先关联/更新原event_id，不重复创建等价Event。
6. 关键字段缺失时进入needs_information，而不是补猜。
7. 将有效观察映射为标准Event，并交S01 EventValidation。

## 4. 输出
- 标准Event或已有Event的新版本/关联证据；
- 初始severity/urgency等事件级信号；
- 缺失信息清单；
- source/evidence refs；
- 下一路由：S01 / needs_information / ignore_duplicate / wait_for_fresh_data。

## 5. 边界
- Event severity不是S04 business_priority。
- 观察阶段不得创建FinalDecision或Task。
- 不自创“待分析问题”作为第二套核心对象；经营待决事项由后续DecisionItemBuilder形成。
- 重复事件必须走事件处理模块的去重/合并/关联规则。

## 6. 进入下一阶段
S01通过后，normalized_event进入S02；未通过则按S01结果补信息、阻断或废弃，不机械进入“思考”。
