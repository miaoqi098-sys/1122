# 自主循环示例与静态验收

## 示例A｜正常循环
1. Agent-4发现广告高点击低转化，形成标准Event。
2. S01通过后S02形成ContextPackage，S03识别无阻断冲突。
3. DecisionItemBuilder形成DecisionItem。
4. S04排序，S05生成多个Option，S06评估风险。
5. DecisionSelector形成FinalDecision。
6. S07生成TaskPlan/Task，等待审批/执行。
7. Executor真实执行，回执经ExecutionResultNormalizer形成ExecutionResult。
8. S08观察窗口后生成ValidationResult。
9. S09生成LearningRecord/memory_writes plan。
10. 没有新Event时进入waiting_for_event，而不是马上重复一轮。

## 示例B｜同一事件补证据
原Event缺关键转化分母。补证据后复用原event_id/DecisionItem关联，只重跑受影响的S02/S03/S06阶段，不创建第二套等价业务链。

## 示例C｜审批等待
FinalDecision要求审批。S07生成pending_approval任务后循环进入等待。审批未返回前不得重复创建相同Task；批准后从原resume_from继续。

## 示例D｜策略反转
新Option与当前StrategyChain方向相反。先进入S10。若hold，则进入hold_for_review，不创建反向Task；若override，则创建新Decision并保留旧Decision/Task历史。

## 示例E｜执行成功但验证未达标
ExecutionResult显示API动作成功，但S08确认经营指标未达到success criteria。ValidationResult记录“未达标”，再决定继续观察、新诊断、回滚或新Decision，不把执行链改写为失败。

## 示例F｜学习不等于已写入
S09形成LearningRecord与memory_writes plan，但没有LearningWriteExecutor回执。正确状态是“写入计划已生成”，不能声称长期记忆已经written。

## 静态验收
- [x] 六阶段全部映射到canonical业务对象链。
- [x] 观察阶段只形成/更新Event并进入S01，不自创第二套核心对象。
- [x] 思考阶段对齐S02/S03/DecisionItemBuilder，不越权下最终决策。
- [x] 计划阶段对齐S04/S05/S06/S10/DecisionSelector/FinalDecision。
- [x] 行动阶段只到S07及真实执行等待，Task创建不等于执行成功。
- [x] 验证阶段必须以ExecutionResult为前置并通过S08形成ValidationResult。
- [x] 学习阶段只通过S09生成LearningRecord/memory_writes plan，真实写入归R10。
- [x] 存在blocked/approval/hold/awaiting_validation等合法休眠状态。
- [x] 无新证据时禁止重复创建等价Event/Decision/Task/LearningRecord。
- [x] StrategyChain方向变化受S10控制。
- [x] 真实Scheduler/Executor/数据库等没有混入Agent库。
