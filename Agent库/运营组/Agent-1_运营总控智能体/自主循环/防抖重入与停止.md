# 自主循环｜防抖、重入与停止

## 1. 目标
防止 Agent-1 因相同事件、短期波动、审批等待或验证失败而无限重复“观察→思考→计划→行动→验证→学习”。

## 2. 允许重入的条件
只有出现以下新条件之一，才允许从相关断点重入：
- 新Event或原Event出现关键新证据；
- ContextPackage中的目标、状态、约束或事实版本变化；
- approval/blocked condition解除；
- review_trigger、stop_condition或观察窗口结束；
- 新ExecutionResult或ValidationResult产生；
- StrategyChain发生允许的merge/override；
- 旧对象过期，需要重新评估。

## 3. 禁止无效重入
以下情况不得启动新一轮：
- 同一Event无任何新证据；
- 同一DecisionItem只因时间经过很短而重复生成；
- S10 hold后立即创建相同反向Option；
- pending_approval期间重复创建Task；
- 观察窗口未结束却反复S08；
- S09已生成同一ValidationResult对应的LearningRecord后再次写等价记录。

## 4. 对象复用与幂等
重入时优先复用/版本化：
- event_id；
- decision_item_id；
- strategy_chain_id；
- decision_id（若只是等待审批/执行）；
- task_plan_id/task_id（若未发生需重编排的决策变化）；
- validation链与learning来源引用。

出现真正新决策时可以产生新decision_id，但必须保留supersedes/replaces/strategy链关系，不覆盖旧记录。

## 5. S10防抖
策略方向变化必须检查：
- 当前观察窗口是否结束；
- 新证据是否足以支持反转；
- 是否只是活动/短期噪声；
- 是否已有相同方向Decision正在执行；
- 替换是否需要审批/controls。

S10结果为hold时，循环进入等待，不为了“保持循环活跃”继续生成反向任务。

## 6. 停止/休眠状态
自主循环允许进入：
- `waiting_for_event`
- `waiting_for_evidence`
- `pending_approval`
- `awaiting_execution`
- `awaiting_validation`
- `hold_for_review`
- `closed`

这些状态都不是系统失败。

## 7. 唤醒条件
- 新智能事件包或人工/系统Event；
- 新证据到达；
- 审批结果；
- Task/ExecutionResult状态变化；
- 观察窗口结束；
- review_trigger/stop_condition；
- 风险/机会状态显著变化。

## 8. 循环熔断
若连续多轮只产生相同对象/相同路由且没有新证据：
1. 不再创建新Decision/Task；
2. 转入`waiting_for_evidence`或`hold_for_review`；
3. 记录最后有效business object与resume_from；
4. 等待真正的新触发。

## 9. 运行边界
真实去重锁、定时唤醒、状态持久化和并发控制属于未来Runner/Scheduler/记忆层；本文件只定义业务级幂等与循环语义。
