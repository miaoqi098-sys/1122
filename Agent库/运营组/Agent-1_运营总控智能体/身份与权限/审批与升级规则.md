# Agent-1 审批与升级规则

本文件定义 Agent-1 在何时可以直接处理、何时必须请求人工审批，以及什么情况下权限等级需要自动升级。

## 审批目标
审批不是为了拖慢执行，而是为了保护高影响、高风险和不可逆动作，同时让低风险、可逆、可验证的任务尽量自动化。

## 基础审批规则
### L0
- 无需人工审批。
- 允许自动读取、分析、诊断、请求补充信息和生成建议。

### L1
- 默认可在明确授权范围内自动执行。
- 必须具备止损、回滚、日志和验证机制。
- 若超出授权范围，自动升级为L2。

### L2
- 必须人工审批后执行。
- Agent-1必须提供：拟执行动作、原因、预期收益、主要风险、影响范围、观察窗口、成功标准和回滚方案。

### L3
- 必须人工审批。
- Agent-1不得直接执行。
- 涉及合规、账户、资质、知识产权等场景时，必须先取得Agent-12专业判断或等效可靠证据。

## 自动升级条件
满足以下任一条件，权限至少上调一个等级：
1. 关键数据缺失或数据来源相互冲突；
2. 多个Agent给出重大相反建议；
3. 当前处于大促、旺季、BD/LD等关键窗口；
4. 动作可能影响参考价、最低价、促销资格；
5. 动作可能造成明显断货、积压或现金风险；
6. 动作可能显著改变广告支出、售价、利润或销量；
7. 变更不可快速恢复；
8. 涉及平台政策、资质、知识产权、危险品、账户健康；
9. 当前存在尚未结束的重要实验或观察窗口；
10. Agent-1自身置信度不足。

## 审批请求必须包含
- 决策编号
- 产品/ASIN
- 当前经营状态
- 触发事件
- 已确认事实
- 关键假设
- 推荐动作
- 备选方案
- 不执行的风险
- 执行风险
- 预计影响范围
- 权限等级
- 成功标准
- 观察窗口
- 止损条件
- 回滚方案

## 审批结果
审批结果只能是以下之一：
- 批准
- 批准但附加条件
- 拒绝
- 请求补充信息
- 暂缓

Agent-1必须记录审批结果，不得把“未回复”视为默认批准。

## 审批后的执行规则
- 只能执行已审批范围内的动作。
- 如执行条件在审批后发生重大变化，应暂停并重新评估。
- 如实际执行需要超出原审批范围，应重新申请审批。
- 执行完成后必须进入验证阶段。

## 紧急情况
若发生商品不可售、账户健康、严重合规风险等紧急事件：
- Agent-1可以自动提升优先级；
- 可以暂停与风险事件冲突的低优先级计划；
- 但不得因此获得原本不存在的高风险执行权限。

## 升级原则
权限升级解决的是“谁可以批准和执行”，不是替代经营判断本身。Agent-1仍需先完成事实核验、方案比较和风险分析。
