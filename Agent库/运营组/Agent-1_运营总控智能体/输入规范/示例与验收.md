# 输入规范示例与静态验收

## 示例A｜商品级专业Agent事件
```json
{
  "event_id": "EVT-001",
  "source_type": "professional_agent",
  "source_agent": "Agent-4",
  "event_type": "advertising_efficiency_drop",
  "scope_type": "product",
  "scope_id": "ASIN-B0XXX",
  "product_id": "ASIN-B0XXX",
  "severity": "P1",
  "occurred_at": "2026-08-30T02:00:00+08:00",
  "summary": "核心Exact词点击增加但未转化",
  "facts": ["最近14天30点击0订单"],
  "recommendation": null,
  "evidence_refs": ["ads-report:2026-08-16/2026-08-29"]
}
```
验收：product作用域有product_id；recommendation允许为空；来源可追溯。

## 示例B｜账户级系统事件
```json
{
  "event_id": "EVT-002",
  "source_type": "system",
  "source_actor": "account-monitor",
  "event_type": "account_risk_signal",
  "scope_type": "account",
  "scope_id": "US-store",
  "product_id": null,
  "severity": "P0",
  "occurred_at": "2026-08-30T02:10:00+08:00",
  "summary": "账户级风险信号",
  "facts": ["检测到需要复核的账户状态变化"]
}
```
验收：账户级事件不伪造ASIN；系统输入不自动成为专业经营结论。

## 示例C｜专业Agent返回证据不足
```json
{
  "request_id": "REQ-101",
  "source_agent": "Agent-7",
  "analysis_scope": {"type": "product", "id": "ASIN-B0XXX"},
  "facts": [],
  "interpretation": [],
  "conclusion": "当前无法可靠判断补货窗口",
  "recommendation": null,
  "confidence": 0.3,
  "data_window": "最近7天",
  "evidence_refs": [],
  "missing_data": ["在途到仓时间"],
  "risks": ["过度补货或断货判断偏差"],
  "status": "insufficient_evidence"
}
```
验收：允许明确证据不足，不要求编造recommendation。

## 示例D｜人工审批输入
人工输入：`input_kind=approval`，只表示批准某决策/任务，不得转写成“经营结果成功”。

## 静态验收
- [x] 旧Schema的 `recommendation` 已从硬必填移除。
- [x] account/store/global 允许 `product_id=null`。
- [x] product/parent_product/sku 仍要求有效product_id。
- [x] 支持 professional_agent/system/human/external 来源类型。
- [x] 专业Agent结构化结果有 request_id/source_agent/data_window/confidence/missing_data/risks。
- [x] Event 与 ContextPackage 边界明确，S02只消费S01 normalized_event。
- [x] run_id/trace_id 与业务主键语义分离。
- [x] 人工偏好、授权、系统失败不会被伪装成客观事实。
