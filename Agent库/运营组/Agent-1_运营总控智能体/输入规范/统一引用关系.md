# 统一引用关系

## 1. 业务主键与运行追踪分离
- `event_id / request_id / decision_id / task_id`：业务对象主键。
- `run_id / trace_id / parent_run_id`：运行调用追踪，不替代业务主键。

## 2. 来源引用
输入对象应尽量保留：
- `source_type`
- `source_agent` 或 `source_actor`
- `source_ref`
- `evidence_refs[]`
- `related_events[]`
- `parent_event_id`

## 3. 请求/返回关系
专业Agent返回必须通过 `request_id` 回链原请求；不得只凭 source_agent 猜测属于哪次分析。

## 4. 事件关系
- `parent_event_id`：明确派生父事件；
- `related_events[]`：相关但非父子；
- 重复/近重复关系由事件处理/S01记录，不通过改写 event_id 合并历史。

## 5. 证据引用
事实、解释、建议必须能区分。evidence_refs 指向证据来源，不应直接存储运行时临时对象地址作为长期业务引用。

## 6. 时间引用
至少区分：
- `occurred_at`：事实/事件发生时间；
- `received_at`：Agent-1接收时间；
- `data_window`：分析数据窗口；
- `valid_until/review_at`：结论有效期或复核时间。

禁止用 received_at 替代 occurred_at 推断事件新鲜度。
