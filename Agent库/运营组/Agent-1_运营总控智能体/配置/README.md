# Agent-1 配置

## 1. 模块定位
`配置/` 只定义 Agent-1 框架层允许被参数化、引用或覆盖的静态配置入口，以及这些配置与正式规则/Schema之间的关系。

配置不能替代：
- 决策规则；
- 目标系统；
- 经营指标库；
- 经营状态识别；
- Skill接口；
- 任务调度/执行运行状态。

## 2. 配置类型
允许在本模块声明：
- Agent身份和版本引用；
- canonical输入/输出Schema路径；
- 运行模式开关的框架默认值；
- 审批/策略/历史上下文等“是否需要”类开关；
- 规则文件引用；
- 配置版本、兼容性和覆盖策略；
- 未来运行层需要注入的参数占位。

## 3. 禁止复制业务规则
以下内容不能在配置里重新定义一遍：
- 固定经营优先级；
- 具体利润/库存/转化等业务阈值；
- 硬编码审批等级替代FinalDecision approval语义；
- S04/S06/S10完整判断逻辑；
- Task状态机或执行器状态；
- 动态经营事实。

配置只引用规则来源，避免形成“规则文件一套、YAML又一套”的双真源。

## 4. Canonical引用
当前核心引用：
- Event：`../输入规范/智能事件包.schema.json`
- FinalDecision：`../输出规范/FinalDecision.schema.json`

旧 `决策指令.schema.json` 仅用于兼容，不作为新配置的 canonical 决策输出。

## 5. 覆盖原则
框架层配置只定义覆盖顺序，不实现真实环境加载：

`系统默认 → Agent默认 → 店铺/账户/产品范围覆盖 → 单次运行显式覆盖`

任何覆盖都不得突破身份权限、硬约束、合规要求或canonical Schema。

## 6. 版本原则
配置必须保留：
- config_version；
- compatible_agent_version；
- schema refs；
- deprecated字段迁移说明。

重大不兼容变化应升级配置版本，不静默改变旧字段语义。

## 7. 运行边界
真实配置加载、环境变量、密钥、动态远程配置、热更新、配置中心和Schema运行校验属于系统运行/公共层。Agent库只定义配置合同。
