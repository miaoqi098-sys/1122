# Agent-3｜标准示例

## 示例1｜竞品价格与促销变化事件
背景：direct_competitor在同一marketplace连续两次观察到售价下降，并新增Coupon；两个快照可比。

事件要点：
```text
source_type: professional_agent
source_agent: Agent-3
event_type: competitor_price_shift
scope_type: product
product_id: OUR-ASIN-001
severity: P2
facts:
- 竞品ASIN B0XXXX售价从39.99降至34.99
- 同期新增10% Coupon
- 第二次复核仍保持该状态
metrics:
  competitor_entity_id: CMP-001
  relationship_type: direct_competitor
  baseline_snapshot_id: CS-100
  current_snapshot_id: CS-102
confidence: 0.91
recommendation: 建议Agent-10评估我方价格/促销响应空间；该建议不是已批准动作
```

## 示例2｜搜索位置波动但证据不足
只观察到某关键词一次从第1屏移至第2屏，后续页面上下文不同。

正确处理：
- 保存新快照；
- comparison_eligible=false或低confidence；
- 不生成“竞品排名持续下降”结论；
- 等待同口径复核。

## 示例3｜Agent-1定向请求
问题：目标ASIN最近7天主要竞争动作是什么？

专业结果应：
- analysis_scope明确我方产品、竞品、marketplace、7天窗口；
- facts列出价格/促销/Listing等可验证变化；
- interpretation说明哪些是持续动作、哪些只是单次观察；
- conclusion给竞争层结论；
- missing_data列出无法确认的销量/广告等；
- recommendation可建议调用Agent-8/9/10，但不生成FinalDecision。

## 示例4｜竞品关系失效
原traffic_competitor连续多个复核周期不再出现在相关核心关键词且产品定位改变。

处理：
`active → downgraded → removed`
保留原relationship_evidence、有效期和历史事件，不删除实体历史。
