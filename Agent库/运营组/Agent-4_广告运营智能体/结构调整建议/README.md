# Agent-4｜广告结构调整建议

## 1. 目标
结构调整用于提高可控性、可解释性、预算与竞价独立性，以及搜索意图隔离能力。结构调整不是为了追求“越细越好”，而是为了让不同目标、生命周期、流量价值和观察需求可以独立管理。

## 2. 可诊断结构问题
- 一个ad group混入明显不同意图/生命周期的target；
- 高价值与低价值流量无法独立竞价；
- 探索型Broad/Auto与成熟Exact共享预算导致互相挤压；
- 多变体混投后无法判断真实承接差异；
- 同一搜索意图在多个结构重复但缺乏目的性；
- 品牌词/类目词/竞品词等意图混合导致口径失真；
- 测试结构长期不收口；
- campaign过碎造成样本不足和维护成本异常。

## 3. 建议动作
- split_campaign
- split_ad_group
- isolate_target
- isolate_search_intent
- isolate_variant
- merge_low_signal_structure
- archive_test_structure
- create_exploration_lane
- create_harvest_lane

每个建议必须说明“为什么现有结构无法实现控制目的”。

## 4. 拆分条件
满足以下至少一种才建议拆分：
- 需要独立预算；
- 需要独立竞价/placement；
- 需要独立否定策略；
- 需要不同观察窗口/目标；
- 需要隔离变体、品牌/非品牌、竞品/类目或成熟/探索流量；
- 现有聚合导致诊断无法归因。

## 5. 合并条件
以下情况可提出合并候选：
- 长期样本极低且无独立控制价值；
- 多个结构目标、竞价、预算、流量意图高度一致；
- 过度拆分导致无法形成有效样本；
- 历史测试结束且没有继续独立管理理由。

合并前必须保留历史映射，不得丢失旧entity_id与策略链引用。

## 6. 变体治理
同一父体下多个子ASIN是否共用广告结构，不做一刀切。需判断：价格、颜色/规格意图、转化率、库存、利润、评价基础和广告承接差异。若差异会导致预算/竞价/诊断需求不同，应建议隔离；若差异小且样本不足，可保持共享结构。

## 7. 重叠治理
重叠不等于必须清理。必须先判断：
- 重叠是否承担不同探索/成熟职责；
- 是否存在预算抢占；
- 是否产生明显流量分散或成本抬升；
- 能否通过否定/竞价/预算而非结构迁移解决。

## 8. 迁移安全
结构调整建议必须带：source_entities、target_structure、migration_steps、history_mapping、observation_window、rollback_condition、risk。禁止建议一次性大规模迁移且不保留对照窗口。

## 9. 边界
Agent-4可以设计广告结构候选方案；跨ASIN资源分配、利润目标、库存承接、促销节奏与最终迁移批准由Agent-1整合其他专业Agent决定。
