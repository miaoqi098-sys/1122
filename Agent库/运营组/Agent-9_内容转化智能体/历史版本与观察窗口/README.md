# 历史版本与观察窗口

## 目的
内容与转化判断必须能回答“哪个内容版本在什么时间生效、当时还有哪些变化”，避免把无法追溯的页面修改当成实验结果。

## 内容版本
每次内容变更至少记录：
- version_id；
- content_type；
- scope；
- changed_fields；
- before_ref；
- after_ref；
- published_at；
- verified_frontend_at；
- source；
- reason；
- related_decision/task。

## 观察窗口
- 发布验证窗口：确认前台真正生效；
- 短期观察：识别明显异常，但不急于因果结论；
- 最小效果窗口：根据流量/订单样本设定；
- 稳定窗口：避开大促、断货、价格大改等强混杂；
- 长期复核：观察退货/VOC是否与短期CVR改善方向一致。

## 基线选择
优先使用变更前稳定窗口；若变更前存在大促、断货、流量重构，则应向前寻找可比窗口或标记基线低可信。

## 混杂因素日志
内容变更同期发生的以下事件必须绑定：广告变动、价格/促销、评分/VOC、库存/配送、竞品/市场异常、变体变化。

## 版本失效
如果后续内容版本已覆盖旧版本，旧版本仍保留历史证据，但不得作为当前页面事实。

## 与记忆层关系
内容版本和转化结果未来由R06长期记忆持久化；当前Agent框架只定义对象、引用和复用规则。
