# 运营组

## 总体定位
运营组负责亚马逊商品从状态监控、竞争/市场情报、广告与流量、利润库存、内容价格、评价风险到增长机会的完整运营判断。组织采用“1个总控 + 12个专业Agent + 1个共享公共协议层”的结构。

`公共协议/` 不是第14个Agent，不拥有业务判断职责；它只保存Agent之间必须共享的交接、职责和协作静态合同。

## 职责地图
| Agent | 主责 | 不负责 |
|---|---|---|
| Agent-1 | 目标、上下文、冲突、跨域方案、FinalDecision、任务编排与验证学习闭环 | 不替专业Agent长期维护各专业事实 |
| Agent-2 | 商品前后台状态、可售、变体、Buy Box、资质状态事实 | 不解释完整政策合规 |

| Agent-5 | 流量来源、搜索可见性、流量结构与归因 | 不做广告执行或内容主诊断 |

| Agent-12 | 风险分类、政策规则、资格门、整改/申诉证据 | 不做法律/平台最终裁定 |
| Agent-13 | 增长机会发现、评估、去重组合、验证设计 | 不成为第二个Agent-1 |

详细交叉边界见：`公共协议/职责覆盖矩阵.md`。

## 标准协作模式
1. 专业Agent产生领域事件、专业响应或协作请求；
2. 按 `公共协议/` 规范化为Agent-1可消费的Canonical Event/专业Agent结果；
3. Agent-1加载产品/策略历史和其他相关Agent证据；
4. Agent-1完成冲突检测、决策排序、方案生成、风险评估；
5. Agent-12提供风险资格/硬约束；
6. Agent-1形成唯一FinalDecision；
7. S07生成任务，执行层未来落实；
8. S08验证，S09学习写回，S10约束策略反转。

典型跨Agent路由见：`公共协议/跨Agent协作路由.md`。

## 冲突处理
专业Agent之间不直接争夺“最终正确”。发生冲突时先识别：事实、口径、新鲜度、因果解释、目标或硬约束冲突。事实/口径/时效/解释冲突优先补证；跨目标与硬约束冲突交Agent-1统一处理。
