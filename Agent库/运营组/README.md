# 运营组

## 总体定位
运营组负责亚马逊商品从状态监控、竞争/市场情报、广告与流量、利润库存、内容价格、评价风险到增长机会的完整运营判断。组织采用“1个总控 + 12个专业Agent”的结构。

## 职责地图
| Agent | 主责 | 不负责 |
|---|---|---|
| Agent-1 | 目标、上下文、冲突、跨域方案、FinalDecision、任务编排与验证学习闭环 | 不替专业Agent长期维护各专业事实 |
| Agent-2 | 商品前后台状态、可售、变体、Buy Box、资质状态事实 | 不解释完整政策合规 |
| Agent-3 | 竞品池、竞品快照、竞争变化 | 不做宏观市场趋势主判断 |
| Agent-4 | 广告实体、搜索词、竞价、预算、广告诊断 | 不把ACOS当利润、不直接跨域决策 |
| Agent-5 | 流量来源、搜索可见性、流量结构与归因 | 不做广告执行或内容主诊断 |
| Agent-6 | 收入成本、贡献利润、break-even、财务约束 | 不直接调广告/价格/库存 |
| Agent-7 | 库存状态、需求覆盖、补货、供应周期、断货/积压 | 不做利润/价格最终方案 |
| Agent-8 | 市场趋势、季节性、类目热度、外部信号 | 不替Agent-3做具体竞品事实 |
| Agent-9 | Listing内容、页面结构、转化诊断、内容实验 | 不做流量获取、评价主诊断 |
| Agent-10 | 售价、参考价、促销、活动资格、价格历史 | 不做利润核算或最终改价 |
| Agent-11 | 评分、评论、VOC、退货体验、异常评价模式 | 不直接定性评价违规/操纵 |
| Agent-12 | 风险分类、政策规则、资格门、整改/申诉证据 | 不做法律/平台最终裁定 |
| Agent-13 | 增长机会发现、评估、去重组合、验证设计 | 不成为第二个Agent-1 |

## 标准协作模式
1. 专业Agent产生专业事件或响应；
2. Agent-1加载产品/策略历史和其他相关Agent证据；
3. Agent-1完成冲突检测、决策排序、方案生成、风险评估；
4. Agent-12资格门约束高风险方案；
5. Agent-1形成唯一FinalDecision；
6. S07生成任务，执行层未来落实；
7. S08验证，S09学习写回，S10约束策略反转。

## 冲突处理
专业Agent之间不直接争夺“最终正确”。当广告增长与库存、利润、风险、价格等发生冲突时，各Agent只提供本域事实和约束，交Agent-1在目标系统中统一权衡。
