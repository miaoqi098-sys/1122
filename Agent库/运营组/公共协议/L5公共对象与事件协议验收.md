# L5｜公共对象与事件协议验收

## 验收范围
Agent-1 至 Agent-13 的跨 Agent Event / 专业分析响应交接语义，重点检查：Event、Scope、证据、时间、置信度、severity、事实/解释/建议边界以及 Agent-1 可统一消费性。

## 发现的问题
1. Agent-2 当前直接遵循 Agent-1 `输入规范/智能事件包.schema.json`，不存在第二份 Event Schema。
2. 部分专业 Agent 为保留领域语义建立了自己的事件 Schema。例如：
   - Agent-4 `AdvertisingIntelligenceEvent.schema.json` 使用嵌套 scope、`info/low/medium/high/critical` severity、标签型 confidence、generated_at；
   - Agent-13 `GrowthOpportunityEvent.schema.json` 使用 opportunity_type、observed_at、constraint_status 等增长领域字段。
3. 这些领域对象不应被直接送入 Agent-1 S01，否则与 Agent-1 Canonical Event 的必填字段和枚举不兼容。
4. 专业请求响应也存在领域 Schema，例如 Agent-4 `AdvertisingAnalysisResponse`，其 responder_agent、diagnoses、data_quality 等字段与 Agent-1 `专业Agent结果.schema.json` 并不同构。

## 本次正式修复
新增 `Agent库/运营组/公共协议/`，确立两层交接模型：

`Professional Domain Event → Canonical Intelligent Event → Agent-1`

`Professional Domain Response → 专业Agent结构化结果 → Agent-1`

正式文件：
- `README.md`
- `专业Agent事件协议.md`
- `专业Agent响应协议.md`
- `ProfessionalAgentEventHandoff.schema.json`
- `事件字段映射表.md`
- `示例/Agent4广告事件交接.example.json`

并更新 Agent-4 `事件输出/README.md`，明确 `AdvertisingIntelligenceEvent` 是领域对象而不是 Agent-1 第二份标准 Event。

## Canonical 权威规则
- Agent-1 `智能事件包.schema.json`：唯一主动事件入站标准。
- Agent-1 `专业Agent结果.schema.json`：唯一专业请求响应入站标准。
- Agent-2 至 Agent-13 可以保留领域对象，但必须可规范化后再交给 Agent-1。
- 领域对象完整细节通过 handoff / metadata / source_ref 保留，不强迫所有内部 Schema 同构。

## 公共字段门禁
- [x] Event 主键与领域事件 ID 可追溯。
- [x] source_agent 统一到 Agent-2..13。
- [x] Scope 有统一主 scope + scope_objects 映射规则。
- [x] severity 统一到 Agent-1 P0-P3。
- [x] confidence 统一到 0-1，原标签保留。
- [x] occurred_at 与 generated_at / observed_at 语义已区分。
- [x] evidence_refs 可透传。
- [x] facts 与 diagnosis/hypothesis/recommendation 明确分离。
- [x] recommendation 不成为 FinalDecision。
- [x] run_id / trace_id 留在运行调用信封，不污染业务对象。
- [x] 专业响应 request_id 必须沿用原请求。
- [x] 专业响应 status、facts、interpretation、missing_data、risks 有统一映射规则。

## 兼容策略
本次没有批量重写 Agent-4/13 等已封板领域 Schema，因为那属于高影响且没有必要的结构迁移。共享协议采用可逆、增量方式完成跨 Agent 兼容。

## 运行依赖
新增 R16 `ProfessionalAgentEventAndResponseNormalizer`：未来负责真实字段/语义规范化；R03 `Schema Validator` 负责结构验证。当前只完成静态合同，不进入运行层。

## L5结论
**通过。**

当前 Agent库 已形成统一的跨 Agent 事件/响应消费原则。后续新专业 Agent 或新领域 Schema 必须先证明可以映射到 Agent-1 Canonical Event / 专业Agent结果，不允许自行创建新的总控入站标准。
