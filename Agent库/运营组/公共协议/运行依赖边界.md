# Agent库运行依赖边界 V1.0

## 1. 原则
Agent库负责定义业务智能体的职责、对象、规则、输入输出、协作、数据需求、工具需求与静态验收；不负责把这些能力部署成真实运行系统。

判断标准：
- **如果缺少它会导致Agent不知道“应该判断什么/输出什么”** → 必须在Agent库框架内定义。
- **如果Agent已经知道合同，但缺少真实调用、持久化、调度、采集或执行能力** → 属于共享运行依赖。

因此“尚未真实运行”本身不能阻塞Agent库静态框架封板。

## 2. R01-R16分类
### 系统运行/调用
- R01 Skill Runner：执行S01-S10调用链。
- R02 Agent Runner：装载专业Agent、上下文、工具与调用。
- R03 Schema Validator：运行时机器校验业务对象。
- R07 调度器：定时/事件唤醒、依赖、重试与队列推进。
- R11 StrategyChain持久化与更新：运行时策略链长期状态。
- R16 ProfessionalAgentEventAndResponseNormalizer：领域事件/响应到Agent-1 Canonical对象的真实转换。

### 数据接口/采集
- R04 Amazon SP-API Connector。
- R05 Amazon Ads API Connector。
- R12 前台商品页状态采集与监控。
- R13 竞品搜索与竞争情报采集。
- R14 市场趋势与外部信号采集。
- R15 Amazon政策、账户健康与合规规则数据源。

### 记忆与数据持久化
- R06 长期记忆数据库。
- R10 LearningWriteExecutor。

### 执行与回执
- R08 执行器。
- R09 ExecutionResultNormalizer。

## 3. Agent库当前必须已定义的静态边界
虽然R01-R16不实施，但Agent库必须已经定义：
- Skill/Agent要消费和输出的业务对象；
- Event、专业响应、FinalDecision、Task、ExecutionResult、ValidationResult、LearningRecord等主要合同；
- 数据来源、时效、新鲜度、证据和缺失/降级要求；
- 哪些动作需要审批、哪些动作禁止自动执行；
- 调度生命周期、观察窗口、失败/阻塞/回滚语义；
- 领域事件/响应到Agent-1 Canonical对象的静态映射；
- 长期记忆写入计划与真实写入回执的区别；
- 真实执行成功与经营结果验证成功的区别。

如果以上任一项缺失，不能用“以后运行层再做”逃避框架定义。

## 4. 不应继续放进Agent库的实现
- OAuth/API认证和密钥管理；
- HTTP请求、限流、分页和重试代码；
- 数据库选型、表结构部署、索引引擎实现；
- 消息队列、定时器、Worker；
- 真实Amazon广告/价格/Listing/库存写操作；
- 服务器、容器、CI/CD、生产监控；
- 模型运行编排与实际token/并发管理；
- 真实normalizer/validator代码。

这些应分别进入 `系统运行层/数据接口层/记忆与数据层/调度与自动化层/执行层/系统公共层`。

## 5. 依赖复用原则
专业Agent不得因为自身需要相同运行能力而重复定义新的Connector/数据库/Runner。例如：
- A2/A9/A10/A11共享R12前台事实能力；
- A4/A6共享R05广告数据；
- 多Agent历史统一依赖R06；
- 所有领域Schema统一依赖R03验证；
- 所有专业领域对象规范化统一依赖R16，而非每个Agent各建一个Normalizer。

## 6. 框架封板条件
运行依赖存在时，只要满足以下条件即可静态封板：
1. 依赖名称和职责明确；
2. 与Agent框架边界明确；
3. 当前所需静态输入输出合同已定义；
4. 缺少真实实现不会导致业务语义无法确定；
5. 测试中明确区分静态PASS与运行期BLOCKED_RUNTIME；
6. 不伪造真实执行/持久化/采集成功。

## 7. 后续启动运行层时
未来启动系统运行建设，应从 `临时建设任务/运行依赖待办.md` 的R01-R16以及本文件反向生成各共享基础设施层任务，而不是重新从专业Agent中猜测需求。
