# 事件去重规则

## 1. 目的
防止同一事实被不同时间、不同来源或重复上报无限生成事件与决策链，同时保留完整来源和证据历史。

## 2. 两阶段去重机制
### 阶段A｜候选检索
可生成 `event_fingerprint`，用于从历史事件中快速找到可能重复的候选集。

建议 fingerprint 至少基于稳定字段组合：
- scope / 业务对象；
- event_type；
- subject / 核心指标或问题键；
- 核心变化方向；
- occurrence window / 时间桶。

fingerprint 必须带 `fingerprint_version`，规则变化时允许版本升级。

### 阶段B｜最终去重判断
fingerprint 只负责候选检索，不能直接决定 exact_duplicate。最终仍必须结合上下文逐项比较：
- scope / 业务对象；
- event_type；
- 核心事实；
- occurred_at 与时间窗口；
- source/evidence refs；
- severity；
- 关键指标变化方向；
- 是否存在新证据、新周期事实；
- 是否属于同一 StrategyChain/DecisionItem；
- 差异是否会改变风险、机会、资格或决策方向。

## 3. 结果分类
- `exact_duplicate`：同一事实重复上报；
- `near_duplicate`：核心问题相同但来源/窗口略有差异；
- `update_existing`：同一事件出现新证据或状态变化，应更新已有事件；
- `related_not_duplicate`：相关但不能合并；
- `new_event`：独立新事件。

这些属于 `processing_disposition`，不与 event_status 混用。

## 4. exact_duplicate
处理：
- 不创建新 canonical 事件；
- 新 event_id 保留在 source/duplicate 记录；
- 指向 `duplicate_of=canonical_event_id`；
- 追加 source/evidence refs；
- 不重复触发 DecisionItem，除非新上报包含会改变判断的证据。

## 5. near_duplicate
必须判断差异是否会改变：
- severity；
- scope；
- root problem；
- deadline/opportunity window；
- eligibility/风险；
- 当前策略方向。

若不会改变，归入已有事件；若会改变，使用 update_existing 或独立相关事件。

## 6. 新证据不是重复
同一问题但出现：
- critical_new_fact；
- scope 扩散；
- severity 实质变化；
- 新时间窗口；
- 原事件 resolved/closed 后再次真实发生；
不能仅因 fingerprint/event_type 相同就压成重复。

## 7. S01 duplicate_signal
S01 只提供初筛信号。事件处理必须重新结合上下文确认最终去重状态，不能把 S01 possible duplicate 自动当作 exact_duplicate。

## 8. 指纹稳定性要求
- fingerprint 字段必须来自可解释、相对稳定的业务键；
- 不建议直接使用自由文本 summary 全文作为指纹；
- 不把 severity 作为唯一身份键，因为 severity 会变化；
- 指纹算法变更必须升级 fingerprint_version；
- 指纹碰撞只能进入候选集，不能自动归并。

## 9. 禁止
- 删除重复事件历史记录；
- 用 summary 文本相同作为唯一去重条件；
- fingerprint 相同就自动 exact_duplicate；
- 多来源重复上报次数直接提高 severity；
- 已经有同类事件就拒绝所有后续新证据。
