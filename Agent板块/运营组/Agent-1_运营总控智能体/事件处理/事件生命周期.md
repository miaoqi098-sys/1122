# 事件生命周期

## 1. 三类概念分离
事件治理必须区分长期状态、当前处理结论和状态转换动作。

### event_status｜长期状态
```text
open
→ monitoring
→ resolved
→ closed
```

### processing_disposition｜当前处理结论
- `new_event`
- `exact_duplicate`
- `near_duplicate`
- `update_existing`
- `merged`
- `related_not_duplicate`

### transition_type｜状态转换动作
- `create`
- `update`
- `resolve`
- `close`
- `reopen`
- `none`

`updated / reopened / merged / duplicate` 不再作为与 open/resolved/closed 同层级的长期状态。

## 2. open
事件首次确认有效，仍需要处理、分析或观察。

## 3. monitoring
事件已采取动作、进入观察期或等待关键证据，但尚不能确认问题已解决。

monitoring 可以来自：
- 已执行动作等待效果验证；
- 风险暂时受控但尚未解除；
- 需要等待观察窗口；
- 正在补充证据但事件仍有效。

## 4. update
`update` 是 transition_type，不是长期 event_status。

同一事件出现新证据、scope 变化、severity 变化、deadline 变化或状态变化时：
- event_status 可保持 open/monitoring；
- processing_disposition 使用 `update_existing`；
- transition_type 使用 `update`；
- 必须保留变化原因、新证据和历史快照。

## 5. resolved
当前触发问题已经被正向证据确认消除、被证伪、由 canonical event 承接或风险/机会窗口明确结束。

进入 resolved 必须满足 `事件关闭与解决证据.md`，至少记录 resolution_basis、resolution_evidence_refs、resolution_source、resolution_confidence 和 resolved_at。

resolved 不表示所有相关 Task 都完成，也不能由 Task completed 自动推导。

## 6. closed
resolved 后完成必要观察且无新的有效触发，或满足明确的直接关闭条件时进入 closed。

关闭必须记录 close_reason 与 closed_at，并保留解决/验证证据引用。

## 7. reopen
`reopen` 是 transition_type，不是长期 event_status。

closed 事件只有出现新证据或新发生事实时才能 reopen。执行 reopen 后：
- event_status 回到 open 或 monitoring；
- 记录 reopen_reason / new_evidence_refs / reopened_at；
- 判断是否仍属于原事件延续。

如果本质是新周期独立发生，应创建 new_event 并建立 follow_up 关系，而不是无限 reopen 同一个 event_id。

## 8. duplicate / merged
`exact_duplicate / near_duplicate / merged` 属于 processing_disposition。

- exact_duplicate：保留原 event_id/source refs，并通过 duplicate_of 指向 canonical_event_id；
- merged：保留原事件和 merged_into；
- 这些处理结论不与 event_status 互斥，例如一个 merged 的来源事件仍可被标记 closed。

## 9. 防重复触发
resolved/closed 事件以及已判定 exact_duplicate/merged 的事件，在无新证据、状态变化或新周期事实时不得重复生成相同 DecisionItem。

## 10. 禁止
- 将 update/reopen/merged/duplicate 与长期状态混成同一个枚举；
- 通过关闭事件删除历史；
- Task completed 就自动推断 Event resolved；
- closed 事件无新事实周期性 reopen；
- 用同一 event_id 承载无限多个完全不同的新周期问题。
