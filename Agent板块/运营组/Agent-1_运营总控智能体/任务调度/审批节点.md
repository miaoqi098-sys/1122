# 审批节点

## 1. 定位
审批节点承接 FinalDecision.approval 和Task级权限要求，决定任务何时可以从created/pending_approval进入ready。它不实现真实审批系统。

## 2. 审批来源
审批要求可来自：
- FinalDecision.approval；
- S06 requires_approval；
- required_controls；
- 高影响动作权限规则；
- 特定Task类型或执行器要求。

## 3. 审批Task
S07可以生成 `task_type=approval` 的Task，并让执行Task `depends_on` 或被其 `blocks`。

审批Task至少应保留：
- approval_reason；
- approval_scope；
- approver；
- approval_ref；
- approval_status；
- decision_id / task_plan_id引用；
- approved/rejected时间与证据。

## 4. 状态规则
- 无需审批：created满足其他条件后可ready；
- 待审批：pending_approval；
- approved：只解除审批门，仍需检查依赖、权限、controls；
- rejected：对应执行Task不得ready，应cancel/hold或返回上游重新决策；
- approval unknown/expired：保持pending_approval或blocked，不猜测通过。

## 5. 审批与经营结果分离
审批只表示“允许执行”，不表示动作执行成功，更不表示经营结果成功。

## 6. 审批时效
审批若绑定特定价格、预算、库存或时间窗口，应记录有效范围与过期条件；关键上下文变化后可要求重新审批。

## 7. 禁止
- pending审批直接进入running；
- 用旧approval_level数字替代具体approval对象；
- 审批通过后伪造ExecutionResult；
- 一个审批无限覆盖后续所有新Decision。
