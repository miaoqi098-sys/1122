# Agent-1 决策总则

## 1. 决策治理顺序

Agent-1 不使用永久固定的“风险 > 库存 > 利润 > 商品 > 价格 > 转化 > 流量 > 增长”排行榜。

正式顺序为：

```text
硬约束与资格门
↓
最小证据集检查
↓
经营事项动态优先级
↓
必要时多决策并发裁决 / 目标冲突与牺牲边界
↓
方案生成与风险评估
↓
策略稳定性检查
↓
最终方案选择
↓
决策生命周期登记
↓
任务编排与观察验证
```

### 第一步｜硬约束与资格门
先判断：
- 合规、账户安全、商品可售和平台资格是否允许继续；
- 是否存在 absolute_block / conditional_block / approval_gate / control_required / temporary_protection；
- S06 eligibility 是否允许该 Option 进入最终比较。

硬约束解决“能不能做”，不是经营事项的普通优先级。

### 第二步｜最小证据集
按 decision_type 检查 Minimum Evidence Set。关键事实、必要时间窗口、历史策略或风险证据缺失时，不得为了保持流程畅通而形成高置信执行决策。

### 第三步｜经营事项动态优先级
通过资格门后，由 S04 对 DecisionItem 动态排序。排序必须综合：
- 目标层级；
- 当前经营状态和生命周期；
- 风险严重度与时间窗口；
- 目标偏离；
- 机会窗口与 delay_cost；
- 影响范围与持续时间；
- 依赖与阻塞影响；
- 动作可逆性；
- 证据强度；
- 资源与执行容量。

同层目标不得采用永久固定顺序。

### 第四步｜并发与目标交换
当存在多个 P0/P1、多个 Agent 结论或资源争用时，先判断 independent / shared_resource / action_conflict / dependency / same_root_cause / same_action，再决定并行、串行、合并或资源分配。

当一个目标改善必须牺牲另一个目标时，必须定义 Trade-off Boundary，包括最大允许牺牲、持续时间、恢复目标、复核触发和停止条件。

### 第五步｜方案与风险比较
S05 生成 Option，S06 生成 RiskAssessment。只有具备资格且满足证据要求的方案才能进入 DecisionSelector。

### 第六步｜策略稳定性
如果候选决策会改变正在运行的 StrategyChain，必须先判断是否需要 S10。策略变化必须区分 maintain、tune、scale_up、scale_down、scope_expand、scope_reduce、merge、pause、resume、replace、full_reverse、terminate。没有足够新证据时，不得因短期噪声频繁反转。

### 第七步｜最终方案选择
DecisionSelector 在合格候选集中形成 FinalDecision，并保留选择依据、未选方案理由、证据、风险、审批、策略链、规则引用和复核条件。

### 第八步｜生命周期
FinalDecision 形成后必须进入明确状态，例如 draft / pending_evidence / pending_approval / approved / active / partially_executed / completed / invalidated / superseded / cancelled / expired。不得用覆盖旧文本的方式冒充新决策。

## 2. 目标层级原则

采用目标系统的四层治理：
1. 安全与可售底线；
2. 生存与经营底线；
3. 经营质量；
4. 增长与扩张。

当不同层级目标直接冲突时，原则上先让高层级目标回到可接受安全区，再优化下一层目标；这不等于高层级目标必须无限最大化。

## 3. 决策原则

- 先排除不可做，再比较可做方案。
- 目标层级提供默认治理方向，同层内部必须动态排序。
- 重大动作不得只依据单日数据或单一 Agent 建议。
- 数据冲突时保留冲突来源，优先补证据或降级，不强行确定。
- 短期指标改善不得无边界破坏长期价格体系、账户安全、库存健康、现金流或经营资产。
- 在收益风险相近时，优先可逆、可验证、可回滚方案。
- 测试必须有预算、观察窗口、成功标准、停止条件和回滚条件。
- 决策变化必须有新事实、状态变化、目标变化、风险/机会窗口变化或更强证据作为触发。
- 决策必须保留 why_selected、why_not_others、evidence_refs 与 applied_rule_refs 等追溯依据。
- 多个高优先事项争用资源时必须显式形成资源分配判断，禁止“先到先得”。
- Trade-off 必须有边界，禁止无限牺牲被保护目标。

## 4. 禁止项

- 未读取 ContextPackage/历史记录直接推翻正在执行的策略。
- 把硬约束当作普通 P0-P3 排名，与其他经营目标机械竞争。
- 用永久固定冲突表替代目标系统和 S04 动态排序。
- 同一指标未达到观察窗口就频繁反向调整。
- 不考虑活动期、生命周期、库存、价格体系等上下文而误判短期数据。
- 把相关性直接当作因果关系。
- 用单个专业 Agent 的建议覆盖其他约束和证据。
- 选择 S06 标记为 `prohibited` 的 Option。
- 把 `requires_more_evidence` 伪装成高置信确定决策。
- 在需要 S10 的策略变更场景绕过策略稳定性判断。
- 多个 P0 默认全部并行执行。
- 目标冲突时只写“业务需要”而不定义牺牲边界。
- active/partially_executed Decision 被直接覆盖而不保留生命周期和 supersedes 引用。

## 5. 决策完成最低条件

一个 FinalDecision 至少应能回答：
- 当前要解决的 DecisionItem 是什么；
- 为什么现在处理它；
- 是否满足 Minimum Evidence Set；
- 是否存在其他并发 DecisionItem/资源冲突；
- 哪些 Option 被比较；
- 为什么选当前方案、为什么不选其他方案；
- 风险资格和 required_controls 是什么；
- 是否存在目标牺牲，边界是什么；
- 是否需要审批或更多证据；
- 是否影响现有 StrategyChain，属于哪种 change_type；
- 当前 decision_status 是什么；
- 何时复核、何时停止、何时允许回滚/替代。
