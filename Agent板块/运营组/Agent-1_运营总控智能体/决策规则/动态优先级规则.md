# 动态优先级规则

## 1. 定位
本规则约束 Agent-1 如何把目标系统与 S04 结合为动态业务优先级。它不重新实现 S04 排序算法。

## 2. 两层机制
### 资格门
硬约束先决定某事项或方案是否允许继续，不属于 P0-P3 的普通竞争。

### 动态业务优先级
通过资格门的 DecisionItem 由 S04 形成 P0-P3 与 rank。

## 3. 目标层级
默认使用：
1. `safety_sellability` 安全与可售底线；
2. `survival_operations` 生存与经营底线；
3. `business_quality` 经营质量；
4. `growth_expansion` 增长与扩张。

跨层直接冲突时，优先确保高层级回到安全区；同层内部禁止永久固定顺序。

## 4. 排序必须综合的因素
- `goal_layer`；
- 当前经营状态/生命周期；
- `severity / urgency / deadline`；
- 目标偏离程度；
- `opportunity_window`；
- `dependency_impact`；
- `reversibility`；
- `evidence_strength`；
- `resource_cost / execution_capacity`；
- `conflict_refs / constraint_refs`；
- `previous_priority` 与 `change_trigger`；
- `impact_scope`：影响对象层级，例如 keyword / campaign / ASIN / store / account；
- `impact_breadth`：影响对象数量或业务覆盖面；
- `impact_duration`：影响预计持续时长；
- `delay_cost`：推迟处理造成的增量损失；
- `window_decay`：机会窗口随时间衰减速度；
- `time_to_irreversibility`：距离不可逆结果发生的剩余时间。

## 5. Impact 范围不得被 severity 替代
相同 severity 的事项可能影响范围完全不同。S04 至少应能区分：
- 单关键词/单搜索词；
- 单广告组/单 Campaign；
- 单 ASIN/父体；
- 多 ASIN/类目；
- 店铺；
- 账户级。

范围越广不代表必然更高优先级，但必须进入解释。

## 6. Opportunity / Delay Cost
有些事项不是当前风险最高，而是“再晚就失去价值”。典型包括：
- 大促前关键准备窗口；
- 新品学习/冷启动窗口；
- 竞品断货或价格异常机会；
- 自然排名冲刺窗口；
- Coupon/Deal 临近结束；
- 外部流量突然放大。

这类事项必须显式计算/解释 `delay_cost` 与 `window_decay`，不得仅依赖当前 severity。

## 7. Priority Gate
S04 Gate：
- `normal`：正常排序；
- `protected`：允许继续，但增长/实验受保护约束限制；
- `blocked`：相关事项不得正常竞争，先解除硬阻断；
- `escalated`：需要人工、专业复核或更高权限。

Gate 不是第五级优先级。

## 8. 优先级变化必须可解释
每次从 P2→P0、P1→P3 等变化至少应能追溯：
- previous_priority；
- current_priority；
- priority_change；
- change_trigger；
- 新证据/新状态/目标变化/风险或机会窗口变化。

没有新触发不得仅因模型重新评估就改变顺序。

## 9. 典型状态调整
- 新品冷启动：在底线安全内，提高验证、关键词资产、转化学习权重。
- 成长期：提高有效放量、自然流量与利润增长协同。
- 稳定期：提高利润效率、自然销售占比、竞争防守与周转质量。
- 大促前：提高库存、价格体系、活动准备与执行稳定性。
- 库存紧张：降低放量和深促销，提高库存保护与单位产出。
- 现金紧张：提高现金回收与利润贡献，压低高成本长期实验。
- 合规/不可售：增长事项 Gate 降级或阻断，先恢复安全与可售。

## 10. 多事项并发
当存在多个 P0/P1 或资源争用时，不在本文件内机械选一个，必须调用 `多决策并发裁决规则.md`。

## 11. 禁止机械排序
禁止把任何历史固定链写成永久优先级，例如“库存永远高于利润”“转化永远高于流量”。真正的规则是目标层级 + 当前状态 + 风险窗口 + 机会窗口 + 证据 + 依赖 + 影响范围 + 延迟成本 + 资源共同决定。
