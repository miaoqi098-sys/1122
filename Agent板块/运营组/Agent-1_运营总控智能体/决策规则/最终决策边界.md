# 最终决策边界

## 1. 定位
本规则定义 DecisionSelector 可以选择什么、必须保留什么，以及 Agent-1 最终经营决策出口与 S04/S05/S06/S10/S07 的边界。

## 2. DecisionSelector 输入前提
至少应具备：
- `scope`；
- `ranked_decision_item`；
- `options[]`；
- `option_risks[]`；
- `context_package`；
- `minimum_evidence_status`；
- 若涉及运行中策略，提供 `strategy_chain` / `s10_result` 或先路由 S10；
- 若存在多个 P0/P1 或共享资源冲突，提供并发裁决结果；
- 若存在目标牺牲，提供 Trade-off Boundary。

## 3. 候选集规则
进入最终比较的 Option 必须：
- 与当前 decision_item 对应；
- 具备足够上下文和证据引用；
- 满足 `最小证据集规则.md`；
- 存在对应 RiskAssessment；
- eligibility 不是 prohibited；
- 若为 eligible_with_controls，控制条件可明确传递；
- 若 requires_approval，最终输出必须停在审批边界；
- 若 requires_more_evidence，不得伪装成正常执行型选择；
- 若与现有 StrategyChain 存在变更关系，必须完成 S10；
- 若存在多个竞争 DecisionItem，必须完成多决策并发裁决。

## 4. FinalDecision 必须回答
至少包含或可追溯：
- `decision_id / decision_item_id`；
- `decision_status`；
- `business_priority`；
- `selected_option`；
- `risk_assessment`；
- `why_selected`；
- `why_not_others`；
- `goal/state/conflict/evidence/knowledge/history refs`；
- `applied_rule_refs[]`；
- `approval`；
- `strategy_chain_id / supersedes_decision_id`（适用时）；
- `decision_confidence`；
- `valid_until / review_trigger`；
- 成功标准与 stop/guardrail 条件；
- 必要的 `rollback_reference`；
- 若存在目标交换，保留 trade-off boundary；
- 若属于并发裁决，保留相关 decision_item_ids / resource allocation 引用。

## 5. FinalDecision 生命周期
FinalDecision 不得只被视为一次性文本输出，必须遵守 `决策生命周期规则.md`。

主要状态包括：
`draft / pending_evidence / pending_approval / approved / active / partially_executed / completed / invalidated / superseded / cancelled / expired`。

任何重大方向、资格或约束变化不得直接覆盖原 Decision；应通过状态迁移或新 Decision + supersedes 引用处理。

## 6. 职责边界
- S04：决定哪个经营待决事项更重要，不选最终 Option。
- S05：生成 Option，不做最终选择。
- S06：判断风险与资格，不做最终选择。
- S10：判断是否允许改变正在运行策略，不生成执行任务。
- DecisionSelector：在允许候选集中形成 FinalDecision。
- S07：把 FinalDecision 编排成 Task/TaskGraph，不重新决定业务方向。

## 7. 选择原则
- 先过滤资格，再比较整体经营结果；
- 不以单一收益指标覆盖主导风险；
- 证据相近时优先更可逆、更可验证方案；
- required_controls、approval、review_trigger 不得在选择时丢失；
- 不能选择与当前策略链冲突但未经过 S10 的方案；
- 低置信决策应缩小动作范围、增加观察或请求更多证据，而不是包装为确定结论；
- 多目标冲突必须保留明确牺牲边界；
- 多 P0/多 Agent 冲突不得按到达顺序或 Agent 编号直接选择。

## 8. next_action
DecisionSelector 输出应根据实际状态路由：
- `continue_to_S07`；
- `send_to_S10`；
- `request_more_evidence`；
- `regenerate_options`；
- `request_approval_context`；
- `hold_for_review`；
- `resolve_concurrent_decisions`；
- `reassess_expired_decision`。

## 9. 禁止
- Agent-2至13直接形成最终经营 Decision；
- DecisionSelector重新创造与 ContextPackage 冲突的事实；
- 选择 prohibited Option；
- requires_approval 未获审批即进入执行；
- 用“无其他方案”作为缺失 why_not_others 的理由而不检查 S05 是否生成不足；
- FinalDecision 不保留证据和历史引用；
- 原地覆盖 active/partially_executed Decision；
- 已 superseded/expired 的 Decision 继续产生新执行任务。
