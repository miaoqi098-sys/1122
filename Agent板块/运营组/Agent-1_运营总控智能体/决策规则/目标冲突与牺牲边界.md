# 目标冲突与牺牲边界

## 1. 定位
本规则定义当多个经营目标互相冲突时，Agent-1 允许牺牲什么、牺牲到什么程度，以及何时必须停止继续交换。目标层级提供治理方向，但不能替代具体的 trade-off boundary。

## 2. 基本原则
- 高层级目标先回到可接受安全区，不等于无限最大化。
- 任何低层级优化不得突破上层明确底线。
- 任何牺牲都必须有上限、持续时间、复核点和退出条件。
- 不能只写“为了增长可以牺牲利润”，必须说明允许范围和恢复条件。

## 3. Trade-off Boundary 最低字段
每个目标冲突至少定义：
- `primary_goal`：本轮主要目标；
- `protected_goals[]`：不可被突破的保护目标；
- `sacrifice_goal`：允许短期牺牲的目标；
- `max_sacrifice`：最大允许损失/偏离；
- `sacrifice_window`：最长允许持续时间；
- `recovery_target`：何时要求恢复；
- `review_trigger`：提前复核触发器；
- `stop_condition`：立即停止条件；
- `evidence_refs`：边界依据。

## 4. 典型冲突模板
### 利润 vs 增长
可接受短期利润下降，但必须限定预算、时间和增长验证目标；不得长期用亏损掩盖无效增长。

### 库存 vs 流量
库存风险上升时可降低放量，但应优先削减低效率流量，不机械停止全部广告；保留必要关键词和自然排名资产。

### 价格体系 vs 清库存
可使用促销清理库存，但必须保护长期参考价、利润底线、品牌价格带和活动后恢复条件。

### 新品学习 vs 短期利润
新品期允许更高学习成本，但必须定义学习窗口、数据目标和毕业条件；超过窗口仍无有效信号，应退出“学习豁免”。

### 现金流 vs 补货
补货不能只追求不断货；必须同时满足现金安全、周转和最坏销售情景下的承受能力。

## 5. 不同层级冲突
- `safety_sellability` 被突破：低层目标自动失去继续扩大资格。
- `survival_operations` 接近底线：增长只能在受控范围内继续。
- `business_quality` 与 `growth_expansion` 冲突：允许按经营阶段动态交换，但必须有边界。

## 6. 边界不是永久常量
Trade-off Boundary 应结合：
- 生命周期；
- 当前经营状态；
- 活动窗口；
- 库存和现金；
- 历史基线；
- 证据强度；
- 可逆性。

同一产品在新品期、稳定期、大促前的允许牺牲边界可以不同。

## 7. 禁止
- 使用“战略需要”作为无限牺牲理由；
- 没有 max_sacrifice 和窗口仍持续加码；
- 牺牲目标已经越界却因为主目标改善而继续；
- 用单一 KPI 替代多目标约束；
- 把临时例外永久化。
