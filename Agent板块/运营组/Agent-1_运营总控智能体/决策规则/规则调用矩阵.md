# 决策规则调用矩阵

## 1. 定位
本文件定义 Agent-1 在不同决策场景下应加载哪些决策规则，避免未来运行层只靠模型临场判断“该看哪些规则”。

## 2. 基础调用顺序
所有经营决策默认按以下顺序检查：
1. `决策总则.md`
2. `资格与硬约束.md`
3. `最小证据集规则.md`
4. `动态优先级规则.md`
5. 按场景加载专项规则
6. `最终决策边界.md`
7. `决策生命周期规则.md`

## 3. 场景矩阵
| 场景 | 必调规则 | 条件规则 | 主要输出 |
|---|---|---|---|
| 单一 DecisionItem 正常决策 | 总则、资格、证据、优先级、最终边界、生命周期 | 目标冲突 | FinalDecision |
| 多 DecisionItem / 多 P0 | 总则、资格、证据、优先级、并发裁决、最终边界、生命周期 | 目标冲突、策略稳定 | 排序/并行/合并/串行方案 |
| 多目标互相牺牲 | 总则、资格、证据、目标冲突、最终边界、生命周期 | 优先级、并发裁决 | Trade-off Boundary |
| 改变运行中 StrategyChain | 总则、资格、证据、策略稳定、最终边界、生命周期 | 目标冲突、并发裁决 | allow/hold/merge/escalate/override |
| 证据不足或冲突 | 总则、资格、证据、信息不足、最终边界 | 策略稳定 | 补证/降级/审批/hold |
| requires_approval | 总则、资格、信息不足、最终边界、生命周期 | 目标冲突 | pending_approval |
| prohibited / 主导风险 | 总则、资格、最终边界 | 信息不足 | 排除方案/阻断 |
| eligible_with_controls | 总则、资格、最终边界、生命周期 | 策略稳定 | controls 传递至 S07 |
| 决策已部分执行后出现新事实 | 总则、证据、策略稳定、生命周期、最终边界 | 并发裁决、目标冲突 | invalidated/superseded/continue |
| 决策过期未执行 | 总则、证据、生命周期、最终边界 | 信息不足 | expired 后重新评估 |

## 4. 条件触发器
### 加载 `目标冲突与牺牲边界.md`
当存在：
- 一个目标改善需要另一个目标恶化；
- 允许短期亏损/降速/降价/增库存等交换；
- 需要定义“牺牲到哪里停止”。

### 加载 `多决策并发裁决规则.md`
当存在：
- 同时多个 P0/P1；
- 多 Agent 对相同/相关 scope 提出事项；
- 预算、库存、人力、审批等资源争用；
- 一个动作可能解决多个 DecisionItem。

### 加载 `策略稳定与反转规则.md`
当新决策可能修改、暂停、扩大、缩小、替换、反转正在运行的 StrategyChain。

### 加载 `信息不足审批与降级.md`
当关键证据缺失、来源冲突、审批未完成或无法安全形成正常执行型 FinalDecision。

## 5. 调用记录
未来运行层每次形成 FinalDecision 时，应保留：
- `applied_rule_refs[]`；
- `skipped_rule_refs[]`（仅对条件规则，可说明为何未触发）；
- `rule_version_refs[]`；
- 关键门禁结果。

## 6. 禁止
- 只加载决策模板，不加载治理规则；
- 发生策略变更却跳过策略稳定规则；
- 多 P0 时仍按单事项流程直接挑一个；
- 有目标牺牲但不定义边界；
- 规则调用完全依赖模型自由发挥且不留引用。
