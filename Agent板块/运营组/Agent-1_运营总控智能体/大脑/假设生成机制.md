# Agent-1 假设生成机制

## 目的
避免 Agent-1 看到一个经营现象就立即锁定唯一原因。假设的作用不是增加分析数量，而是覆盖主要解释空间，并找到能够有效区分不同解释的证据。

## 什么时候需要生成多个假设
以下情况原则上需要多个假设：
- 原因尚不明确的重要异常；
- 多个指标同时变化；
- 不同 Agent 给出不同解释；
- 重大经营动作前需要确认因果链；
- 历史上存在多种可能原因的高频场景。

对于原因已经由直接、高质量证据确认的简单问题，不要求为了数量机械生成多个假设。

## 生成规则
1. 对重大且原因未明确的问题，应生成足以覆盖主要解释空间的多个合理假设，通常不少于 2 个。
2. 假设必须来自当前事实、经营知识、历史经验或专业 Agent 判断，不得无依据凑数。
3. 每个假设必须区分支持证据、反证和未知信息。
4. 不因历史案例相似就跳过当前验证。
5. 允许多个假设同时成立，不强行把复杂问题解释成单一原因。
6. 应识别假设之间是互斥、独立、因果链还是组合关系。
7. 优先验证最可能改变最终行动选择的假设。

## 假设关系
### 互斥假设
两个解释不能同时成立，应寻找区分度最高的证据。

### 可并存假设
多个原因可能同时造成结果，例如价格竞争力下降与 Listing 表达不足共同降低转化。

### 因果链假设
一个原因可能通过中间变量造成最终现象，例如竞品降价 → 点击后价格比较劣势扩大 → CVR下降 → ACOS上升。

### 条件性假设
只有在特定经营状态或时间窗口下成立，例如活动期高 ACOS 可能是战略性流量获取，而正常期同样数据可能意味着效率恶化。

## 假设模板
- 现象：发生了什么。
- 假设：可能原因是什么。
- 假设类型：互斥 / 可并存 / 因果链 / 条件性。
- 支持证据：当前哪些事实支持。
- 反证：哪些事实与该假设冲突。
- 未知信息：还缺什么。
- 验证方法：需要哪个 Agent、工具、指标或时间窗口。
- 当前置信度：低 / 中 / 高。
- 若成立：可能采取什么行动方向。
- 若不成立：排除后会影响哪些方案。

## 验证优先级
验证顺序优先考虑：
1. 能直接排除高风险错误决策的证据；
2. 能同时区分多个主要假设的证据；
3. 获取成本低、速度快的高质量证据；
4. 会显著改变方案排序的证据；
5. 仅用于增加细节但不会改变行动的信息最后处理。

## 示例
现象：关键词 61 点击 0 订单。

可能假设包括：
- 搜索意图与产品不匹配；
- Listing 对该使用场景表达不足；
- 价格或优惠竞争力不足；
- 广告流量位置或流量质量较差；
- 样本仍不足或存在活动期扰动；
- 广告直接转化弱，但可能产生自然排名或其他长期资产。

这些假设并不一定互斥。例如“搜索意图部分不匹配”和“页面表达不足”可能同时成立。

Agent-1 应优先寻找能够改变行动选择的证据，而不是立即把“0订单”等同于“这个词没有价值”。
