# 回路、阻断与重入

## 1. 正式回路
工作流允许回到上游补充信息或重新生成对象，但每次回路必须说明原因和目标，不允许无条件循环。

### 信息不足
- S01 needs_information → 补原始Event字段后重跑S01；
- S02 needs_information → 补决策相关上下文后重跑S02；
- S06 requires_more_evidence → 补风险关键证据后重评；
- DecisionSelector request_more_evidence → 回S02/专业Agent请求，不伪造FinalDecision。

### 方案不足
`regenerate_options` → 回S05，并保留为什么现有Option集合不足。

### 策略稳定
`send_to_S10` → S10结果返回DecisionSelector/S07；hold则停在观察/复核，不反复生成相同反向Option。

### 审批
`request_approval_context` / pending_approval → 等授权上下文；审批结果回来后从原decision/task断点继续，不重建整条链。

### 执行/验证失败
- Execution failure → 记录ExecutionResult，判断重试/阻塞/回到S07/新Decision；
- Validation failure → 根据结果进入继续观察、新诊断、rollback或新Decision。

## 2. blocked
blocked表示当前链路缺少可继续条件。必须保留：
- blocked_at；
- blocked_reason；
- blocked_stage；
- required_information/condition；
- resume_from；
- related business IDs。

解除条件后从`resume_from`恢复，不必从Event重新开始，除非上游事实已失效。

## 3. 重入与幂等
同一个business object重入时应优先：
- 复用event_id/decision_item_id等已有对象；
- 检查是否已有新版本/已关闭/已superseded；
- 只重跑受新证据影响的阶段；
- 避免重复创建相同Task/Decision/LearningRecord。

## 4. 重新运行条件
只有出现：
- 新证据；
- 上游对象版本变化；
- 状态/目标/约束变化；
- approval/blocked condition解除；
- review_trigger/stop_condition触发；
才允许从相关断点重入。

## 5. 循环保护
框架层禁止：
- S05↔DecisionSelector无限regenerate；
- S06↔补证据在无新数据情况下无限重试；
- S10 hold后立即再次生成同一反向决策；
- Validation failure无新诊断直接反复执行同一Task。

达到重复条件时应hold/blocked/escalate，而不是继续空转。

## 6. 运行trace
run_id/trace_id可以标记一次运行尝试，但业务恢复依据仍是event/decision/task等对象状态和版本。

## 7. 禁止
- 因系统重启就重建整条业务链；
- blocked解除后丢失原上下文与引用；
- 同一审批回执重复消费产生多个Task；
- 无新证据无限回跳。
