# 工作流桥接组件

## 1. 为什么需要桥接
Skill输出之间存在业务对象转换，不能由下游Skill临时猜测拼接。桥接组件只做标准对象转换/选择/归一，不重新承担专业业务判断。

## 2. DecisionItemBuilder
输入：
- normalized Event / event refs；
- ContextPackage；
- S03 conflict结果；
- 目标/状态/约束派生视图。

输出：canonical DecisionItem。

职责：把“发生了什么、需要决定什么、影响什么目标、有哪些约束”整理为S04可排序对象。

禁止：直接选择Option或形成FinalDecision。

## 3. DecisionSelector
输入：
- ranked DecisionItem；
- Option[]；
- RiskAssessment[]；
- ContextPackage；
- 必要时S10结果/StrategyChain。

输出：
- FinalDecision，或
- send_to_S10 / request_more_evidence / regenerate_options / request_approval_context / hold_for_review等路由。

禁止：选择prohibited Option，或绕过S10/approval。

## 4. ExecutionResultNormalizer
输入：不同API、人工流程、工具执行器的真实回执。

输出：canonical ExecutionResult，并保持task_id/task_plan_id/decision_id引用。

职责：标准化执行状态、actual changes、错误和来源；不判断经营目标是否达成。

## 5. LearningWriteExecutor
输入：S09 memory_writes计划。

输出：未来真实持久化回执（written/failed等）。

职责：写入共享记忆层并返回真实结果；S09本身不得伪造written。

## 6. StrategyChain Builder / Persistence
用于创建/维护strategy_chain_id、版本、替代和反转历史。框架对象可定义，但真实持久化属于R11。

## 7. 共同要求
桥接组件必须：
- 保留canonical业务主键；
- 不静默丢失evidence/approval/control/strategy refs；
- 输入不足时返回明确错误/缺口；
- 不把运行trace当业务主键；
- 不在转换过程中重新做已由Skill完成的核心判断。

## 8. 运行边界
真实桥接执行程序属于系统运行/执行/记忆层，本文件只定义业务接口和职责边界。
