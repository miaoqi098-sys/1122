# 工作流示例与静态验收

## 示例A｜正常决策执行学习链
广告Event通过S01 → S02装载上下文 → S03无阻断冲突 → DecisionItemBuilder → S04排序 → S05方案 → S06风险eligible_with_controls → DecisionSelector形成FinalDecision → S07生成approval/control/execution/monitoring/validation Task → Executor回执经Normalizer → S08验证 → S09形成LearningRecord。

验收：required_controls不丢失；ExecutionResult成功不直接等于Validation成功；S09不伪造written。

## 示例B｜证据不足回路
S06=`requires_more_evidence`。

正确处理：回到S02/专业Agent补充指定证据，保留原decision_item_id；没有新证据时不得重复S06空转。

## 示例C｜策略反转
新Option与运行中StrategyChain方向相反。

正确处理：DecisionSelector或工作流路由S10；S10 hold则不创建反向Task；override则形成新Decision并保留旧Decision/Task历史。

## 示例D｜审批断点恢复
FinalDecision需要审批。审批回执晚到。

正确处理：保持decision/task业务ID和resume_from；批准后从审批断点继续，不重新从Event创建第二套Decision。

## 示例E｜执行成功但验证失败
API动作成功，S08在观察后确认经营结果未达标。

正确处理：保留ExecutionResult成功事实；ValidationResult记录未达标；进入新诊断/回滚/新Decision，不把执行链标failed。

## 静态验收
