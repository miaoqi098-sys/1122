# S01 事件校验判断规则 V1.1

## 一、校验顺序
```text
1. 输入容器
2. 必填字段
3. scope/object
4. 字段格式
5. 来源
6. 时间有效性
7. 事实质量
8. severity一致性
9. 重复初筛
10. normalized_event输出
```

## 二、基础必填字段
事件必须包含：
- event_id
- source_agent
- scope_type
- event_type
- severity
- occurred_at
- summary
- facts

`recommendation`不是必填字段。

## 三、作用域规则
### product / parent_product / sku
- product_id必须存在且可解析；
- 若提供known_product_ids，应能匹配或明确进入needs_information；
- 不得自动绑定其他产品。

### account / store / global
- product_id允许为null；
- 必须能通过scope_id、scope_objects或事件内容识别真实业务作用域；
- 禁止为了满足Schema伪造ASIN。

### scope矛盾
若scope_type=account但product_id/summary/facts又声明仅针对单产品，应输出作用域矛盾警告并要求澄清，不静默选择任一解释。

## 四、来源规则
- allowed_sources存在时必须检查来源合法性；
- 来源合法但专业边界不匹配：warning，不直接丢弃事实；
- 来源伪装或无法解释：rejected或hold_for_review。

## 五、时间规则
- occurred_at必须可解析；
- 运行时统一带时区ISO 8601；
- 不硬编码统一过期天数；
- 新鲜度根据事件类型与freshness policy判断；
- 旧事件用于历史复盘时可以passed_with_warnings。

## 六、事实质量
facts应尽量是可验证事实，而不是纯结论。

较好：
- “过去14天点击61，订单0。”
- “当前可售库存120件。”

较差：
- “这个词没用了。”
- “库存很危险。”

主要由判断构成时输出`FACTS_NOT_VERIFIABLE`。

## 七、severity一致性
S01只检查明显异常，不在这里重新做完整风险评估。

例如：
- Listing已冻结但severity=low；
- 普通CTR小幅波动却severity=critical。

保留来源severity并输出warning，不静默覆盖。

## 八、重复事件
S01只输出duplicate_signal：
- 相同event_id；
- 相同scope；
- 相同event_type；
- 时间接近；
- facts/summary高度相似。

正式合并、关闭、更新属于事件处理模块。

## 九、状态判定
### passed
无阻断错误，关键事实足够。

### passed_with_warnings
无阻断错误，但存在非关键质量问题。

### needs_information
问题可修复，但缺失信息会显著影响后续处理。

### rejected
输入不可用、来源无法解释、作用域不可解释、关键字段严重错误。

## 十、标准错误/警告代码
阻断/补充：
- EVENT_MISSING
- EVENT_ID_MISSING
- SOURCE_MISSING
- SCOPE_TYPE_MISSING
- SCOPE_UNRESOLVED
- PRODUCT_ID_REQUIRED
- EVENT_TYPE_MISSING
- TIME_INVALID
- EVENT_STRUCTURE_INVALID
- SOURCE_INVALID

警告：
- SUMMARY_WEAK
- FACTS_WEAK
- FACTS_NOT_VERIFIABLE
- SOURCE_SCOPE_MISMATCH
- EVENT_SCOPE_MISMATCH
- SEVERITY_MISMATCH
- EVENT_STALE
- POSSIBLE_DUPLICATE

## 十一、标准化输出
`normalized_event`必须保留：
- event_id
- source_agent
- scope_type
- scope_id
- product_id（可为null）
- scope_objects
- event_type
- severity
- occurred_at
- summary
- facts
- recommendation（如有）

## 核心原则
S01只负责“这个事件是否足够干净、可靠、可解释地进入下一步”，不提前把事件校验变成经营决策系统。
