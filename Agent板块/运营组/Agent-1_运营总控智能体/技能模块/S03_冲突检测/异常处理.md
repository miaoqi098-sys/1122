# S03 异常处理 V1.1

- 无多Agent结论：仍检测目标、任务、事实、策略和约束冲突，不报错。
- `normalized_elements` 未提供：由S03标准化器从context_package提取；提取失败的内容保留原始引用并标记未标准化。
- 来源时间不明：freshness视为unknown，标记证据不足，不默认最新。
- 同一指标单位/口径不同：先标准化单位与口径；无法转换时不得直接比较。
- 冲突无法判定：输出 `needs_evidence`，列出最小决定性证据和建议来源。
- 关键事实严重冲突：不得形成高置信度方案，decision_impact可设为blocks_decision，必要时整体status=`blocked`。
- 专业Agent越权建议：保留其专业事实和分析；将越权动作记录为constraint/边界问题，不直接丢弃整个结论。
- 任务记录缺失：无法判断新旧策略反转时明确缺口，交S02补当前任务/历史上下文。
- 检测到大量重复冲突：按共同根因聚类，生成conflict_group，避免同一根因产生大量重复项。
- 同一冲突既涉及多个维度：选择最底层/最决定性的主type，其他维度放入标签或disputed_points，不复制成多个假冲突。
- Agent参与方无法识别：允许involved_agents为空，但保留source/parties。
- 目标张力已被预算/约束容纳：不得误判为阻断，可设decision_impact=none/confidence_only。
- 策略反转是否允许无法判断：S03输出strategy冲突并发送S10，不在本技能内部裁决。
- 未知冲突类型：使用最接近底层类型并保留原始描述；如果无法可靠归类，标记需要复核，不静默丢弃。

## 核心原则
异常处理的目标不是强行得到“有冲突/没冲突”，而是在证据不足时保留不确定性，并告诉后续系统缺什么。
