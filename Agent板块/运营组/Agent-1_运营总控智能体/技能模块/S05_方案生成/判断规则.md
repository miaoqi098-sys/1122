# S05 判断规则 V1.1

## 一、标准生成链
```text
1. 读取S04 decision_item
2. 锁定problem/objective/goal_layer/priority_basis
3. 读取约束、S03冲突、状态、知识和历史
4. 生成候选策略路径
5. 硬约束过滤
6. 动作原子化
7. 补假设、收益、成本、成功标准、停止条件
8. 方案差异检测与去重
9. 形成可交给S06的options
```

## 二、不重新定义S04优先级
S05可以发现“问题定义本身需要补信息”，但不得因为更喜欢另一个问题而自行改变S04 business_priority。

如果S05发现关键前提错误，应返回needs_information/redefine_problem，而不是偷偷换题。

## 三、方案类型按需要选择
conservative / balanced / aggressive / experiment / observe / information_first不是必须凑齐的六宫格。

只有真正合理时才生成。通常2-4个实质不同方案即可；只有一个可行路径时允许只输出一个并说明其他路径为何被排除。

## 四、先定义约束再生成动作
硬约束、审批限制、不可售/合规限制、库存/利润/现金保护条件必须在生成动作前进入边界。

违反硬约束的候选方案应进入excluded_options，不得包装成“高风险进取方案”。

## 五、动作必须可执行
禁止仅输出“优化广告”“提升转化”“控制成本”等空泛动作。

动作至少要尽量明确action_type、target，并在适用时说明change、scope、intensity、duration_or_window和preconditions。

## 六、方案差异必须是策略差异
至少比较：方向、强度、范围、资源投入、时间尺度、信息要求、可逆性。

仅参数小幅不同、策略逻辑相同的方案应合并。例如-10%、-15%、-20%竞价通常属于同一方案族。

## 七、高不确定性优先可逆学习
关键事实不充分时优先考虑：
- experiment：小预算/小范围测试关键假设；
- information_first：先拿决定性证据；
- observe：已有有效观察窗口时继续观察。

不得为了“行动感”强制改变策略。

## 八、observe也必须完整
继续观察必须说明：观察对象、观察窗口、成功/失败信号、结束条件和下一复核点。单纯“再看看”不是方案。

## 九、information_first必须有决策价值
必须说明data_needed以及：该信息能区分什么假设、会改变哪个方案或风险判断。不能把“收集更多数据”当无限拖延。

## 十、来源可追溯
每个方案通过derived_from尽量引用：证据、知识、历史经验、专业Agent结论、S03冲突。

历史经验复用前必须检查对象、状态、时间、适用边界；过去失败的策略只有条件发生实质变化时才可重新进入候选。

## 十一、S05只描述已知风险信号
S05使用known_tradeoffs / known_risk_signals描述显而易见的代价和风险线索。

不得在S05正式输出风险等级、发生概率、审批等级、残余风险或最终风险结论；交S06处理。

## 十二、成功标准和停止条件
行动/实验方案必须带success_criteria和stop_conditions；observe/information_first也必须定义何时结束当前阶段。

成功标准尽量连接经营指标库和当前基线，不随意硬编码全类目统一阈值。

## 十三、不宣称最终最佳
S05生成可选路径，不输出“最终最佳方案”。选择需要S06风险评估和大脑综合比较。

## 核心原则
好的方案集不是数量多，而是覆盖真正不同的经营路径，并且每条路都知道为什么存在、怎么执行、怎么验证、什么时候停。
