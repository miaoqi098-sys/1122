# S06 判断规则 V1.1

## 一、标准风险链
```text
1. 逐个读取S05 option
2. 拆解actions / assumptions / known_risk_signals
3. 先检查禁止项、合规、账户、可售和硬约束
4. 逐风险维度识别risk
5. 判断likelihood / impact / time / detectability / reversibility / exposure
6. 评估inherent_risk
7. 读取或设计mitigation/controls
8. 评估controlled_risk
9. 评估residual_risk
10. 识别dominant_risk / worst_case
11. 确定eligibility / approval_level
```

## 二、逐方案、逐动作评估
不得给问题本身笼统贴风险标签。风险必须尽量关联到具体option/action/assumption/状态或约束。

## 三、先检查上层风险
合规、账户、不可售、明确禁止行为和硬约束优先检查。触碰禁止项的方案不得包装成“R4高风险可尝试”，应eligibility=prohibited或升级授权层。

## 四、概率不是风险本身
风险判断至少综合：likelihood、impact、time_horizon、detectability、reversibility、exposure和证据强度。

低概率但重大不可逆损失仍可为高风险。

## 五、三层风险不可混淆
- inherent：不考虑新增保护措施；
- controlled：假设控制措施正确部署后的风险；
- residual：控制后仍然存在的风险。

控制措施不能删除原始风险记录。

## 六、控制措施必须真实可用
mitigation只有在满足以下条件时才能降低controlled_risk：
- 有明确动作；
- 有责任/执行可能性；
- 有触发或前置条件；
- 可以在风险发生前或可接受时间内生效。

依赖尚未完成、权限未知或无法执行的mitigation不得用于降低风险。

## 七、总体风险不得平均
不得把R4、R1、R1平均成R2。

aggregation_rule必须说明总体等级如何形成。合规、账户、不可售、禁止行为、重大不可逆风险等允许dominant-risk override。

`dominant_risk`记录主导总体风险的risk_id；`risk_drivers`记录主要风险驱动项。

## 八、证据不足本身是风险
数据过期、关键假设未验证、概率无法估计、关键阈值缺失时增加data_uncertainty风险。

无法估计概率时使用unknown，不伪造百分比。

## 九、最坏情况
重要风险应描述合理的worst_case。方案整体worst_case优先反映可能造成最大经营损失、不可逆后果或上层目标破坏的情形。

不得为了显得谨慎而编造极端灾难。

## 十、执行资格
- eligible：风险处于允许范围，可正常进入方案比较；
- eligible_with_controls：必须落实required_controls；
- requires_approval：风险可讨论但需权限矩阵指定审批；
- requires_more_evidence：关键风险无法可靠判断；
- prohibited：当前明确禁止执行。

## 十一、审批来自权限系统
R3通常需要人工审批，R4通常禁止或必须升级，但具体approval_level必须读取身份与权限/权限矩阵和审批规则，不在S06硬编码人员名称。

缺权限矩阵时可评估风险，但不得宣称“允许自动执行”。

## 十二、风险高不等于方案差
S06不按“风险最低”选最终方案。高收益、高风险方案在权限和保护条件满足时仍可进入Agent-1比较。

## 十三、停止条件也是风险控制
S05的stop_conditions应作为风险控制证据之一检查。没有可监测停止信号、动作不可逆或detectability低时，应提高风险关注度。

## 核心原则
风险评估的目标不是把所有方案都压到最低风险，而是让Agent-1清楚知道：每条路承担什么风险、保护措施能降低多少、最坏会怎样、剩余风险是否值得承担。
