# S07 验收测试 V1.1

- T01 “优化广告”必须拆成具体execution任务与validation任务，禁止保留空泛动作。
- T02 需先修Listing再放量：建立depends_on/blocks关系，后续任务未满足前置时不得ready。
- T03 两个独立分析或数据任务：允许parallel_with并行。
- T04 高风险价格动作：加入approval、stop、rollback和validator。
- T05 7天观察：写入monitoring/validation任务窗口并指定S08验证。
- T06 新任务与执行中旧任务互斥：建立mutex_with，不得同时running。
- T07 循环依赖：必须报编排错误。
- T08 完整承接S05 option：actions、success_criteria、stop_conditions不得丢失。
- T09 S06 eligible_with_controls：required_controls必须转成control/monitoring/start/stop等真实任务约束。
- T10 S06 prohibited：不得生成正常执行链。
- T11 S06 requires_more_evidence：优先生成data_collection任务，不直接执行高风险动作。
- T12 action结构化：必须至少包含action_type和target，不允许仅自然语言字符串。
- T13 owner/executor/approver/validator角色分离：能够表达Agent负责、工具执行、人工审批、S08验证。
- T14 owner明确但executor未知：任务不得进入ready，应blocked并记录原因。
- T15 approval未完成：任务状态pending_approval，不得ready/running。
- T16 blocked与failed区分：依赖未完成=blocked；已经执行但API失败=failed。
- T17 同一P0经营问题可能需要P1控制任务先执行：business_priority不因执行顺序而被篡改。
- T18 互斥任务同时被安排执行：验收失败，必须冻结或重排。
- T19 资源不足：保留任务并blocked/deferred，不静默删除。
- T20 success_criteria不可测：不得进入调度执行，应先补验证设计。
- T21 stop_conditions与rollback分离：止损停止不等于执行后恢复。
- T22 rollback必须说明恢复目标或动作，不能只写“回滚”。
- T23 monitoring任务必须有监控对象、窗口或触发条件。
- T24 task_type必须与动作一致，approval任务不得偷偷执行真实业务变更。
- T25 active_tasks存在旧观察窗口，新方案要求反向动作：交S03/S10确认，S07不得直接覆盖。
- T26 DAG存在不存在的dependency task_id：写入unresolved_dependencies，不伪造依赖已完成。
- T27 required_controls只存在文字备注、未进入任务/条件：验收失败。
- T28 execution任务必须指定validator，最终可进入S08。
- T29 S07不得实际调用API或模拟执行成功，只输出任务计划。
- T30 task_graph必须至少能表达execution_order、parallel_groups、mutex_groups和validation_tasks。

## 验收总要求
1. S07输出的是Task DAG，不是待办清单；
2. S05/S06关键信息必须向下游保真传递；
3. 风险控制必须被任务化；
4. action达到可交给执行器的结构粒度；
5. owner、executor、approver、validator语义分离；
6. blocked与failed不得混淆；
7. S07只编排，不越权执行；
8. 每条执行路径最终必须能够进入S08验证。
