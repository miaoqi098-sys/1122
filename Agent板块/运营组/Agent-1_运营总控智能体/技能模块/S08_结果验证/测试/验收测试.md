# S08 验收测试 V1.1

- T01 7天观察第2天：observation_window=incomplete，continue_observation，不判strategy_failure。
- T02 动作执行成功但CVR无改善：execution=success，business_outcome不得positive。
- T03 API修改失败且CVR无变化：failure_type=execution_failure，不得写strategy_failure。
- T04 销量上涨但利润跌破底线：guardrail breach，不得判整体success。
- T05 同期BD导致销量上涨：business_outcome可positive，但attribution降低为weak/confounded。
- T06 达成primary且guardrail正常：允许success。
- T07 缺baseline：business_outcome=not_evaluable，overall=inconclusive。
- T08 stop_condition触发：进入rollback/rediagnose，不等待完整窗口。
- T09 完整承接S07 task：读取task_id、decision_id、action、criteria、stop、validator等。
- T10 planned action与actual action不一致：不得按计划动作直接验证，先识别执行偏差。
- T11 execution_status与business_outcome_status必须分离。
- T12 criteria_results必须结构化包含criterion_id/type/status。
- T13 primary/secondary/guardrail/stop_condition能够分别判断。
- T14 7天窗口完整但第4-6天数据缺失：data_completeness降低，不得视为完整高质量验证。
- T15 数据源延迟导致订单暂时为0：不得把0当真实经营结果。
- T16 baseline和actual统计口径不同：criterion not_evaluable或窗口invalid。
- T17 指标单位不同且无法标准化：不得直接比较。
- T18 正向结果+无明显干扰+执行事实明确：attribution允许strong。
- T19 正向结果+多个同期动作：attribution不得strong。
- T20 concurrent_events为空但active执行事实表明有其他动作：降低归因置信度。
- T21 assumption被事实推翻：failure_type=assumption_failure。
- T22 策略正确执行、窗口完整、数据可靠、核心指标恶化：允许strategy_failure。
- T23 数据本身损坏：failure_type=data_failure，不写strategy_failure。
- T24 外部重大变化主导结果：failure_type=external_confounding。
- T25 过早验收：failure_type=premature_evaluation或continue_observation。
- T26 primary部分达成且副作用可控：允许partial_success。
- T27 primary无变化：允许no_effect，但需确认窗口和数据质量合格。
- T28 positive outcome但attribution weak：不得作为高置信S09知识输入。
- T29 execution failed：允许记录事实观察，但不得沉淀“策略无效”知识。
- T30 decision_implication=adjust：S08不得直接生成新的执行任务。
- T31 decision_implication=scale：仍需Agent-1按目标/风险重新决定，不代表自动扩大。
- T32 side_effect触发上层风险：总体状态不得success。
- T33 stop_condition未触发但guardrail接近危险线：应记录side_effect/风险，不静默忽略。
- T34 actual_execution只有API success日志但前台状态未改变：优先真实状态核验，execution不得直接success。
- T35 observation_window=invalid：不得给高置信strategy success/failure。
- T36 attribution_status=confounded时confidence通常不得high，除非有额外强证据并说明。

## 验收总要求
1. 执行成功与经营成功必须分开；
2. 原始baseline/criteria不得事后篡改；
3. 观察窗口和数据质量必须进入机器输出；
4. primary、guardrail和stop条件必须分别验证；
5. 归因必须显式处理同期事件；
6. 失败必须分类，不能把执行/数据问题学成策略失败；
7. S08输出决策含义但不越权生成新方案；
8. 只有足够可信的验证结果才能进入S09形成较高层经验。
