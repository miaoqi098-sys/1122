# S09 异常处理 V1.1

- S08结果inconclusive：只写fact/observation与证据缺口，不生成强经验。
- execution_failure：不得沉淀“策略无效”；只记录执行链问题及无法验证策略的事实。
- data_failure：不把缺失/错误数据形成经营规律，必要时生成数据治理lesson。
- premature_evaluation：记录过早验证，不形成策略成功/失败结论。
- external_confounding或attribution=confounded：保留事实和解释，promotion_gate通常hold/needs_more_evidence。
- attribution=weak：不得生成高置信强因果知识。
- 经验缺applicability或invalid_when：降级为observation/hold。
- previous_lessons缺失：允许创建新lesson，但不能声称不存在历史冲突。
- 与旧经验冲突：relationship=contradicts/conflicted，保留双方证据并进入复核，不覆盖旧记录。
- 新旧经验其实适用条件不同：优先coexists/refines，不误用supersedes。
- 重复经验：merge证据、增加support_count，不无限创建新ID。
- 反例存在：保留contradiction_count，不因当前成功清零。
- 敏感/短时信息：必须设置valid_until或review_trigger。
- knowledge_candidate证据不足：promotion_gate=needs_more_evidence，不为满足流程强行升级。
- validated_knowledge缺知识治理证据：禁止升级，最高停在knowledge_candidate。
- memory store不可写：memory_writes.status=failed/queued，不得假装沉淀成功。
- source decision/task/validation不可追溯：learning item不得升级到可复用知识层。
- fact与interpretation混写：拆分后再沉淀，因果句不能作为原始事实。
- 数据质量低但结果极端：仍受data_quality限制，不因结果幅度大就提升置信度。
- 新结果支持旧经验但样本完全重复：不能把重复数据当独立support_count。
- 时间戳/版本缺失：允许暂存，但进入知识治理前必须补齐。

## 核心原则
长期记忆宁可少学、慢升级，也不能把执行错误、数据错误、偶然相关和短期噪声固化成“经营规律”。
