# S10 判断规则 V1.1

## 一、标准判断链
```text
1. 对齐proposed_action与当前strategy_chain
2. 判断change_relation
3. 检查active/recent tasks与真实状态
4. 判断观察窗口是否完成
5. 分类新信号signal_class
6. 比较original evidence与new evidence，得到evidence_delta
7. 检查state change / guardrail / stop / critical risk
8. 进入Hold Gate或Override Gate
9. 输出allow / hold / merge / escalate / override
10. 如改变策略，明确旧任务后续动作并交S07重新编排
```

## 二、先判断动作关系
仅“对象相同”不足以判定反转。必须比较target、action_type、direction、magnitude、scope、time_horizon。

- same_direction：同方向继续推进；
- minor_adjustment：小幅参数微调且不改变主方向；
- neutral：不影响当前策略方向；
- partial_reversal：部分回撤或局部反向；
- full_reversal：主方向明显反转；
- conflicting_action：动作逻辑冲突，需进一步分析。

## 三、策略链优先于单任务
S10应读取strategy_chain，而不是只看最后一条task。连续多次小幅同方向/反方向变化应累计adjustment_count和reversal_count。

短时间高频小调即使每次都是minor_adjustment，也可能形成慢性抖动，此时可hold或escalate。

## 四、观察窗口未结束时默认保护原策略
如果observation window未结束，且没有stronger evidence、critical_new_fact、state_change、guardrail/stop trigger或critical risk，默认hold。

## 五、重复事实优先merge
同一事实被多个Agent或多个事件重复上报，不自动视为多份独立证据。应merge到同一strategy_chain，并避免重复创建反向任务。

## 六、Signal Classification决定响应方式
- noise：通常hold；
- repeated_signal：通常merge；
- trend：允许重新评估，但不自动override；
- state_change：允许提前重评旧策略；
- guardrail_trigger：根据严重度escalate或override；
- stop_trigger：优先override/停止旧策略；
- critical_risk：优先override或escalate，不受普通观察窗口机械限制。

## 七、Evidence Delta必须比较“新旧证据”
- weaker：新证据弱于原策略启动依据，通常不足以反转；
- same：证据没有实质增强，通常继续观察；
- stronger：新证据明显增强，可进入重评；
- critical_new_fact：出现原策略启动时不存在的关键事实，可直接进入Override Gate；
- unknown：证据质量不明，默认不足以直接override。

## 八、反转门槛高于启动门槛
如果一个策略已经被批准并进入执行/观察阶段，反向动作原则上需要比普通新建议更强的证据，或者关键新事实。

这是为了避免系统被短期噪声来回拉扯。

## 九、Hold Gate不是死等
hold必须同时输出：
- hold_reason；
- hold_until（如能确定）；
- release_conditions；
- review_trigger；
- required_new_evidence。

只要release condition提前触发，就允许重新进入S10判断。

## 十、Override Gate
满足以下任一高强度条件可进入override判断：
1. stop_condition明确触发；
2. guardrail达到不可接受风险；
3. critical_risk出现；
4. confirmed state_change导致原策略不再适用；
5. critical_new_fact出现；
6. 新证据显著强于原启动证据并直接推翻原核心假设。

## 十一、override必须处理旧任务
每次override必须形成override_record，并为被覆盖任务指定：cancel / pause / rollback / continue_monitoring / review。

S10只给出策略级处理意图，真正任务图修改由S07完成。

## 十二、状态证据冲突交S03
如果是否发生state_change本身存在冲突，S10不得自行拍板，应send_to_S03或请求更多上下文。

## 十三、观察窗口结束不等于自动改变
窗口结束只是解除防抖保护，允许进入正常重新决策。是否真的换策略，仍需回到Agent-1的目标、状态、指标和风险判断。

## 十四、S10不阻止正常实验迭代
同方向小幅调整、按既定实验计划切换阶段，不应被误判为策略抖动。但如果调整频率超过策略链容忍度，仍应触发检查。

## 十五、真实状态优先于任务标签
旧任务标记running/completed与真实执行状态冲突时，不应机械依赖任务状态。必要时回S02或执行层核验事实。

## 十六、模块边界
- S03负责冲突识别；
- S10负责策略稳定性和反转门槛；
- S07负责允许变化后的任务重编排；
- S08负责结果验证。

## 核心原则
S10判断的不是“现在数据好不好看”，而是“现在是否有足够新的、足够强的理由，值得打断一条已经在运行的策略链”。
