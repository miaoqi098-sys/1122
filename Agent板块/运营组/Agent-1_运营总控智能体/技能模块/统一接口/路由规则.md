# S01-S10 统一路由规则

## 目的
明确 Skill Runner / Agent Runner 在不同结果状态下下一步去哪里，避免把S01-S10错误实现成固定for-loop。

## 主线正常路由
```text
S01 passed/passed_with_warnings
→ S02

S02 ready/ready_with_gaps
→ 状态识别/必要指标与知识匹配
→ S03

S03 clear/conflicts_found且不阻断
→ DecisionItemBuilder
→ S04

S04 normal/protected且存在可处理事项
→ S05

S05 options_generated/single_feasible_option
→ S06

S06完成且存在可选方案
→ DecisionSelector
→ FinalDecision

FinalDecision可进入执行
→ S07

S07任务具备执行条件
→ 调度/审批/执行层

ExecutionResult +观察数据
→ S08

S08具备学习价值
→ S09
```

## 信息不足路由
- S01 needs_information → 上游事件来源/人工补充；补齐后重新S01。
- S02 needs_information → 数据/Agent/工具补充；补齐后重新S02。
- S03 needs_evidence → S02或对应Agent补证据；不可直接跳S04。
- S04 request_information → 回S02/DecisionItemBuilder更新事项。
- S05 needs_information → 回S02或专业Agent补信息。
- S06 requires_more_evidence → 优先选择information_first路径或回S02/专业Agent。
- S08 inconclusive且窗口未成熟 → continue_observation，不急于S09形成强经验。
- S09 request_more_evidence → 进入下一观察/实验循环，不强行升级知识。

## 阻断/升级路由
- S01 rejected → 终止当前事件链或人工复核。
- S02 blocked → 暂停决策链，解决核心数据/对象依赖。
- S03 blocks_decision → 补证据；requires_escalation → 人工/专业复核。
- S04 gate_status=blocked → 解决blocker；escalated → 审批/复核。
- S06 prohibited → 移除方案，禁止进入S07。
- FinalDecision approval pending → S07只能编排审批前任务，执行任务不得ready。

## S10横向路由
S10触发条件：发现拟议新动作与正在运行/待验证策略链可能存在方向变化、重复或冲突。

### allow
允许新动作继续进入正常决策/任务链。

### hold
保持现有策略，不建立反向执行任务；等待hold_gate释放条件。

### merge
将新证据/同方向动作合入现有strategy_chain，不重复建立孤立策略。

### escalate
进入审批/复核，不自动执行反转。

### override
允许打断旧策略，但必须：
1. 形成override_record；
2. 将旧任务cancel/pause/rollback/continue_monitoring/review动作交S07重新编排；
3. 保留旧decision/task历史；
4. 新FinalDecision引用supersedes_decision_id。

## 回路原则
允许回路，不把回路视为失败：
```text
S03 → S02 补证据
S05 → S02 补信息
S06 → S05 重新生成受约束方案
S08 → Agent-1 → S04/S05 重新诊断
S09 → 下一轮观察
S10 → S03/S02 复核
```

## 禁止路由
- S01 rejected直接进入S02：禁止。
- S03 blocks_decision直接进入S04：禁止。
- S06 prohibited option进入S07：禁止。
- 未形成FinalDecision就由S07自行选方案：禁止。
- 执行层API success直接跳过S08并写S09成功经验：禁止。
- S10 hold状态下创建反向执行任务：禁止。

## Runner原则
Runner只负责按状态和协议路由，不替代Skill业务判断；转换逻辑由canonical schema与桥接组件明确完成。
