# Agent-1 事件日志规范

## 1. 记录目标
记录标准Event从创建、校验、去重、合并、关联、更新到关闭/重开的完整生命周期。

## 2. 必需字段
- event_id
- event_version / revision
- event_type
- scope_type / scope_id / scope_objects
- source_type / source_refs
- evidence_refs
- occurred_at / observed_at / received_at
- freshness / confidence（如适用）
- severity / urgency（事件级，不等于business_priority）
- lifecycle_status
- duplicate_of / merged_into / related_event_ids（如适用）
- validation_status / S01 result ref
- created_at / updated_at

## 3. 生命周期动作日志
以下动作必须追加记录：
- create
- validate / reject / needs_information
- deduplicate
- merge
- relate
- update_evidence
- close
- reopen

每条动作记录要包含动作时间、原因、触发来源和前后版本引用。

## 4. 证据与来源
事件日志不得只写“发现异常”。必须保留可追溯来源：Agent结果、人工输入、系统输入、报告、指标快照等。多个来源冲突时保留全部引用，不静默覆盖。

## 5. 去重与合并
- 重复Event保留duplicate_of；
- 合并后保留merged_into以及原始event_id；
- 不因合并删除原始证据链；
- merged event只聚合，不重写原来源事实。

## 6. 边界
- 事件日志不保存FinalDecision结果。
- Event severity不能被当成S04 business_priority。
- 没有通过S01的输入不得写成“已确认经营事实”。
- run_id/trace_id可附加，但不替代event_id。
