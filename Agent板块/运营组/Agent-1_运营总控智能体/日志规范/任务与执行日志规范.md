# Agent-1 任务与执行日志规范

## 1. 记录目标
记录 FinalDecision 经 S07 转为 TaskPlan / Task / TaskGraph 后的生命周期，以及未来真实执行回执形成 ExecutionResult 的全过程。

## 2. TaskPlan / Task必需引用
- decision_id
- task_plan_id
- task_id
- scope_type / scope_id
- strategy_chain_id（如适用）
- depends_on / blocks / mutex / parallel关系（如适用）
- approval requirements / approval state
- required_controls
- success_criteria / monitoring / validation refs

## 3. Task状态变化
状态变化必须append-only记录：
- created / planned
- pending_approval
- ready / scheduled
- executing
- awaiting_validation
- blocked
- failed
- cancelled
- rollback_planned / rolled_back（仅有真实回执时）
- completed / closed（按正式状态机语义）

每次变化记录前状态、后状态、时间、触发来源、原因和相关证据。

## 4. 审批日志
审批记录必须保留：
- approval_request_id（如未来存在）
- related decision_id / task_id
- requested_at
- requirements
- approver/source
- result
- result_at
- reason / conditions

审批通过不等于执行成功。

## 5. ExecutionResult日志
只有真实执行源回执经ExecutionResultNormalizer后才能记录：
- execution_result_id
- task_id / task_plan_id / decision_id
- execution_source
- started_at / completed_at
- status
- actual_changes
- error / failure reason
- source_receipt_refs
- rollback refs（如适用）

## 6. 边界
- Task created ≠ executed。
- scheduled ≠ executed。
- approved ≠ executed。
- ExecutionResult success ≠经营验证成功。
- 没有真实回执不得写rolled_back/succeeded。
- Scheduler/Executor内部运行trace可以附加，但业务日志仍以task_id/execution_result_id为主键。

## 7. 失败与重试
每次重试都应记录attempt/run引用，但不得重复创建等价Task业务对象，除非S07明确重编排或新FinalDecision要求新任务。
