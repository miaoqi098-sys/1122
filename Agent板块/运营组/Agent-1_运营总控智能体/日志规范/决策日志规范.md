# Agent-1 决策日志规范

## 1. 记录目标
记录从DecisionItem排序、Option生成、RiskAssessment、S10横向控制到FinalDecision形成的完整决策证据链。

## 2. 必需业务引用
- decision_item_id
- option_id / considered_option_ids
- decision_id
- strategy_chain_id（如适用）
- source event_id(s)
- context/evidence refs
- scope_type / scope_id / scope_objects

不得强制所有决策都有product_id/ASIN。

## 3. DecisionItem阶段
记录：
- 问题定义；
- 目标与约束；
- S04 business_priority及其依据；
- 依赖/冲突；
- 证据缺口。

## 4. Option与风险阶段
每个重要Option记录：
- option_id；
- 方案摘要；
- 预期收益/成本/可逆性；
- RiskAssessment ref；
- eligibility；
- required_controls；
- 被排除原因。

prohibited方案必须保留“为何不可选”，不能从日志中消失。

## 5. FinalDecision阶段
记录：
- decision_id；
- selected_option_id；
- why_selected；
- why_not_others；
- success_criteria；
- guardrails / stop_conditions / rollback conditions；
- approval requirements / approval state；
- required_controls；
- strategy_chain关系；
- next_action / routing。

审批不再使用旧固定“L0-L3审批级别”作为唯一真源。

## 6. S10记录
若发生策略冲突/反转，记录：
- trigger；
- prior strategy_chain_id / prior decision refs；
- allow / hold / merge / escalate / override；
- release_conditions / review_trigger；
- supersedes/replaces关系。

## 7. Append-only
人工/系统修订FinalDecision时，不覆盖旧日志。必须保留：旧decision/version、修改时间、修改来源、原因和新版本/新decision引用。

## 8. 与后续对象边界
决策日志只记录“决定了什么、为什么”。
- Task状态属于任务与执行日志；
- ExecutionResult属于执行日志；
- ValidationResult属于验证日志；
- LearningRecord属于学习日志。

不得把“最终经营结果/复盘结论”塞回FinalDecision当作同一对象字段。

## 9. 运行trace
run_id/trace_id可用于定位一次执行尝试，但不得替代decision_id、option_id或strategy_chain_id。
