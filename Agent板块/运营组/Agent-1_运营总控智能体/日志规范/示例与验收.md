# Agent-1 日志规范示例与静态验收

## 示例A｜决策后执行失败
正确日志链：Decision成功形成 → Task创建 → Executor失败 → ExecutionResult=failed → 不生成“策略失败”LearningRecord；后续根据原因重试/阻断/新Decision。

## 示例B｜执行成功但经营结果失败
ExecutionResult=succeeded；S08观察后ValidationResult=failed/未达标。日志保留两者，不把执行日志改写成失败。

## 示例C｜审批等待
FinalDecision需要审批，Task=pending_approval。审批未返回前只追加等待状态，不创建第二个等价Task。

## 示例D｜策略反转
新Decision override旧StrategyChain时，日志保留旧decision/task，新增supersedes/replaces关系和S10证据，不覆盖旧记录。

## 示例E｜学习尚未真实写入
S09已生成LearningRecord和memory_writes plan，但没有R10回执。日志只能记录“计划已生成”，不得写“长期记忆已写入”。

## 静态验收
- [x] 事件、决策、任务执行、验证学习日志职责分层。
- [x] scope不再强制product_id/ASIN。
- [x] 旧固定审批级别不再作为决策日志唯一真源。
- [x] canonical业务主键链完整。
- [x] strategy_chain_id可跨多轮决策追溯。
- [x] run_id/trace_id与业务主键分离。
- [x] 日志默认append-only，修订有版本链。
- [x] source/evidence refs保留。
- [x] Task创建、执行成功、经营验证成功三者严格分离。
- [x] S09计划与R10真实写入严格分离。
- [x] 与历史记忆边界清楚，不复制第二套事实库。
