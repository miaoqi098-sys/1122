## 2. 结构验收
标准案例示例具备 Case.schema.json 要求的核心字段：
- case_id / case_version / case_status / case_type；
- title / scope / time_window / problem_summary；
- decision_item_refs / decision_refs；
- outcome；
- applicability / invalid_when；
- created_at。

并包含完整决策链引用：事件、上下文、冲突、模板、方案、决策、任务、执行、验证、学习、历史。

结论：**统一结构静态检查通过。**

> 当前未运行真实 R03 Schema Validator；这是静态字段与语义验收，不伪称机器验证已执行。

## 3. 引用边界验收
通过：
- Case 不复制 FinalDecision 完整对象；
- Case 不复制 LearningRecord 完整对象；
- Case 不复制历史记忆时间序列；
- Case 只保存episode必要摘要和canonical refs；
- template_refs 保留 template_id + template_version。

这保证案例库不是第二套事实数据库。

## 4. 与相邻模块边界

### 对经营知识库
通过：案例保存具体episode，知识库保存泛化理解和诊断原则。

### 对历史记忆
通过：历史保存事实时间线；Case把相关历史ID作为episode证据组织起来。

### 对S09
通过：Case引用learning_id；经验的证据质量、归因、promotion gate仍以LearningRecord为准。

### 对决策模板库
通过：Case记录当时模板版本用于复盘，但不改变模板治理状态。

## 5. 分类验收
正式 case_type 已覆盖：
- success
- failure
- conflict
- exception
- experiment
- human_correction
- mixed
- investigation

并与 outcome.status 明确分离，避免“实验=成功”或“人工纠正=失败”等错误等价。

结论：**分类语义通过。**

## 6. 复用验收
案例复用必须比较：问题、目标、Scope、状态、约束、动作、证据、时间环境。

复用等级：
- direct_reference
- supporting_reference
- contrast_reference
- historical_only
- excluded

同时受 attribution_strength 与 freshness 约束。

结论：**复用规则通过，禁止机械照抄已明确。**

## 7. 反例检查
以下对象不得进入 reviewed：
1. 只有“上次降价销量涨了”一句总结，没有Decision/Validation引用；
2. 结果成功但同时改了价格、广告、Listing，却写成“价格策略已验证有效”；
3. 平台规则已经变化，仍把三年前促销案例标 direct_reference；
4. 人工纠正只记录“老板要求改”，没有原因和新增证据；
5. 把一个Case的 reusable_summary 直接写入 validated_knowledge；
6. 为方便阅读把整个FinalDecision复制进Case并独立更新。

上述均违反总则/复用门禁。
