# 经营状态识别

## 模块定位
本目录负责帮助 Agent-1 在解释指标和形成重大决策之前，先建立当前产品的“经营状态画像”。

经营状态不是单选标签。一个产品可以同时具有生命周期状态、经营情境状态、风险状态和机会状态。

例如：
```text
生命周期：成长期
经营情境：活动进行期 + 关键词测试
风险状态：库存预警
机会状态：核心关键词自然排名增长机会
```

Agent-1 应基于完整状态画像决定当前主目标、指标解释方式、需要调用的经营知识、风险等级和策略方向。

## 四维状态模型
### 1. 生命周期状态
回答“产品当前处于哪个发展阶段”。原则上一个产品只有一个主要生命周期状态。

### 2. 经营情境状态
回答“当前正在经历或执行什么经营情境”。允许多个状态共存。

### 3. 风险状态
回答“当前有哪些需要保护、限制或优先处理的问题”。允许多个风险同时存在，并应标记严重程度。

### 4. 机会状态
回答“当前有哪些值得主动利用的增长窗口”。机会可以与风险同时存在。

## 标准运行流程
```text
获取产品当前数据与事件
↓
识别生命周期状态
↓
识别经营情境状态
↓
识别风险状态
↓
识别机会状态
↓
处理状态共存、冲突和优先级
↓
形成经营状态画像
↓
交给目标系统调整主目标与目标权重
↓
大脑按当前状态解释指标并形成决策
```

## 核心原则
1. 状态识别先于重大经营决策。
2. 不允许只用一个指标判断复杂经营状态。
3. 不把上架天数直接等同于生命周期阶段。
4. 不把一次短暂波动直接升级为风险状态。
5. 风险状态与机会状态可以同时成立。
6. 高优先级风险可以压制增长机会，但不代表增长机会不存在。
7. 状态必须包含证据、时间范围和置信度。
8. 状态变化应有进入、持续、升级、降级和退出逻辑，避免频繁抖动。
9. 具体数值阈值原则上由经营指标库和配置层提供，本模块负责识别逻辑。

## 与其他模块的关系
- `目标系统/`：根据状态调整主目标、副目标和暂停目标。
- `大脑/`：使用状态决定如何解释事实、证据和方案。
- `经营指标库/`：提供状态识别所需指标、口径和阈值。
- `经营知识库/`：提供不同状态下的经营规律和诊断知识。
- `协作机制/`：状态证据不足时请求对应专业 Agent。
- `技能模块/`：未来把状态识别逻辑工程化为可重复能力。
