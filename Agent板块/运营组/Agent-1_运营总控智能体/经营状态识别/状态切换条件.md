# 经营状态切换条件

## 目的
定义经营状态如何进入、持续、升级、降级和退出，避免 Agent-1 因短期波动频繁改变状态和策略。

## 一、状态生命周期
每个重要状态原则上应支持：
```text
候选 → 已确认 → 持续 → 升级/降级 → 退出
```

### 候选
出现初步信号，但证据不足。

### 已确认
满足识别条件，证据足以把状态纳入正式经营画像。

### 持续
状态仍满足条件，继续影响目标和决策。

### 升级/降级
严重程度、机会强度或影响范围发生变化。

### 退出
触发条件已经消失，或达到预设退出标准。

## 二、进入原则
复杂状态原则上不因单次短暂波动立即进入。

进入时至少判断：
- 是否达到触发条件；
- 是否持续足够时间或拥有足够强的直接证据；
- 是否存在活动、测试或数据延迟造成的假信号；
- 是否会显著影响目标或决策。

对于 Listing冻结、账户通知、已断货等明确事实，可以由单一强证据直接进入状态。

## 三、退出原则
状态退出不能简单依赖“指标回到正常一次”。

应检查：
- 根因是否已经消除；
- 关键指标是否恢复；
- 是否完成必要验证；
- 是否仍存在滞后影响；
- 是否需要进入恢复观察阶段。

## 四、防抖机制
为避免状态频繁来回切换：
1. 进入阈值和退出阈值可以不同；
2. 允许设置最短持续时间；
3. 允许设置恢复确认窗口；
4. 单次异常原则上不改变生命周期状态；
5. 活动和测试期间使用对应状态规则，不用正常期阈值机械切换；
6. 高风险强证据可以绕过普通等待窗口立即升级。

具体阈值由经营指标库和配置层提供。

## 五、生命周期切换
### 新品冷启动 → 成长期
不是按固定天数切换。应看到基本经营模型开始成立，例如稳定订单、有效流量入口、转化基础或关键词资产逐步建立。

### 成长期 → 成熟稳定期
当增长速度和结构逐渐稳定，主要流量入口、转化模型和经营策略进入相对成熟阶段。

### 成熟稳定期 → 衰退/调整期
需要结构性、持续性证据，例如需求、流量、竞争力、利润或产品价值持续弱化，而不是短期活动后回落。

### 任意阶段重新进入调整/再验证
重大改版、重新定位、市场结构变化等可能使产品进入调整状态，但不应简单篡改历史生命周期记录。

## 六、活动状态切换
```text
正常/其他经营情境
↓
活动准备期
↓
活动进行期
↓
活动恢复期
↓
正常经营或其他状态
```

活动结束后必须经过恢复判断，不能立即把活动数据和正常期数据混用。

## 七、测试状态切换
### 进入
测试方案被确认并记录测试对象、假设、窗口、成功标准和止损条件后进入。

### 持续
主要测试变量保持可解释，且未触发止损。

### 提前退出
- 触发止损；
- 高优先级风险出现；
- 测试变量被其他动作污染；
- 数据源失效；
- 测试已经提前得到足够明确结果。

### 正常退出
观察窗口结束并完成结果验证后退出，随后进入学习和历史记录。

## 八、风险状态升级与降级
风险等级应根据：
- 发生概率；
- 影响范围；
- 距离风险发生的时间；
- 可逆性；
- 可替代方案；
- 最新证据。

例如库存风险可以按：
```text
安全 → 预警 → 高风险 → 断货临界 → 已断货
```
也允许补货确认、销量变化等使风险逐级下降。

## 九、异常待诊断切换
### 进入
重要经营结果异常，且原因尚不明确。

### 转换
根因得到确认后：
- 转换为具体风险状态；
- 转换为机会状态；
- 判定为活动/测试正常扰动；
- 判定为无实质异常。

### 退出
原因已经足够解释，或新增数据证明原异常不成立。

## 十、机会状态退出
机会应在以下情况重新评估或退出：
- 机会窗口已经消失；
- 竞争环境发生变化；
- 需求信号不再成立；
- 资源或库存无法承接；
- 验证结果证明机会价值不足；
- 更高优先级风险长期压制，机会已经失去时效。

## 十一、状态切换记录
重要状态切换应记录：
- 原状态；
- 新状态；
- 切换时间；
- 触发证据；
- 关键指标；
- 置信度；
- 对目标的影响；
- 是否触发任务、审批或策略调整；
- 下次复核时间。

## 核心原则
状态切换不是为了追着指标跑，而是为了在经营环境真正发生变化时及时调整目标和策略，同时避免短期噪声造成策略振荡。
