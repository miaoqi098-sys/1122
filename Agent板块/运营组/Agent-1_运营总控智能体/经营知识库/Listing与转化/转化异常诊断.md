# 转化异常诊断

## 核心定位
转化异常是结果，不是原因。Agent-1必须先判断异常发生在哪一层，再决定由哪个Agent继续诊断。

## 第一步：确认异常是否真实
检查：
- 时间窗口是否足够；
- 是否处于活动期或活动结束后；
- 流量结构是否变化；
- 是否只是某个广告组/关键词异常；
- 是否存在样本过小问题。

## 第二步：拆分原因层级
### 流量层
- 新增流量是否更泛；
- 搜索词意图是否变差；
- 广告位是否变化；
- 自然流量来源是否变化。

### 页面层
- 主图、标题、五点、A+、视频是否最近变化；
- 页面是否出现错误信息；
- 核心卖点是否表达不清；
- 移动端展示是否异常。

### 价格促销层
- 售价变化；
- Coupon结束；
- 竞品促销；
- 参考价/划线价展示变化。

### 信任与体验层
- Rating下降；
- 新增集中差评；
- 退货/VOC异常；
- 配送时效变化。

### 商品状态层
- 购物车丢失；
- 库存状态；
- 变体异常；
- 页面被冻结或部分功能异常。

## 第三步：建立假设而非立即改页面
至少形成2-3个最可能原因，并为每个原因列出验证数据。

## 第四步：减少同时变量
尽量不要同时大改价格、主图、广告和促销，否则很难知道恢复由什么造成。

## 第五步：修复顺序
优先修复：
商品不可售/购物车问题 → 价格促销异常 → 明显流量错配 → 严重消费者信任问题 → Listing表达问题 → 细节优化。

## Agent协作
Agent-9内容转化为主要诊断Agent；联动Agent-5流量、Agent-10价格、Agent-11评价、Agent-2商品状态、Agent-3竞品。
