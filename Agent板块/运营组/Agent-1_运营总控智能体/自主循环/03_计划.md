# 自主循环 03｜计划

## 1. 目标
把DecisionItem推进为经过动态排序、候选方案、风险资格和最终选择的FinalDecision，而不是把“计划”当成自由文本建议。

## 2. 正式映射
`S04 DecisionPrioritization → S05 OptionGeneration → S06 RiskAssessment → 必要时S10 → DecisionSelector → FinalDecision/正式非执行路由`

## 3. 动作
1. S04结合目标层级、经营状态、风险机会窗口、依赖、证据和资源动态排序DecisionItem。
2. S05为优先DecisionItem生成多个Option；继续观察/不行动也可以是合法Option。
3. S06评估风险与eligibility，淘汰prohibited方案；requires_more_evidence进入补证据回路。
4. 若候选方案改变现有StrategyChain，按S10规则做allow/hold/merge/escalate/override判断。
5. DecisionSelector选择可成立方案并输出唯一FinalDecision，或输出request_more_evidence/regenerate_options/request_approval_context/hold等正式路由。
6. FinalDecision明确成功标准、required_controls、approval、strategy_chain和后续验证要求。

## 4. 输出
- ranked DecisionItem；
- Option[]；
- RiskAssessment[]；
- 必要时S10结果；
- FinalDecision或明确的非执行路由。

## 5. 边界
- 不使用固定“风险→库存→利润……”链替代S04。
- 不保证必须生成两个方案；方案数量由问题性质决定，但必须足以形成有效比较。
- 不在本阶段创建Task或伪造执行状态。
- prohibited不得进入最终候选。
- eligible_with_controls的controls必须继续传给FinalDecision和S07。

## 6. 回路
方案不足可regenerate_options回S05；证据不足回S02/专业Agent；策略稳定性不足进入S10 hold。任何回路都必须有新原因/新证据，禁止机械循环。
