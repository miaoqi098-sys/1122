# 自主循环 04｜行动

## 1. 目标
把已成立的FinalDecision交给S07转化为可执行任务结构，并进入审批、调度、执行等待；本阶段不伪造真实执行结果。

## 2. 正式映射
`FinalDecision → S07 TaskOrchestration → TaskPlan / Task[] / TaskGraph → Approval / Scheduler / Executor（未来运行层）`

## 3. 动作
1. S07读取FinalDecision，不重新选择Option。
2. 将decision拆成TaskPlan、Task和依赖/互斥关系。
3. 把required_controls、approval requirements、success criteria、monitoring/validation要求传入任务链。
4. 需要审批时进入pending_approval/request_approval_context，不提前执行。
5. 满足执行条件后，由未来Scheduler/Executor真实执行。
6. 只有取得真实执行回执，才能通过ExecutionResultNormalizer形成canonical ExecutionResult。
7. 执行环境重大变化、guardrail触发或S10 hold时，允许暂停/取消/重编排，但保留旧Task历史。

## 4. 输出
框架层输出：
- TaskPlan；
- Task[]；
- TaskGraph；
- approval/blocked/waiting条件；
- 执行所需参数、controls、观察与验证要求。

真实运行后才可能产生：
- ExecutionResult。

## 5. 状态边界
- `task created` ≠ `executed`。
- `approved` ≠ `executed`。
- `execution succeeded` ≠ `business outcome succeeded`。
- 没有真实ExecutionResult，不得写“执行成功/已回滚”。

## 6. 高风险动作
高风险、不可逆或需要审批的经营动作必须遵守FinalDecision/S07的approval与control要求；Agent-1框架只定义条件，真实授权与执行属于运行层。

## 7. 进入下一阶段
只有ExecutionResultNormalizer取得真实执行回执并形成ExecutionResult后，才进入验证阶段。没有回执则保持等待/阻塞/重试状态，不跳到S08。
