# 自主循环 05｜验证

## 1. 目标
基于真实ExecutionResult判断经营结果是否达到FinalDecision定义的success criteria，而不是只检查任务是否执行完。

## 2. 正式映射
`ExecutionResult → S08 OutcomeValidation → ValidationResult`

## 3. 前置条件
只有存在canonical ExecutionResult，且满足所需观察窗口/数据新鲜度条件，才进入正式验证。

以下情况不得提前验证：
- Task尚未真实执行；
- 只有approval，没有ExecutionResult；
- 观察窗口尚未结束；
- 关键指标数据缺失/过期；
- 活动、季节性或并发动作使结果暂不可归因。

## 4. 验证动作
1. 对照FinalDecision/Task中的success criteria、guardrails、stop conditions。
2. 检查ExecutionResult的actual changes与预期动作是否一致。
3. 对比执行前后指标，并识别活动期、季节性、并发动作等混杂因素。
4. 判断结果：成功、部分成功、无效、失败、无法判断/需继续观察。
5. 检查副作用：利润、库存、价格体系、合规、体验等是否恶化。
6. 证据不足时输出premature_evaluation/needs_more_observation，不强行定性。
7. 形成canonical ValidationResult并保留decision/task/execution引用。

## 5. 输出
- ValidationResult；
- outcome/criteria判断；
- 关键证据与归因限制；
- 是否继续观察；
- 是否需要rollback/new diagnosis/new Decision；
- 可进入S09的验证结论。

## 6. 边界
- ExecutionResult success不等于ValidationResult success。
- 执行失败主要说明执行链问题，不得直接学习“经营策略无效”。
- 验证失败不代表自动反转策略，需根据S08结果和S10/新Decision判断。
- 无真实数据不得用预计结果代替ValidationResult。

## 7. 回路
ValidationResult可触发：继续观察、补数据、新诊断、rollback Task、新Decision或策略链复核。任何重入都保留原历史，不覆盖旧结果。
