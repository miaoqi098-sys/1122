# 身份与权限

本目录定义 Agent-1 在运营智能体系统中的身份、职责边界、协作关系、权限/影响分类、审批机制和禁止行为。

这一层回答六个问题：
1. Agent-1是谁？
2. Agent-1应负责什么？
3. Agent-1不得越界做什么？
4. Agent-1与Agent-2至Agent-13如何协作？
5. 什么动作在当前授权范围内可继续，什么动作必须进入approval正式路由？
6. 哪些行为无论什么情况下都不能做？

## 当前文件
- `身份定义.md`：定义Agent-1的系统身份、管理对象、上下游和唯一最终经营决策角色。
- `职责边界.md`：定义Agent-1与各专业Agent的职责分界，以及何时必须请求专业分析。
- `Agent协作关系.md`：定义Agent-1与Agent-2至Agent-13的组织关系、联合分析和冲突处理方式。
- `权限矩阵.md`：定义L0-L3权限/影响等级参考、动作影响边界与自动执行前置条件。L0-L3不再等同固定审批等级。
- `审批与升级规则.md`：定义approval requirements、request_approval_context、pending_approval等正式审批语义，以及权限/影响上调如何影响审批严格度。
- `禁止行为.md`：定义决策、专业边界、权限、执行、合规、数据与冲突处理红线。

## 使用顺序
Agent-1先加载`身份定义.md`和`职责边界.md`确认身份与边界，再按场景加载协作、权限、审批和禁止行为规则。

权限/影响等级只作为风险与授权参考。是否需要审批，必须通过当前正式链：

`S06 RiskAssessment → 必要时S10 → DecisionSelector → FinalDecision.approval → S07 Task审批节点`

不得通过“动作命中L2/L3”直接绕过或替代该链。

## 与其他模块的边界
- 本目录不定义经营目标层级，由`目标系统/`管理。
- 本目录不定义S04 business_priority，由目标系统、经营状态和S04动态形成。
- 本目录不定义分析推理方法，由`大脑/`和Skill负责。
- 本目录不保存具体经营知识，由`经营知识库/`管理。
- 本目录不实现具体Skill能力，由`技能模块/`管理。
- 本目录不负责真实执行，由未来共享`执行层/`承担。
- 本目录的approval语义必须与`决策规则/`、`输出规范/FinalDecision`和`任务调度/`一致。
