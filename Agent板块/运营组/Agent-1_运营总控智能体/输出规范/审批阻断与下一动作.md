# 审批、阻断与下一动作

## 1. 输出不等于执行
Agent-1形成输出后，必须根据当前资格、审批、证据与策略稳定状态决定下一路由，而不是所有结果都自动进入S07执行链。

## 2. DecisionSelector next_action
- `continue_to_S07`：FinalDecision完整、资格允许、必要审批条件满足，可进入任务编排。
- `send_to_S10`：候选决策可能改变正在运行的StrategyChain，先做策略稳定判断。
- `request_more_evidence`：关键证据不足，不形成高置信执行型决策。
- `regenerate_options`：当前Option集合不足以安全选择，返回S05。
- `request_approval_context`：需要审批上下文/授权信息，审批前不得执行。
- `hold_for_review`：当前应保持未决/观察状态，等待触发条件或复核。

## 3. approval状态
FinalDecision.approval至少应能表达：
- required
- status: not_required / pending / approved / rejected / unknown
- reason
- approver
- approval_ref

规则：
- pending/unknown：相关执行Task不得ready；
- rejected：不得继续原执行路径，应返回替代方案或终止；
- approved：只表示授权通过，不代表执行成功；
- not_required：仍需满足其他风险/控制条件。

## 4. blocked与needs information
“缺证据”和“审批未完成”不是执行失败：
- 缺证据 → request_more_evidence；
- 审批缺失 → request_approval_context；
- S10 hold → hold_for_review；
- 硬约束prohibited → 不生成可执行FinalDecision；
- 运行层Task blocked → 属于S07/调度执行链状态，不反写成业务选择失败。

## 5. 低置信输出
decision_confidence=low时：
- 不承载高影响不可逆动作；
- 应缩小动作、增加review_trigger或请求更多证据；
- 必要时hold_for_review。

## 6. 禁止
- 把approval pending包装成continue_to_S07可立即执行；
- 把request_more_evidence包装成“建议已确定”；
- 把执行层blocked等同于DecisionSelector选择错误；
- 审批通过后伪造ExecutionResult。
