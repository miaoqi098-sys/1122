# 输出追溯字段规则

## 1. 业务对象主链
Agent-1 输出必须尽量保持以下主链可追溯：

```text
event_id
→ decision_item_id
→ option_id
→ decision_id
→ task_plan_id
→ task_id
→ execution_result_id
→ validation_id
→ learning_id
```

## 2. StrategyChain
`strategy_chain_id` 横跨多个Decision版本，不等同于decision_id。发生策略替代时应保留：
- strategy_chain_id；
- supersedes_decision_id；
- 旧decision/task引用；
- 新旧方向和触发证据。

## 3. FinalDecision中的追溯
至少应能通过对象或引用获得：
- source_event_ids；
- decision_item_id；
- selected_option.option_id（若对象定义支持）；
- decision_basis.evidence_refs；
- conflict_refs；
- historical_refs；
- strategy_chain_id；
- approval_ref（适用时）。

## 4. Task侧追溯
S07生成Task时至少保留：
- decision_item_id；
- decision_id；
- task_plan_id；
- task_id；
- option_id/source_action_id（可获得时）；
- strategy_chain_id（适用时）。

## 5. 运行追踪
`run_id / trace_id / parent_run_id` 属于运行调用层，可通过trace_refs保存，但不得取代业务对象主键。

## 6. 禁止
- 用最新decision覆盖旧decision记录；
- Task无法追溯到其来源决策；
- 只保存reasoning文本而不保存evidence_refs；
- 使用trace_id作为长期业务唯一ID。
