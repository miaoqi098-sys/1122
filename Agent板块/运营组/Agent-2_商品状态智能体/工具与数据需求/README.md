# Agent-2｜工具与数据需求

## 1. 目标
定义商品状态监控需要的事实来源、最低证据条件和未来工具能力，不在Agent-2内实现API或抓取器。

## 2. 主要数据来源
### Amazon官方/后台事实
- Listing/SKU可售状态；
- 抑制/受限/审核/资质提示；
- 商品关系与变体信息；
- 后台价格/促销配置状态；
- 平台通知/Case/绩效或资质状态（按权限可读范围）。

未来主要依赖R04 Amazon SP-API及其他官方接口/报告能力。

### 前台事实
- detail page可访问性；
- 当前售价/参考价/促销展示；
- Featured Offer显示；
- Listing内容、A+、变体、评分等页面展示。

真实前台抓取/浏览器监控属于未来数据接口/运行层，不在Agent-2本体实现。

### 历史状态
- 上一有效快照；
- 未关闭商品状态事件；
- 过去恢复/重复异常；
- 相关Decision/Task/Validation历史。

依赖未来R06长期记忆/数据层。

## 3. 数据质量要求
每条关键事实至少有：
- source_ref；
- scope；
- observed_at/collected_at；
- freshness；
- evidence_ref；
- 可识别的状态字段或页面事实。

## 4. 来源优先
平台资格、限制、后台状态等事实优先官方来源。

前台显示事实必须以前台证据为准；后台配置不能自动等价“前台已经生效”。

前后台冲突时保留双来源，而不是强制选一个覆盖另一个。

## 5. 所需抽象工具能力
- 读取商品/SKU后台状态；
- 读取Listing/变体结构；
- 检查前台detail page；
- 读取Featured Offer与价格展示；
- 检查内容/A+/促销显示；
- 读取资质/限制状态；
- 生成状态快照；
- diff当前与历史快照；
- 查询未关闭事件；
- evidence存储/引用；
- 向Agent-1上报Event；
- 响应Agent-1专业请求。

## 6. 新鲜度原则
高变状态：Featured Offer、前台价格、促销展示、页面可访问性，需要较高新鲜度。

中变状态：Listing内容、变体关系、评分展示。

低频但高风险状态：资质、限制、合规审核，一旦出现变化需立即上报。

具体抓取间隔/TTL不在框架硬编码，由未来配置和Scheduler实现。

## 7. 降级
- 官方后台暂不可用：可用前台事实，但必须标记后台未知；
- 前台暂不可访问：不能自动判定商品已被删除，应区分网络/工具失败；
- 单一来源冲突：进入recheck/source_conflict；
- 数据过期：降低confidence并请求刷新；
- 工具失败：记录tool failure，不当作业务异常。

## 8. 运行依赖
复用：
- R02 Agent Runner
- R03 Schema Validator
- R04 Amazon SP-API Connector
- R06 长期记忆数据库
- R07 Scheduler

前台页面监控能力未来应归数据接口/运行层；若后续独立建设可新增运行依赖编号，目前先作为R04之外的共享数据接口需求挂账，不在Agent-2实现。
