# Agent-2｜检测与变化规则

## 1. 目标
从连续状态快照中识别“真实、值得上报、可追溯”的商品状态变化，避免页面瞬时抖动或重复采样造成事件洪泛。

## 2. 基本检测链
```text
获取当前快照
→ 检查来源/新鲜度
→ 与上一有效快照比较
→ 识别变化域
→ 判断变化是否持续/是否需要复核
→ 计算事件严重度建议
→ 去重/合并
→ 形成智能事件或继续观察
```

## 3. 立即事件候选
以下变化通常无需等待多个周期即可形成事件候选，但仍需保留证据：
- 前台页面从可访问变为dog page/not found；
- 后台状态变为restricted/suppressed/action_required；
- 商品突然不可售；
- 父子体/变体关系发生明确结构变化；
- 关键资质状态从clear/pending变为failed/restricted；
- 页面/后台出现明确高风险状态冲突。

## 4. 需要持续确认的变化
以下变化可能受缓存、实验、前台个性化等影响，默认要求至少一个复核来源/后续快照：
- Featured Offer短暂丢失；
- 划线价/参考价短暂不显示；
- Coupon/Badge偶发消失；
- 图片/A+部分模块瞬时未加载；
- 评论数量/评分小幅变化；
- 前台与后台单次不一致。

若已有官方后台通知或高置信证据，可跳过等待。

## 5. 严重度建议
Agent-2只提供事件severity建议，不决定S04 business_priority。

参考：
- P0：账户/店铺级商品状态大面积失效，或关键商品明确高危停售且影响巨大；
- P1：核心商品不可售、页面变狗、明确restricted/failed、重大变体断裂；
- P2：Featured Offer持续丢失、参考价/促销展示异常、内容/变体局部异常；
- P3：低影响展示变化、需要观察但暂不影响可售的状态变化。

severity必须允许因scope、持续时间和证据升级/降级。

## 6. 去重指纹
建议事件去重指纹：
`scope_type + scope_id + status_domain + normalized_change_type`

同一指纹在未恢复前重复采样：
- 更新原事件证据/持续时间；
- 不重复创建等价Event。

恢复后再次发生可新建事件，并关联previous_event_id。

## 7. 恢复事件
高影响异常恢复也应形成状态更新/恢复事件，例如：
- dog page恢复；
- suppressed→active；
- Featured Offer恢复；
- 资质审核通过；
- 变体恢复。

恢复事件不能静默删除旧异常历史。

## 8. 缺失与冲突
无法确认变化时输出：
- insufficient_evidence；
- needs_recheck；
- source_conflict；
并记录所需补证据。

不得为保持监控“有结果”而猜测状态。

## 9. 时间与新鲜度
不同状态域可拥有不同复核周期；具体分钟数/抓取频率属于未来配置/调度，不在本规则硬编码。
