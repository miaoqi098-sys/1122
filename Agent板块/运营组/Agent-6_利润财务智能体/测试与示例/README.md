# 测试与示例

## 静态验收目标
验证 Agent-6 的利润口径、财务约束、事件输出、跨Agent边界和数据降级逻辑在框架层可闭合。

## 必测场景
1. 销量上涨但贡献利润下降：必须识别成本/折扣/广告拖累，不能只看收入增长；
2. ACOS高但仍盈利：不得机械判定广告失败；
3. ACOS低但产品亏损：必须识别COGS/FBA/退款等非广告成本；
4. Coupon加深导致转化提升但利润跌破break-even：应形成财务约束事件并上报Agent-1；
5. 仓储费用突增：应区分销量问题与库龄成本；
6. 退款成熟数据不足：输出必须降级置信度；
7. COGS版本更新：旧模拟必须失效或重算；
8. 广告归因窗口不一致：禁止直接横向比较；
9. 价格变化与CVR同时变化：模拟必须标记非线性风险；
10. 多Agent冲突：Agent-6只提供财务边界，由Agent-1做最终权衡。

## 示例A｜收入增长但利润压缩
- 30日销售额 +18%；
- 广告成本 +35%；
- Coupon让利 +20%；
- 单位贡献利润 -12%。

正确结论：`MARGIN_COMPRESSION`，主要驱动为广告成本与促销让利，不得输出“销量增长=经营改善”。

## 示例B｜高ACOS但仍处于可承受区间
- 当前ACOS 31%；
- break-even ACOS 38%；
- 单位贡献利润仍为正；
- Agent-4报告增长词流量扩张。

正确结论：广告成本压力存在但未越过财务硬边界；是否继续扩张由Agent-1结合目标系统决定。

## 示例C｜退款数据不成熟
近3日退款率显著低于30日，但退款成熟窗口不足。正确输出应标记 `data_quality` 风险，不允许直接判断体验改善或利润改善。

## 验收判定
- 核心利润指标口径清楚；
- 财务约束不越权为最终决策；
- 事件/响应对象可供Agent-1消费；
- 数据缺失有降级；
- 历史基线有版本和混杂因素；
- 不把模拟值当真实值；
- 无需真实API即可完成静态框架验收。
