# 历史基线与观察窗口

## 目的
库存判断必须结合历史销量、供应周期、季节性和活动上下文，避免用单一短期均值机械补货。

## 基线
- 销量基线：7/14/30/60/90日；
- 同期基线：去年同期、同节日前后；
- 供应周期基线：供应商/线路/FBA接收的P50/P90；
- 活动基线：活动前、活动中、活动后；
- 库存基线：历史覆盖天数、断货频率、积压与库龄变化。

## 观察窗口
短期用于断货风险，中期用于补货，长期用于季节性和库龄。窗口必须与lead time匹配；供应周期60天时只看最近7天需求不得直接做最终补货判断。

## 必须标记的混杂因素
- 断货/低库存；
- 广告扩量或缩量；
- 价格/促销；
- Listing状态变化；
- 节假日与季节性；
- 竞品大促或市场趋势突变；
- FBA接收延迟；
- 大额B2B/异常订单。

## 基线失效
以下情况重新构建基线：产品生命周期切换、重大价格体系变化、供应商/运输路线变化、促销机制变化、广告策略重构、市场需求结构突变。

## 历史学习边界
历史补货结果可以用于修正lead time和forecast error，但不能因为“上次补了X件”就机械复用数量。所有历史经验必须保留当时需求、供给和活动上下文。
