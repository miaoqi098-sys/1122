# 专业 Agent 事件字段映射表 V1.0

| 领域事件语义 | Agent-1 Canonical Event | 规则 |
|---|---|---|
| 领域事件主键 | `event_id` + `source_ref` | canonical event 使用业务链 event_id；原领域ID写 `source_ref` 并在 metadata 保留 |
| Agent编号 / agent_id | `source_agent` | 固定 Agent-2 至 Agent-13 |
| 专业事件来源 | `source_type` | 固定 `professional_agent` |
| 领域事件类型 / opportunity_type | `event_type` | 转为稳定、非同义重复的事件类型 |
| 嵌套 scope | `scope_type / scope_id` | 主经营对象规范化；其他对象进 scope_objects |
| affected_entities / dependencies | `scope_objects` | 只放与该事件事实相关的对象，不把任务依赖伪装成 scope |
| product / asin | `product_id / asin` | product、parent_product、sku scope 按 Agent-1 Schema 要求补 product_id |
| critical | `severity=P0` | 最高紧急/影响 |
| high | `severity=P1` | 高影响 |
| medium | `severity=P2` | 中影响 |
| low / info | `severity=P3` | 低影响/信息性 |
| numeric confidence 0..1 | `confidence` | 直接保留 |
| confidence=low | `confidence=0.35` | metadata.original_confidence=`low` |
| confidence=medium | `confidence=0.65` | metadata.original_confidence=`medium` |
| confidence=high | `confidence=0.85` | metadata.original_confidence=`high` |
| observed_at / detected_at | `occurred_at` | 优先使用事实首次发生/观测时间 |
| generated_at | `occurred_at` 或 metadata | 仅无更准确发生时间时作为 occurred_at |
| Agent-1接收时间 | `received_at` | 接收侧时间，不覆盖领域发生时间 |
| hypothesis / diagnosis | metadata / interpretation context | 不进入 facts，除非其中存在可拆分验证事实 |
| 领域事实 | `facts[]` | 必须是可证实陈述 |
| 专业摘要 | `summary` | 事实导向、可独立理解，不写成决策指令 |
| metric_deltas / expected_impact数据 | `metrics` | 已观测指标可进 metrics；纯预测应保留在 metadata |
| evidence_refs | `evidence_refs` | 原样透传，必要时补统一引用 |
| recommendation_candidates | `recommendation` / metadata | 仅候选建议，不升级为 FinalDecision |
| current_window / baseline_window | `data_window` + metadata.domain_payload | data_window存摘要，完整窗口保留领域payload |
| status | metadata.domain_status | 领域状态不直接替代 Agent-1 事件生命周期 |
| related domain event | `related_events / parent_event_id` | 仅真实存在业务关系时映射 |
| strategy_chain_id | metadata.strategy_chain_id | Canonical Event 当前无主字段，不应为此强改Schema |
| run_id / trace_id | 不映射 | 属于运行调用信封，不是业务 Event |

## Scope选择规则
当一个领域事件同时涉及多个层级：
1. 选择事件主要经营影响对象作为 canonical `scope_type`；
2. 其余受影响对象放 `scope_objects`；
3. 不因 campaign / target / product 多层对象同时存在，就重复上报多份同一事实；
4. 如果不同对象事实上拥有不同严重度、不同发生时间或不同处置路径，才允许拆成多个 Event。

## Facts过滤规则
允许：
- “过去7天该target 42次点击0订单。”
- “ASIN前台页面返回not found。”
- “过去14天贡献利润率下降至8.2%。”

禁止直接写入 facts：
- “应该降价。”
- “广告算法坏了。”
- “该机会一定能增长30%。”
- “竞品恶意攻击。”

## 兼容原则
本映射表只规范跨 Agent 交接，不替代任何专业 Agent 的领域 Schema。专业对象内部可以继续采用更细粒度状态与字段。
