# 亚马逊智能体架构

本仓库作为亚马逊运营智能体系统的主工程仓库。

## GPT → Codex 长期执行入口

涉及“调用 Codex、让 Codex 执行、让 Codex 施工、让 Codex 修改工程、让 Codex 在本地执行”等需求时，新的 GPT 对话必须优先读取：

`10_对外链接/01_GPT链接Codex/GPT链接Codex_长期执行入口.md`

机器可读配置：

`10_对外链接/01_GPT链接Codex/gpt-codex-control.json`

长期控制面采用：`GPT → GitHub → AACC CodexBridge / LocalOps → NODE-001 → Codex / 固定本地操作`。聊天历史不是该执行链的唯一事实来源；执行前必须 fresh-read GitHub / NODE 状态。若当前 GPT 对话没有 GitHub 写能力或 AACC Runtime 没有 fresh evidence 证明可用，不得伪造“Codex 已执行”。

## 项目定位

以 Agent-1_运营总控智能体为运营组唯一总控决策中枢，Agent-2 至 Agent-13 负责各专业领域分析；所有 Agent 共用统一的大模型运行、工具、数据接口、长期记忆、调度、执行与公共基础设施。

目标不是建立 13 个互相孤立的机器人，而是建设一套“共享基础设施 + 多专业 Agent + 统一总控”的亚马逊运营智能体系统。

## 七个共享基础设施层

### 1. 系统运行层
负责大模型运行时、Agent运行器和上下文管理，把 Agent 的静态定义真正装载并运行。

### 2. 工具层
提供 Agent 可调用的“手和眼睛”，包括亚马逊、广告、关键词、财务、网页、GitHub 等工具。

### 3. 数据接口层
负责连接 Amazon SP-API、Amazon Ads API、第三方数据源和文件导入，并进行数据标准化。

### 4. 记忆与数据层
保存产品主数据、产品历史、决策历史、任务历史、实验历史和长期记忆。

### 5. 调度与自动化层
负责定时任务、事件触发、Agent调度、失败重试和异常处理。

### 6. 执行层
负责人工审批、自动执行、任务执行器、回滚和执行结果回传。

### 7. 系统公共层
提供统一配置、日志、权限、监控与测试能力。

## 当前工程原则

- Agent 负责目标、分析、判断、Skill 与专业决策逻辑。
- 共享基础设施负责运行、数据、工具、记忆、调度和执行。
- Agent-1 是运营组最终决策出口，不等于所有其他 Agent 的简单汇总器。
- 高风险、不可逆、合规类操作必须受审批和权限控制。
- 所有决策、任务、执行结果与复盘都必须可追溯。
