1122 现以 **12 个一级业务/系统板块 + UI界面设计板块 + 系统冲突问题库** 作为正式根级架构。

## 正式一级板块

1. 选品板块
2. 运营板块
3. 沙盘演练板块
4. 政策边界板块
5. **亚马逊政策边界**
6. Agent板块
7. 技能板块
8. 对外连接板块
9. 任务中心板块
10. 知识板块
11. 记忆板块
12. **数据板块**（系统级经营事实、历史快照、运营计划、事件与存储访问层）
13. UI界面设计板块（+1，系统建设与界面设计承载区）
14. 系统冲突问题库（+1，跨模块冲突登记、修复与闭环追踪）

`.github/`、`tools/` 与根 `README.md` 属于仓库工程支撑文件，不计入正式业务板块。

## 为什么数据板块提升为根级

1122 已从原型阶段进入真实 Amazon / Sif 数据持续接入阶段。数据不再只是某一个业务模块的附件，而是运营 UI、Agent、A1、任务中心、沙盘、知识和长期分析共享的系统事实层。

因此正式将 `数据板块/` 提升为系统级一级模块。

这不等于把真实数据写进 Git：

- Git：保存 Schema、Migration、数据契约、访问代码和治理规则；
- D1：保存可查询的长期经营事实；
- R2：保存原始报告和长期档案（账号 R2 功能启用后接入）；
- KV：保存当前状态和高速缓存；
- Worker Secrets：保存 Secret / Token。

## 数据层正式资源

```text
数据板块
├── HOT  → KV / Current State Cache
├── WARM → D1 / 1122-core
└── COLD → R2 / 1122-data-archive（待 Cloudflare 账号启用 R2）
```

D1 `1122-core` 已创建并完成第一版 Schema Migration；当前 ProductIdentity、InventorySnapshot、SalesSnapshot、TrafficSnapshot 和 FinanceSnapshot 已开始进入永久事实层。

## 关键归位关系

- 运营业务页面、计划和策略入口 → `运营板块/`
- Agent 与运行基础能力 → `Agent板块/`
- 工具调用与技能 → `技能板块/`
- 执行、调度和自动化 → `任务中心板块/`
- 第三方连接与 API Bridge → `对外连接板块/`
- **Canonical Model、历史事实、Snapshot、OperatingPlan、Event、D1/R2/KV访问规范 → `数据板块/`**
- 1122 系统自身的安全、权限、审批、自动化治理和公共运行边界 → `政策边界板块/`
- **Amazon 平台政策、经营动作限制、商品合规、官方政策证据、政策版本与 Policy Diff → `亚马逊政策边界/`**
- 用户/Agent 长期记忆语义 → `记忆板块/`；经营事实数据库本身归 `数据板块/`

## 数据流原则

```text
Amazon / Ads / Sif / Internal
            ↓
       对外连接板块
            ↓
      Normalize / Validate
            ↓
         数据板块
      ┌─────┼─────┐
      ↓     ↓     ↓
     R2    D1    KV
      ↓     ↓     ↓
   Archive Query Current
            ↓
  UI / Agent / A1 / Task
```

经营历史不可静默覆盖、不可静默删除、必须可追溯、必须能够在关键层级重建。
