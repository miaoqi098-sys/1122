## 五、运营UI的双视角原则

运营UI不能把各业务模块设计成彼此孤立的页面，需要同时支持“全局管理视角”和“单品经营视角”。

### 01 全局管理视角
用户从运营二级板块进入，对全店或多个产品进行横向管理，例如：
- 进入广告板块，查看和管理全部产品广告；
- 进入库存物流板块，查看全部SKU库存与物流状态；
- 进入竞品板块，查看全部竞品池；
- 进入站外推广板块，查看全部推广项目；
- 进入产品板块，查看全部产品经营状态。

### 02 单品经营视角
产品是运营UI的重要核心对象。用户进入某一具体产品后，应围绕该产品查看完整经营状态与关联信息。

已经确认的产品级核心内容包括：
- 当前经营状态；
- 当前阶段；
- 当前目标；
- 今日已执行操作；
- 当前任务；
- 历史总结；
- 流量与转化；
- 价格与促销；
- 利润与经营；
- 消费者体验。

广告、库存物流、竞品、站外推广等全局板块的信息，也可以在单品视角中以该产品的关联摘要、入口或组件方式出现；是否成为产品三级独立页面，后续再确定。

因此当前设计原则是：

```text
运营
├── 全局功能入口
│   ├── 产品
│   ├── 库存物流
│   ├── 站外推广
│   ├── 竞品
│   └── 广告
│
└── 单品经营入口
    └── 某个产品
        ├── 产品经营状态
        ├── 当前目标
        ├── 今日操作
        ├── 当前任务
        ├── 历史总结
        └── 已确认的产品三级经营页面
```

## 六、UI首页定位

首页定位为“经营指挥中心”，而不是单纯的数据仪表盘。

首页需要让用户快速回答：
- 今天整体经营怎么样？
- 哪些事情必须由我处理？
- Agent今天做了什么？
- 每款产品现在处于什么经营状态？
- 今天系统对每款产品具体执行了什么操作？
- 当前有哪些值得关注的异常或机会？

首页的信息需要区分：
- 需要知道：经营数据；
- 需要用户行动：今日需要我处理；
- 系统正在/已经行动：Agent今日动态、产品今日操作；
- 值得持续关注：异常与机会。

## 七、首页六大区域

### 01 左侧全局导航
承载终端业务导航：选品、运营、沙盘演练、政策边界、Agent、技能、对外连接、任务中心、知识、记忆。

UI界面设计板块自身不进入终端用户左侧业务导航。

当前导航原则：左侧主要承载一级业务入口；进入运营等一级板块后再展开对应二级入口，避免把全部三级页面一次性堆入全局导航。三级页面的最终承载方式（页签、子导航或页面内入口）后续确定。

### 02 今日经营概览
首页顶部展示核心经营指标。当前已确认核心方向包括：
- 今日销量/销售；
- 今日花费；
- 今日利润。

其他指标是否进入首页后续再确定，避免首页堆积过多指标。

### 03 今日需要我处理
只展示智能体无法自行完成、需要人工审批、人工决策或人工执行的事项。

基本要求：
- 按优先级排序；
- 每项任务可进入任务详情；
- 包含任务说明与备注；
- 需要说明为什么必须人工处理；
- Agent建议、依据、风险、截止时间、操作按钮等作为任务详情设计方向，具体字段后续继续确认。

该区域与“任务中心”不同：任务中心承载全部任务；首页这里只聚合真正需要用户介入的任务。

### 04 Agent今日动态
用于展示Agent已经发现、判断、创建或执行的重要动作，避免Agent后台工作成为黑箱。

该区域与“今日需要我处理”严格区分：
- 今日需要我处理 = 用户需要行动；
- Agent今日动态 = 系统/Agent已经做了什么。

### 05 产品经营状态与今日操作
首页展示每款产品的经营摘要。

首页产品摘要至少应让用户看到：
- 产品；
- 当前阶段；
- 今日/当前核心目标；
- 今日操作数量或摘要；
- 当前状态。

关键交互已经确认：**点击首页对应产品，进入该产品的完整“产品状态卡”。**

“今日已执行操作”必须在产品经营状态中一级可见，不能隐藏成只有进入深层页面才能看到的信息。

首页产品列表/摘要可以采用类似以下信息结构：

```text
产品        当前阶段        今日/当前目标        今日操作        当前状态
产品A       阶段X           目标X                5项             正常
产品B       阶段Y           目标Y                3项             关注
```

阶段名称、状态枚举和具体视觉表达尚未确认，上表只定义信息结构，不固化示例值。

### 06 重点异常与机会
展示值得用户知道、但当前不一定需要用户立即操作的风险、异常、竞争变化和增长机会。

该区域与“今日需要我处理”不同：异常/机会可以处于Agent分析、观察或自动处理过程中，不代表一定需要人工动作。

## 八、产品状态卡（点击产品后进入）

完整产品状态卡当前至少包含：

1. 今日经营
2. 当前经营阶段
3. 当前核心目标
4. 今日已执行操作
5. 当前进行中的任务
6. 最近阶段总结 / 完整经营历史入口

### 01 今日经营
用于回答“这个产品今天经营结果怎么样”。具体指标字段后续继续规划，不在本版擅自固定。

### 02 当前经营阶段
用于明确产品目前处于哪个经营阶段以及阶段进度。具体阶段枚举和判定标准尚未确认。

### 03 当前核心目标
用于显示该产品目前正在追求的主要经营目标，并与当前任务、今日动作和后续验证建立联系。

### 04 今日已执行操作
必须作为一级可见信息，建议采用时间轴表达。

每项操作需要能够追溯：
- 谁执行（Agent/人工/系统）；
- 何时执行；
- 为什么执行；
- 做了什么；
- 执行结果；
- 关联任务或关联决策。

必要时可以继续进入操作详情查看依据、操作前后值、任务来源、决策来源和后续验证状态。

核心原则：未来Agent系统不能成为AI黑箱，用户必须能够回答“今天系统到底对这个产品做了什么”。

### 05 当前进行中的任务
展示仍处于执行、观察、等待、验证、审批或等待触发状态的工作，用于回答“这个产品接下来正在做什么”。

### 06 最近阶段总结 / 完整经营历史
首页或状态卡优先展示简短阶段总结；完整历史通过入口进入经营历史/记忆视图，避免把长历史直接堆在首页。

### 今日已执行操作 与 当前任务的边界

两者必须严格区分：
- 今日已执行操作 = 已经发生的动作和结果；
- 当前任务 = 正在执行、观察、等待、验证、审批或等待触发的工作。

## 九、首页到产品的交互关系

```text
首页
└── 产品经营状态与今日操作
    ├── 产品A摘要 ──点击──> 产品A完整状态卡
    ├── 产品B摘要 ──点击──> 产品B完整状态卡
    └── 产品C摘要 ──点击──> 产品C完整状态卡

产品状态卡
├── 今日经营
├── 当前经营阶段
├── 当前核心目标
├── 今日已执行操作时间轴
├── 当前进行中的任务
└── 最近阶段总结 / 完整经营历史
```

关键交互原则：
- 首页负责快速判断，不承载全部细节；
- 点击对应产品进入该产品状态卡；
- 状态卡负责回答该产品“现在怎么样、目标是什么、今天做了什么、接下来做什么、之前发生过什么”；
- 需要更深分析时，再从状态卡进入对应产品三级经营页面或关联业务板块。

## 十、当前明确边界

- Agent ≠ Skill：Agent回答“谁负责”，Skill回答“会什么”。
- 知识 ≠ 记忆：知识是可复用认知，记忆是具体产品/任务/决策真实发生过的历史。
- 政策边界 ≠ 风险Agent：政策边界提供系统级约束，风险Agent使用这些约束进行业务判断。
- 对外连接 ≠ Skill/工具：对外连接回答“接了什么系统”，Skill/工具回答“利用连接能做什么”。
- 任务中心 ≠ Agent：Agent是判断/决策主体，任务中心承载决策后形成并运行的工作。
- UI界面设计板块负责“怎么展示”，业务架构负责“系统有什么”。
- 首页“今日需要我处理” ≠ 全部任务：前者只聚合需要人工介入的任务。
- 首页“Agent今日动态” ≠ 今日需要我处理：前者说明系统做了什么，后者说明用户必须做什么。
- 首页“重点异常与机会” ≠ 人工任务：值得关注不代表需要立刻人工处理。
- 产品“今日已执行操作” ≠ 当前任务：前者是已经发生的动作，后者是尚在运行或等待的工作。
