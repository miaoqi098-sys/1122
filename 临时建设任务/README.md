# 临时建设任务

> 本目录是 `Agent库/` 框架建设期间使用的临时施工控制区，**不属于“亚马逊智能体架构”的正式组成部分**。

它不是简单的待办清单，而是当前 Agent库 建设的 **施工队列 + 任务生成器 + 阻塞管理器 + 分层验收记录**。

---

## 1. 核心目的

本目录用于保证 Agent库 可以沿既定主线持续推进，而不会因为聊天中断、临时发现问题或运行层依赖而失去建设顺序。

必须实现五件事：

1. **自动确定下一任务**：当前任务完成并通过回顾后，从 `任务总表.md` 找到下一可执行任务；当前模块结束则进入下一模块，当前 Agent 结束则进入下一 Agent。
2. **分析后再生成任务**：任何模块/子模块开始时先读取现状、分析缺口，再决定需要哪些任务、文件或文件夹；不得把预估任务直接当成最终施工清单。
3. **任务执行中可继续生长任务**：执行某个任务前再次分析；若发现新的必要工作，先同步到任务总表，再逐项执行。
4. **逐层回顾**：单任务完成回顾单任务；子模块完成回顾子模块；模块完成回顾模块；Agent 完成回顾整个 Agent；Agent库 完成做全库总验收。
5. **一次用户指令默认只推进一个最小可验收单元**：不得一次跨过多个独立 Skill、模块或 Agent。每次执行结束后完成汇报、回顾、任务表更新和下一任务指针更新，然后结束本轮执行，等待用户下一次“执行/继续”指令；**不要求主动向用户提出问题，也不制造额外问答环节。**

---

## 2. 正式任务命名

统一使用：

`Agent编号-正式文件夹路径-任务主题-序号`

例如：

```text
Agent-1-决策模板库-广告决策模板-结构分析-1
Agent-1-决策模板库-广告决策模板-字段规范-1
Agent-1-决策模板库-广告决策模板-示例与验收-1
```

如果当前只是施工子域、尚未确认需要正式建文件夹，也可以先使用该名称作为任务前缀；只有分析确认正式架构需要时，才创建正式文件夹。

任务名必须回答：**这件事属于哪个 Agent、哪个模块、哪个子模块、要解决什么。**

---

## 3. 任务不是一次性预制，而是“分析 → 生成 → 执行”

`任务总表.md` 中提前存在的任务属于 **计划任务**，不是不可修改的最终清单。

每进入一个新的施工单元，必须先执行：

```text
读取当前正式目录
↓
分析已有文件与上下游关系
↓
判断缺失/冲突/重复/越界
↓
确认是否需要新增、拆分、合并或取消任务
↓
同步任务总表
↓
再开始执行
```

如果分析发现需要新的正式文件夹：

```text
先登记“建立文件夹/定义职责”任务
↓
确认该目录确实属于正式架构
↓
创建文件夹及承载文件
↓
再生成该文件夹内部任务
```

禁止先大量建空文件夹，再倒推它们应该做什么。

---

## 4. 任务递归生成机制

执行任务本身也必须先分析。

例如当前：

`Agent-1-决策模板库-广告决策模板-1`

分析后发现还需要：

```text
Agent-1-决策模板库-广告决策模板-统一结构-2
Agent-1-决策模板库-广告决策模板-适用边界-3
Agent-1-决策模板库-广告决策模板-验收规则-4
```

则必须先把这些任务同步到 `任务总表.md`，再按照依赖顺序逐项执行。

如果其中某一项再次分析出新任务，同样先登记再执行。

任务允许递归生长，但不得无限发散；每个新任务必须说明：
- 为什么需要；
- 正式归属在哪里；
- 是否阻塞当前任务；
- 是否属于框架层；
- 完成后返回哪里。

---

## 5. 自动续接规则

“自动继续”指 **任务队列自动推导下一项并更新当前指针**，不是在同一回复中连续执行所有后续任务。

当前任务完成并回顾后：

```text
是否有未完成阻塞任务？
├─ 有 → 下一任务 = 最高优先级阻塞任务
└─ 无
   ↓
当前子模块是否还有任务？
├─ 有 → 下一任务 = 当前子模块下一任务
└─ 无 → 做子模块回顾
          ↓
当前模块是否还有任务？
├─ 有 → 下一任务 = 当前模块下一子模块/任务
└─ 无 → 做模块总回顾
          ↓
当前Agent是否还有模块？
├─ 有 → 下一任务 = 当前Agent下一模块
└─ 无 → 做Agent总回顾
          ↓
Agent库是否还有Agent？
├─ 有 → 下一任务 = 下一Agent的启动分析任务
└─ 无 → Agent库总体验收
```

例如：

`Agent-1-决策模板库-示例与验收-1`

完成后不会停在“请用户重新告诉我下一项”，而应自动检查：
- 是否新生成了同模块阻塞任务；
- 若没有，则把下一任务指向 `Agent-1-决策模板库-总验收-1`；
- 决策模板库封板后，把指针更新到 Agent-1 下一未完成模块；
- Agent-1 封板后，自动生成/指向 Agent-2 的启动分析任务。

完成这些自动续接动作后，本轮执行结束。**无需主动提问；只需明确汇报下一唯一任务，等待用户下一次下达执行指令。**

---

## 6. 一次用户指令的最大执行粒度

默认一次用户“执行/继续”只推进 **一个最小可验收单元**。

正确示例：

```text
用户：完善 S01
→ 分析 S01
→ 生成/更新 S01 所需任务
→ 执行当前 S01 子任务
→ 回顾该子任务
→ 若 S01 当前轮已收口，再回顾 S01
→ 更新下一任务为 S02
→ 汇报本轮结果
→ 本轮结束
```

错误示例：

```text
用户：完善技能模块
→ 一次性修改 S01-S10
→ 直接宣布整个技能模块完成
```

即使下一任务已经明确，也只**更新并汇报下一任务指针**，不默认在同一轮继续执行，除非用户明确要求本轮连续处理多个任务。

## 7. 分层回顾机制

### L1｜任务回顾
每完成一个任务必须检查：任务目标、实际修改、遗漏、冲突、运行依赖、新增任务。

### L2｜子模块回顾
一个子文件夹/子域的任务全部完成后，检查内部结构、接口、示例、测试和边界是否完整。

### L3｜模块回顾
一个一级模块完成后，必须重新读取模块整体，并与上下游模块做一致性复核。

### L4｜Agent回顾
一个 Agent 的所有模块完成后，检查身份、输入、分析、Skill、输出、协作、工具需求、测试之间是否形成完整框架。

### L5｜Agent库回顾
Agent-1 至 Agent-13 完成后，做公共对象、职责重叠、空白区、协作协议和整体静态验收。

任何层级回顾发现问题，都要先生成正式路径任务并回到队列，不得为了“已经做到总验收”而忽略问题。

## 8. 状态

统一使用：
- `⬜ 待分析`
- `🔎 分析中`
- `⬜ 待执行`
- `🟦 执行中`
- `🟨 被阻塞`
- `🟪 待回顾`
- `✅ 已完成`
- `⏸ 暂缓`
- `❌ 取消`

“完成修改”不等于“已完成”；必须经过相应层级回顾后才能标记 `✅`。

---

## 9. 当前建设边界

当前目标是：**把 Agent库 的框架内容完善到可供未来运行层实现，但不进入真实运行实现。**

允许：
- 目录、README、规则、流程；
- Schema、字段、接口、对象关系；
- 模板、案例、知识、状态、指标；
- 异常路径、审批边界、权限需求；
- 示例、静态测试、验收标准；
- 工具/API/数据库/调度/执行的需求定义与接口占位。

不进入：
- Agent Runner / Skill Runner 实现；
- Amazon SP-API / Ads API 真实接入；
- 数据库真实部署；
- Scheduler / Executor 真实实现；
- 生产环境权限、服务器、部署、监控；
- 真实广告、价格、库存、Listing 修改。

遇到这些内容统一写入 `运行依赖待办.md`，不偏离 Agent库 主线。

---

## 10. 本目录文件职责

- `README.md`：施工系统总原则与推进算法。
- `任务总表.md`：唯一任务队列、当前指针、任务状态和层级回顾节点。
- `任务管理规则.md`：任务生成、插入、阻塞、自动续接、回顾和单轮边界规则。
- `任务模板.md`：每个新任务的标准记录结构。
- `运行依赖待办.md`：所有当前不实施的运行层依赖及其来源。

如果后续任务量明显增大，可以在本临时目录新增 `Agent-1任务/`、`Agent-2任务/` 等承载详细任务卡，但 `任务总表.md` 始终保持为唯一总队列和当前指针。

## 12. 删除/归档条件

只有当 Agent库 完成 L5 总回顾、所有框架阻塞任务清零、剩余事项全部属于明确的运行依赖时，本目录才允许归档或删除。

正式 Agent 架构不能依赖本临时目录才能成立。
