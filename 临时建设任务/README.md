# 临时建设任务

> 本目录是仓库建设期间使用的临时施工管理区，**不属于“亚马逊智能体架构”的正式组成部分**。

## 目的
用于管理接下来对 `Agent库/` 的持续完善工作：
- 按顺序记录待执行建设任务；
- 标记当前正在执行的任务；
- 在执行中发现新问题时动态拆分子任务；
- 确保当前任务及其全部子任务完成后，再进入下一主任务；
- 防止建设过程中被系统运行、API接入、数据库实现等工作带偏。

## 核心执行方式
```text
任务1
↓
任务2
├─ 任务2-1
├─ 任务2-2
├─ ...
└─ 任务2-N
↓
任务2全部完成
↓
任务3
↓
任务4
↓
...
```

如果执行 `任务2` 时发现多个必须解决的问题，则自动新增：
- `任务2-1`
- `任务2-2`
- `任务2-3`
- ...
- `任务2-N`

这些子任务属于 `任务2` 的阻塞项。只有所有阻塞子任务完成，任务2才允许标记完成。

## 主任务状态
统一使用：
- `待执行`
- `执行中`
- `被子任务阻塞`
- `待复核`
- `已完成`
- `暂缓`
- `取消`

## “完善”的正式边界
一个任务只有在其范围内达到以下标准后，才可视为“框架完善”：
1. 目录结构合理且无明显缺项；
2. README定位、职责、边界清楚；
3. 规则、流程、接口和对象关系定义完整；
4. 需要结构化的数据对象有Schema或字段规范；
5. 与上游/下游模块关系已明确；
6. 与其他Agent/共享层边界不冲突；
7. 异常、缺失信息、审批、冲突等非正常路径已考虑；
8. 有必要的示例、验收标准或静态测试；
9. 已完成跨模块一致性检查；
10. 不存在已知且会阻断后续框架建设的重大问题。

## 明确不进入的范围
当前任务区**不推进真实运行层实现**。包括但不限于：
- 不编写 Skill Runner / Agent Runner；
- 不接入 Amazon SP-API / Ads API；
- 不实现真实数据库；
- 不实现调度器、定时器、任务执行器；
- 不真实调用广告、价格、库存等修改API；
- 不实现生产环境权限系统；
- 不搭建部署、服务、服务器和监控运行环境；
- 不因为某模块未来需要运行能力，就转去建设整个基础设施层。

允许做的是：
- 定义未来需要哪些工具/API/数据；
- 定义接口、Schema、权限边界和依赖关系；
- 定义执行要求、运行要求和验收要求；
- 保留未来实现位置和接口占位。

## 越界处理原则
如果当前建设中发现一个问题必须依赖真实运行才能最终验证：
1. 先把框架层能定义的内容补完整；
2. 将真实运行需求记录为 `运行依赖待办`；
3. 不进入运行层实现；
4. 当前模块在“框架层完成”条件满足后仍可继续推进。

## 文件说明
- `任务总表.md`：所有主任务、子任务和当前执行顺序；
- `任务管理规则.md`：任务插入、编号、阻塞、完成和复核规则；
- `任务模板.md`：新任务标准模板；
- `运行依赖待办.md`：框架完善过程中发现但当前明确不执行的运行层事项。

## 删除条件
当 `Agent库/` 当前阶段全部建设完成并完成总体验收后，本目录可以归档或删除；正式架构不依赖本目录才能成立。
