# 临时建设任务

> 本目录是仓库建设期间使用的临时施工管理区，**不属于“亚马逊智能体架构”的正式组成部分**。

## 目的
用于持续推进 `Agent库/` 框架完善：
- 按正式Agent/文件夹路径建立任务；
- 明确每个问题最终应该修改到哪个正式目录；
- 在执行中发现新问题时动态追加同路径任务或跨模块阻塞任务；
- 当前任务及阻塞任务完成后再继续后续队列；
- 防止建设被系统运行、API、数据库和执行器实现带偏。

## 正式任务命名

不再使用抽象的 `任务1 / 任务2 / 任务2-1`。

统一使用：

`Agent编号-正式文件夹路径-序号`

例如：

```text
Agent-1-决策模板库-广告决策模板-1
Agent-1-决策模板库-广告决策模板-2
Agent-1-决策模板库-广告决策模板-3
...
Agent-1-决策模板库-广告决策模板-N
```

一级模块没有子目录时：

```text
Agent-1-事件处理-1
Agent-1-事件处理-2
```

已经存在深层目录时保留目录语义：

```text
Agent-1-技能模块-S01_事件校验-总验收-1
Agent-1-技能模块-统一接口-总验收-1
```

任务名回答一个问题：**这件事最终应该改到正式架构的哪里？**

## 新问题插入方式

如果正在执行：

`Agent-1-决策模板库-广告决策模板-2`

又发现一个仍属于广告模板的问题，则追加：

`Agent-1-决策模板库-广告决策模板-3`

如果发现真正问题属于决策规则，则创建：

`Agent-1-决策规则-N`

并把它登记为当前任务的阻塞项。修完后返回原任务。

因此，父子/阻塞关系不再靠 `2-1、2-2` 表示，而是靠正式归属路径和任务关系管理。

## “完善”的正式边界
一个任务只有在其范围内达到以下标准后，才视为框架完成：
1. 目录结构合理且无明显缺项；
2. README定位、职责、边界清楚；
3. 规则、流程、接口和对象关系完整；
4. 需要结构化的数据对象有Schema或字段规范；
5. 与上下游模块关系明确；
6. 与其他Agent/共享层边界不冲突；
7. 异常、缺失信息、审批、冲突等非正常路径已考虑；
8. 有必要的示例、验收标准或静态测试；
9. 完成跨模块一致性检查；
10. 不存在会阻断后续框架建设的已知重大问题。

## 明确不进入的范围
当前任务区**不推进真实运行层实现**，包括：
- 不编写 Skill Runner / Agent Runner；
- 不接 Amazon SP-API / Ads API；
- 不实现真实数据库；
- 不实现调度器、定时器、任务执行器；
- 不真实修改广告、价格、库存、Listing；
- 不建设生产权限系统、服务器、部署和运行监控。

允许完成：
- 定义未来需要哪些工具/API/数据；
- 定义接口、Schema、权限边界和依赖；
- 定义执行要求、运行要求和验收要求；
- 把真实实现记录到 `运行依赖待办.md`。

## 文件说明
- `任务总表.md`：按照Agent和正式目录展开的任务地图与执行顺序；
- `任务管理规则.md`：路径式命名、插入、阻塞、完成和复核规则；
- `任务模板.md`：新增任务标准模板；
- `运行依赖待办.md`：当前明确不执行的运行层事项。
