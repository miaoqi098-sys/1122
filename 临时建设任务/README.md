# 临时建设任务

> 本目录是 `Agent库/` 框架建设期间使用的临时施工控制区，**不属于“亚马逊智能体架构”的正式组成部分**。

它不是简单的待办清单，而是 Agent库 无人值守建设的 **施工队列 + 任务生成器 + 阻塞管理器 + 施工日志 + 分层验收门禁 + 运行依赖账本**。

---

## 1. 核心目的

本目录用于保证 Agent库 可以长期持续推进，而不会因为用户不在线、临时发现问题、局部阻塞或运行层依赖而失去建设顺序。

必须实现：

1. **持续施工**：自动运行被唤醒后，在本次可用时间和工具预算内连续处理尽可能多的可执行任务，而不是只推进一项。
2. **每小时汇报**：每小时是进度汇报/续跑窗口，不是“每小时只完成一个任务”。
3. **分析后生成任务**：进入任何模块/子模块/任务前先读取真实仓库，再生成、拆分、合并、取消或调整任务。
4. **真实写回**：完成任务必须真实修改 `Agent库/` 正式框架，禁止只修改临时任务表后宣称完成。
5. **阻塞绕行**：卡住的任务进入 `阻塞任务池.md`，保留并持续汇报；不依赖它的任务继续施工。
6. **逐层回顾**：L1任务、L2子模块、L3模块、L4 Agent、L5 Agent库逐层验收。
7. **循环熔断**：任务指纹去重、失败次数限制、循环依赖识别、跨模块回跳限制，防止无限循环。
8. **变更规模保护**：高影响、不可逆或会推翻基础架构的修改不得无人值守直接执行。
9. **断点续跑**：因单次运行预算结束时保存当前指针，下次自动运行继续，不视为施工停止。

---

## 2. 正式任务命名

统一使用：

`Agent编号-正式文件夹路径-任务主题-序号`

例如：

```text
Agent-1-决策模板库-广告决策模板-结构分析-1
Agent-1-决策模板库-广告决策模板-字段规范-1
Agent-1-决策模板库-广告决策模板-示例与验收-1
```

如果当前只是施工子域、尚未确认需要正式建文件夹，也可以先使用该名称作为任务前缀；只有分析确认正式架构需要时，才创建正式文件夹。

任务名必须回答：**这件事属于哪个 Agent、哪个模块、哪个子模块、要解决什么。**

---

## 3. 任务指纹

每个新任务除名称外，还应生成稳定指纹：

`Agent + 正式路径 + 问题类型 + 目标对象`

示例：

`Agent-1|决策模板库/广告决策模板|字段冲突|FinalDecision引用`

生成新任务前必须检查是否已有相同/等价指纹：
- 已有未完成任务 → 更新原任务，不重复创建；
- 已有阻塞任务 → 追加新证据，不新建同义任务；
- 已完成任务但出现新证据 → 创建“复开/修订”任务并引用原任务；
- 无等价任务 → 才创建新任务。

---

## 4. 分析 → 生成 → 执行 → 回顾

每进入一个施工单元必须执行：

```text
读取正式目录
↓
分析现有文件与上下游关系
↓
判断缺失 / 冲突 / 重复 / 越界
↓
生成任务指纹并去重
↓
确认新增 / 拆分 / 合并 / 取消 / 重排任务
↓
同步任务总表
↓
执行真实框架修改
↓
L1回顾
↓
通过门禁后继续下一可执行任务
```

如果分析发现需要新正式文件夹，先登记“目录必要性/职责定义”任务，确认后再创建。禁止先大量建空目录。

---

## 5. 持续自动施工与绕行

自动运行时：

```text
取当前可执行任务
→ 分析
→ 更新任务队列
→ 执行真实修改
→ 回顾与门禁
→ 完成则取下一可执行任务
→ 遇阻塞则写入阻塞池并绕行
→ 持续到本次运行预算结束或没有可执行任务
```

局部阻塞不能停止整个 Agent库。只有所有剩余任务都不可绕行时，当前施工才真正进入等待状态。

每小时汇报必须累计所有未解除阻塞项，直到它们被解决、取消或明确废弃。

---

## 6. 分层回顾

### L1｜任务回顾
检查目标、真实修改、遗漏、冲突、运行依赖、新任务、Git写入证据。

### L2｜子模块回顾
检查子目录/施工子域内部结构、接口、字段、示例、测试、边界。

### L3｜模块回顾
重新读取整个一级模块，与上下游和已封板模块做一致性复核。

### L4｜Agent回顾
检查整个 Agent 从身份、输入、分析、能力到输出、协作、工具数据、测试是否闭环。

### L5｜Agent库回顾
检查 Agent-1 至 Agent-13 的公共对象、职责覆盖、重叠、空白与协作协议。

具体门禁见 `验收门禁规则.md`。

---

## 7. 真实施工证据

任务完成至少需要：
- 正式 `Agent库/` 路径发生真实修改，或有明确证据证明无需修改；
- 修改内容与任务目标对应；
- 有 Git commit SHA / 仓库写入记录；
- L1回顾通过；
- `任务总表.md` 已同步；
- `施工进度日志.md` 已记录。

禁止“只更新临时任务区就算完成”。

---

## 8. 无限循环保护

无人值守施工必须遵守：
- 同一任务一次运行最多重新分析2次；
- 同一路径连续失败2次后进入阻塞池；
- 无新证据不得重复重试阻塞任务；
- 相同任务指纹禁止重复创建；
- 循环依赖必须熔断一项后绕行；
- 同一运行中跨模块回跳最多1次；
- 不得通过换任务名称制造等价任务无限增长；
- 回顾发现问题必须先去重再生成任务。

---

## 9. 变更规模保护

可以无人值守执行：
- 新增必要文件；
- 补充 README、规则、Schema、模板、案例、示例、测试；
- 修复明确字段/引用冲突；
- 新建必要且可逆的子目录；
- 对旧规则做有迁移说明的修订。

默认阻塞、等待用户确认：
- 删除正式一级模块或批量文件；
- 大规模批量重命名；
- 推翻已封板核心Schema/对象链；
- 一次改写多个已封板模块的核心职责；
- 改变 Agent-1 唯一决策出口等基础原则；
- 可能导致大量引用失效的迁移。

---

## 10. 当前建设边界

允许：目录、README、规则、流程、Schema、字段、接口、对象关系、模板、案例、知识、状态、指标、异常路径、审批边界、示例、静态测试、验收标准、工具/API/数据库需求定义。

不进入：真实 Agent Runner / Skill Runner、Amazon SP-API / Ads API 接入、数据库部署、Scheduler / Executor、生产权限、服务器、部署、真实经营动作。

这些统一记入 `运行依赖待办.md`。

---

## 11. 本目录文件职责

- `README.md`：无人值守施工总原则。
- `任务总表.md`：唯一任务队列、状态、指针和动态插入记录。
- `任务管理规则.md`：生成、去重、阻塞、绕行、续跑、熔断规则。
- `任务模板.md`：新任务标准记录结构。
- `阻塞任务池.md`：所有未解决阻塞任务、恢复条件与绕行关系。
- `施工进度日志.md`：每次自动施工批次的真实进度、commit与断点记录。
- `验收门禁规则.md`：L1-L5完成门禁和高影响变更保护。
- `运行依赖待办.md`：当前明确不实施的运行层依赖。

## 13. 归档条件

只有 Agent库 完成 L5 总回顾、所有框架阻塞项清零或明确处置、剩余待办全部属于运行依赖/未来扩展时，本目录才允许归档或删除。正式架构不得依赖此临时目录才能成立。
