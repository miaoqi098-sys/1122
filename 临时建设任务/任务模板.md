# 建设任务模板

## 任务编号
`任务X` 或 `任务X-Y`

## 任务名称
填写需要完善的正式模块/Agent名称。

## 所属范围
- Agent：
- 正式路径：
- 上游模块：
- 下游模块：

## 当前状态
`待执行 / 执行中 / 被子任务阻塞 / 待复核 / 已完成 / 暂缓 / 取消`

## 建设目标
说明本任务完成后，这一模块在框架层应该达到什么状态。

## 排查内容
- 目录与文件是否完整；
- README定位和边界；
- 规则与流程；
- 输入输出/Schema；
- 与其他模块的关系；
- 异常与非正常路径；
- 示例与测试；
- 旧内容冲突；
- 重复职责；
- 缺失但必须补的内容。

## 已发现问题
执行过程中持续追加。

## 子任务
无问题时写：`暂无`。

发现必须解决的问题时追加：
- `任务X-1｜问题名称｜状态`
- `任务X-2｜问题名称｜状态`
- ...

## 运行依赖
如果发现需要真实运行/API/数据库/执行器才能完成的内容，只记录依赖：
- 依赖名称：
- 未来归属层：
- 当前框架层需要定义到什么程度：
- 是否阻塞本任务框架完成：否/是（原则上仅真正影响接口定义时才是）

## 完成检查
- [ ] 内容逐项排查完成
- [ ] 结构缺口补齐
- [ ] 规则无重大冲突
- [ ] 接口与字段统一
- [ ] 跨模块边界清楚
- [ ] 所有阻塞子任务完成
- [ ] 示例/验收达到框架要求
- [ ] 运行依赖已单独挂账
- [ ] 最终静态复核完成

## 完成结论
记录：
- 完成状态；
- 剩余非阻塞问题；
- 运行层待办；
- 下一主任务编号。
