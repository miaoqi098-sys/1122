# 临时建设任务管理规则

## 1. 总执行原则

每个施工单元必须遵循同一闭环：

```text
定位当前任务
→ 读取正式目录
→ 分析
→ 生成/调整任务
→ 同步任务总表
→ 执行一个最小任务
→ 回顾该任务
→ 必要时生成新任务
→ 判断当前层级是否完成
→ 层级回顾
→ 推导下一任务
→ 停止并等待下一轮问答
```

不得跳过“分析”和“回顾”。

---

## 2. 任务命名

正式格式：

`Agent编号-正式文件夹路径-任务主题-序号`

示例：

```text
Agent-1-决策模板库-广告决策模板-结构分析-1
Agent-1-决策模板库-广告决策模板-统一字段-1
Agent-1-决策模板库-广告决策模板-示例与验收-1
```

序号在完整前缀下递增，不回收、不复用。

任务名用于说明正式归属；尚未确认要建立的子目录可以作为“施工子域”出现在任务名中，但只有分析确认后才写入正式架构。

---

## 3. 计划任务与确认任务

任务分两类：

### 计划任务
根据当前架构预先推测未来可能需要完成的任务，状态默认 `⬜ 待分析`。

### 确认任务
进入该模块并完成现状分析后，确认确实需要执行的任务，状态进入 `⬜ 待执行`。

计划任务允许在分析后：
- 拆分；
- 合并；
- 重命名；
- 调整顺序；
- 取消；
- 增加新任务。

因此 `任务总表.md` 是动态施工队列，不是一次写死的项目计划。

---

## 4. 开始任何模块前必须先分析

首次进入模块/子模块时，不得直接修改。

必须检查：
1. 当前目录和文件；
2. README定位；
3. 已有规则、Schema、模板、示例、测试；
4. 与上游/下游模块的连接；
5. 与其他 Agent 的职责边界；
6. 旧内容冲突；
7. 缺失结构；
8. 是否需要新增文件或文件夹；
9. 哪些属于框架，哪些属于运行依赖；
10. 应拆成哪些最小可验收任务。

分析结果先同步任务总表，再进入执行。

---

## 5. 执行每个子任务前再次分析

即使任务已经在总表中，执行前仍要做任务级分析：
- 这个任务现在是否仍然需要；
- 是否需要先完成其他任务；
- 是否发现新的结构缺口；
- 是否需要新文件/新文件夹；
- 是否会修改已封板模块；
- 是否越界进入运行层。

发现新任务时：**先登记，后执行。**

---

## 6. 新任务生成规则

### A. 同一正式归属
继续使用当前路径前缀，新增任务主题/序号。

### B. 实际属于其他模块
回到真实正式路径命名，并登记：
- 来源任务；
- 是否阻塞；
- 修复后返回任务。

### C. 需要新正式文件夹
先创建“目录必要性/职责定义”任务；只有该任务确认需要，才创建正式文件夹。

### D. 属于真实运行
写入 `运行依赖待办.md`，默认不阻塞框架完成。

### E. 新想法但非当前必要
进入相应模块的后续候选任务，不打断当前主线。

---

## 7. 阻塞与返回

任务可以临时跳到阻塞项，但必须保留返回指针。

```text
当前任务 A
↓
发现阻塞任务 B
↓
A = 🟨 被阻塞
B = 当前执行
↓
B 完成并回顾
↓
返回 A
↓
重新检查 A 是否已解除阻塞
```

不能因为跳去修 B，就忘记原任务 A。

---

## 8. 自动续接算法

任务完成后必须按以下顺序确定下一任务：

1. 当前任务产生的未完成阻塞项；
2. 当前子模块内已确认的下一任务；
3. 当前子模块回顾任务；
4. 当前模块内下一子模块/任务；
5. 当前模块总回顾；
6. 当前 Agent 下一模块；
7. 当前 Agent 总回顾；
8. 下一 Agent 的启动分析；
9. Agent库整体回顾。

如果下一层尚无详细任务，不要求用户重新规划；系统应创建一个“启动分析任务”，例如：

`Agent-2-总体框架-启动分析-1`

由这个任务读取 Agent-2 当前目录，再生成 Agent-2 的详细施工队列。

**自动续接只负责自动生成/指向下一任务，不代表同一轮对话继续执行。**

---

## 9. 单轮执行限制

默认一轮只执行一个最小可验收任务。

每轮最多完成：

```text
分析当前任务
+ 必要的任务登记
+ 当前任务的实际修改
+ 当前任务回顾
+ 若恰好结束一个子模块/模块，则追加对应层级回顾
+ 指出下一任务
```

不得默认在同一轮继续执行下一独立任务。

尤其禁止：
- 一次完成 S01-S10；
- 一次完成一个 Agent 的所有模块；
- 一次完成多个相互独立的决策模板域；
- 因为“下一任务很明确”就不经用户下一轮确认继续施工。

用户明确要求连续处理多个任务时除外，但仍必须逐任务分析和逐任务回顾。

---

## 10. 分层回顾

### L1 任务回顾
检查本任务目标、修改、遗漏、新问题、运行依赖和完成条件。

### L2 子模块回顾
检查该子模块所有任务之间是否完整、重复、冲突，文件结构是否合理。

### L3 模块回顾
重新读取整个一级模块，检查与上下游、统一对象和已封板模块的一致性。

### L4 Agent回顾
重新审视整个 Agent：身份→输入→分析→技能/能力→决策/输出→协作→工具数据→测试是否闭合。

### L5 Agent库回顾
检查 Agent-1 至 Agent-13：公共对象、事件协议、职责覆盖、重叠、空白、协作和整体框架。

回顾不是一句“已完成”，必须产生检查结论；发现问题立即生成任务并重新进入队列。

---

## 11. 状态机

```text
⬜ 待分析
→ 🔎 分析中
→ ⬜ 待执行
→ 🟦 执行中
→ 🟪 待回顾
→ ✅ 已完成
```

异常分支：
- `🟨 被阻塞`
- `⏸ 暂缓`
- `❌ 取消`

只有完成对应回顾后才允许 `✅ 已完成`。

---

## 12. 完成判定

一个任务完成至少满足：
1. 已做任务级分析；
2. 所需新任务已登记；
3. 正式架构修改已真实写回；
4. 已知阻塞项已解决；
5. 规则/接口无重大冲突；
6. 必需 Schema/字段/示例/测试达到该任务粒度要求；
7. 运行依赖已挂账；
8. 已做 L1 回顾；
9. 未越界进入运行实现。

子模块/模块/Agent 完成还必须通过对应 L2/L3/L4 回顾。

---

## 13. 正式架构与临时任务区的关系

临时任务区只管理施工过程。

真正成果必须写回：

`Agent库/运营组/对应Agent/...`

禁止出现：任务表写“已完成”，正式目录却没有相应内容。

反过来，正式目录发生新增/删除/重命名，也必须同步任务总表，避免施工地图与真实架构分叉。

---

## 14. 运行边界

当前只建设：

`设计正确 + 内容完整 + 接口清楚 + 静态可验收 + 可供未来运行层实现`

不建设：

`真实Runner + API连接 + 数据库 + Scheduler + Executor + 部署环境`

遇到运行依赖，记录到 `运行依赖待办.md` 后继续 Agent库 框架施工。

---

## 15. 当前推进顺序

```text
Agent-1 当前未完成模块
→ Agent-1 L4总回顾
→ Agent-2 启动分析并动态生成任务
→ Agent-2 L4总回顾
→ ...
→ Agent-13 L4总回顾
→ Agent库 L5总回顾
```

专业 Agent 不提前一次性生成全部细任务；到达对应 Agent 时先读取真实框架，再动态展开，避免现在凭空设计未来任务。

---

## 16. 每轮结束必须输出的施工结论

每轮结束必须明确：
- 本轮任务；
- 本轮完成了什么；
- L1回顾结果；
- 是否触发 L2/L3/L4/L5 回顾；
- 新增/取消/调整了哪些任务；
- 是否新增运行依赖；
- 当前任务状态；
- **下一唯一任务**。

然后停止，等待下一轮。
