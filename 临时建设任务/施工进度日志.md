# 施工进度日志

> 本文件记录无人值守施工的连续进度快照。目标是让任何时候打开仓库，都能知道上一阶段真实做了什么、改了哪里、卡在哪里、下一步是什么。

## 1. 每次自动运行必须追加的内容

每次自动施工唤醒结束前追加一条记录：

### [时间] 施工批次
- 批次起点任务：
- 批次结束任务：
- 本批次完成任务数：
- 本批次完成任务：
- 本批次真实修改路径：
- 新建文件/目录：
- 修改文件：
- 删除/废弃内容：
- 关键规则/Schema变化：
- 新增任务：
- 取消/合并/重排任务：
- 新增阻塞任务：
- 累计未解决阻塞：
- 新增运行依赖：
- L1/L2/L3/L4/L5 回顾：
- 相关 Git commit SHA：
- 当前施工指针：
- 下一批可执行任务：
- 本批次停止原因：预算结束 / 无可执行任务 / 全部阻塞 / 仓库异常 / 正常断点

## 2. 真实施工证据要求

任务只有同时具备下列证据，才允许在进度日志中计为“完成”：
- 对应正式 Agent库 路径实际发生修改，或经复核确认无需修改且有明确验收依据；
- 有修改文件/新建文件/Schema/规则/模板/示例/测试等具体内容；
- 有 Git commit SHA 或明确的仓库写入记录；
- 已完成该任务 L1 回顾；
- `任务总表.md` 状态已同步。

禁止以下情况计为完成：
- 只分析未写回；
- 只更新临时任务表；
- 只写“已完善”但没有正式文件变化；
- 仅生成未来运行层待办却没有完成当前框架内容。

## 3. 小时汇报与日志关系

每小时面向用户的汇报，应直接来源于本文件自上一批次以来的增量内容，包括：
- 真实完成内容；
- 具体修改路径；
- 累计阻塞项；
- 新生成任务；
- 当前模块/Agent进度；
- 下一批可执行任务。

即使某小时没有完成任务，也必须记录原因，例如：
- 全部候选任务被阻塞；
- 仓库异常；
- 工具预算不足；
- 本轮只完成分析并生成确认任务。

但禁止无原因空转。

## 4. 断点恢复

下一次自动施工启动时先读取最新一条施工记录：
- 如果存在未完成当前任务，恢复该任务；
- 如果当前任务已完成，按任务总表下一指针继续；
- 如果指针与任务总表冲突，以任务总表和正式仓库真实状态重新校验后修正；
- 禁止因为上次运行中断而重复创建相同任务。
