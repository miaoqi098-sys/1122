# 运行依赖待办

## 1. 定位

本文件只记录完善 `Agent库/` 框架时发现、但当前明确不实施的真实运行依赖。

它的作用是把“未来必须做”与“现在应该做”分开：

```text
Agent库框架问题
→ 留在任务总表并解决

真实运行问题
→ 记录到本文件
→ 当前不实施
→ 不打断Agent库施工主线
```

运行依赖默认不阻塞模块框架完成，除非连未来接口、输入输出或职责边界都无法定义。

---

## 2. 每条运行依赖必须记录

- 依赖编号；
- 名称；
- 首次来源任务；
- 后续引用任务；
- 未来归属层；
- 未来作用；
- 当前框架层已经定义到什么程度；
- 尚缺的真实实现；
- 是否阻塞当前框架；
- 状态。

状态：
`待未来建设 / 已被后续任务引用 / 已进入未来建设 / 已完成 / 已废弃`

---

## 3. 去重规则

执行新任务发现运行需求时，先检查本表：

### 已存在相同依赖
不得重复创建新编号，只把当前任务追加到“后续引用任务”。

### 属于现有依赖的子能力
优先追加到现有依赖的“尚缺实现”，除非未来确实需要独立建设和验收。

### 确实是新的独立运行能力
才创建新的 `Rxx`。

这样避免每完善一个 Agent 都重新生成一套“API/数据库/Runner”待办。

## 5. 新增流程

每次任务分析/执行发现运行依赖时：

```text
识别运行需求
↓
检查R01-Rxx是否已有
├─ 已有 → 追加来源/缺失能力
└─ 没有 → 创建新R编号
↓
在当前任务卡记录引用
↓
继续当前Agent库框架任务
```

新编号按 `R12、R13...` 递增，不回收。

---

## 6. 回顾时如何使用

L1/L2/L3/L4/L5 回顾时都要检查：
- 是否把运行问题错误留在正式Agent规则里；
- 是否有运行依赖未挂账；
- 是否重复创建相同运行依赖；
- 当前框架是否已经把未来接口定义到足够程度。

运行依赖存在不等于框架未完成。
