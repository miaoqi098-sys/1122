# 验收门禁规则

> 本文件规定任务、子模块、模块、Agent、Agent库在进入下一层级前必须通过的静态验收门禁，防止“任务都打勾了但框架仍然有洞”。

## 1. 总原则

任何层级完成都必须满足：

`有真实成果 + 有检查证据 + 无未处理阻塞性缺口 + 无已知重大冲突`

仅凭任务状态全部变成 ✅，不能自动宣布模块或 Agent 完成。

---

## 2. L1｜任务门禁

一个最小任务完成前必须检查：
- [ ] 已做开始前分析；
- [ ] 分析产生的新任务已先登记；
- [ ] 正式 Agent库 路径有真实写回，或明确证明该任务无需修改；
- [ ] 修改内容与任务目标一致；
- [ ] 未把运行层实现混入当前框架；
- [ ] 相关阻塞项已解决或已登记并允许绕行；
- [ ] 无等价重复任务；
- [ ] 有 Git commit/写入证据；
- [ ] 已完成 L1 回顾。

任何一项不满足，不得标记 ✅。

---

## 3. L2｜子模块门禁

一个子文件夹/施工子域结束前必须检查：
- [ ] 子模块目录结构合理；
- [ ] README/定位/职责边界清楚；
- [ ] 规则、字段、Schema、模板之间没有内部冲突；
- [ ] 旧内容/过时字段已清理或明确废弃；
- [ ] 输入输出与上下游对象一致；
- [ ] 异常路径和缺失信息路径已考虑；
- [ ] 必要示例/静态测试存在；
- [ ] 所有阻塞任务已解决，或剩余阻塞明确不影响该子模块框架成立；
- [ ] 未发现未登记的新问题。

未通过则自动生成补充任务，不能进入下一个子模块。

---

## 4. L3｜一级模块门禁

一个一级模块完成前必须重新读取整个模块并检查：
- [ ] 模块定位与 Agent 总职责一致；
- [ ] 目录结构完整；
- [ ] README 与实际文件一致；
- [ ] 核心对象/Schema/字段统一；
- [ ] 与技能模块、决策规则、知识库、指标库等无重复职责；
- [ ] 与上游/下游模块连接完整；
- [ ] 已知旧版本冲突已清理；
- [ ] 示例、测试、验收足够支撑框架判断；
- [ ] 运行依赖已挂账；
- [ ] 模块所有任务均有真实施工证据；
- [ ] 无未解决的模块级阻塞。

未通过必须生成该模块的新任务并继续施工。

---

## 5. L4｜Agent门禁

一个 Agent 封板前必须检查完整链路：

`身份/职责 → 输入 → 状态/知识/指标 → 分析/Skill → 决策/输出 → 协作 → 工具数据 → 任务/记忆 → 示例测试`

门禁包括：
- [ ] Agent 身份、职责、权限和边界明确；
- [ ] 输入事件/Scope/来源统一；
- [ ] 专业状态、指标、知识需求完整；
- [ ] 分析流程和能力/Skill结构完整；
- [ ] 输出对象能被下游消费；
- [ ] 与 Agent-1 或其他 Agent 的协议一致；
- [ ] 没有重大职责重叠或空白；
- [ ] 工具与数据需求定义完整；
- [ ] 异常、审批、信息不足、冲突路径存在；
- [ ] 示例/测试覆盖主要场景；
- [ ] 所有一级模块通过 L3；
- [ ] Agent级阻塞清零或明确不影响框架成立。

---

## 6. L5｜Agent库门禁

Agent-1 至 Agent-13 全部完成后必须检查：
- [ ] 公共 Event/Scope/证据/时间/置信度语义一致；
- [ ] Agent-2至13输出能被Agent-1统一消费；
- [ ] 无两个Agent长期重复负责同一最终决策；
- [ ] 无重要经营问题无人负责；
- [ ] 跨Agent协作场景能闭合；
- [ ] 冲突处理和升级路径一致；
- [ ] 工具/数据/运行依赖无明显重复或遗漏；
- [ ] 所有Agent均通过L4；
- [ ] 所有框架阻塞项已处理；
- [ ] 剩余待办仅为明确的运行依赖或经确认的未来扩展。

---

## 7. 变更规模保护

无人值守施工允许自动执行：
- 新建必要文件；
- 补README/规则/Schema/模板/示例/测试；
- 修复字段、引用和明确冲突；
- 新增必要且可逆的子目录；
- 废弃旧规则时保留清楚迁移说明。

以下属于高影响变更，默认不得无人值守直接执行：
- 删除正式一级模块或大批文件；
- 批量重命名核心目录；
- 推翻已封板统一Schema/核心对象链；
- 一次修改多个已封板模块的核心职责；
- 改变 Agent-1 唯一决策出口等基础架构原则；
- 大规模迁移导致大量引用失效。

遇到高影响变更：
1. 生成阻塞任务；
2. 写入 `阻塞任务池.md`；
3. 记录建议方案、影响范围和恢复条件；
4. 绕行其他不依赖任务。

---

## 8. 假完成检测

出现以下任一情况必须退回：
- 任务表完成但正式目录无变化；
- README声称已有对象/文件，但仓库实际不存在；
- Schema字段与示例字段不一致；
- 模块引用一个不存在或已废弃的对象；
- 总验收只总结、不重新读取正式内容；
- 通过把问题丢进运行依赖来规避本应完成的框架定义。

---

## 9. 回顾发现问题后的动作

所有门禁回顾采用同一规则：

```text
发现问题
→ 判断真实归属
→ 生成任务指纹
→ 检查是否已有等价任务
├─ 已有 → 更新原任务
└─ 没有 → 新建任务
→ 同步任务总表
→ 若阻塞则进入阻塞池
→ 未通过门禁，保持当前层级未完成
```
