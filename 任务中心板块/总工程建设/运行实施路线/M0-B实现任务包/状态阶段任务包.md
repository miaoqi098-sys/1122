# 状态与阶段实现任务包 V1

> 覆盖：R-GP-008、R-GP-009、R-GP-010

## 1. BusinessState Engine
输入：MetricSnapshot、Event、ValidationResult、规则版本。
输出：BusinessState。
要求：
- 规则版本化；
- overall_status 与维度状态可解释；
- 保留 evidence_refs；
- 缺关键事实时输出 unknown/not_evaluated，而不是模型猜测；
- 同一输入+同一规则版本结果应确定性一致。

## 2. ProductStage Dictionary
业务侧维护：stage_code、名称、定义、进入条件、退出条件、最短观察窗口、规则版本、生效期。
阶段枚举未正式确认前，运行系统不得自行创建永久阶段语义。

## 3. ProductStage Evaluator
输入：BusinessState、阶段字典、历史阶段、观察窗口。
输出：ProductStage + transition evidence。

人工覆盖必须记录：actor_id、reason、effective_until、previous_stage、override_ref，并形成 AgentActivity/Memory。

## 4. 失败路径
- 状态数据不足 → unknown
- 阶段规则无匹配 → not_evaluated
- 多规则同时命中 → conflict/requires_review
- 人工覆盖过期 → 回到规则重新判定

## 5. 验收条件
- 状态与阶段不混为一个字段；
- 阶段变化可回放；
- 规则变化不改写旧历史解释；
- 人工覆盖可审计；
- Aggregator能读取最新状态/阶段和 freshness。

## 6. 静态L1
运行职责、输入输出、冲突和人工覆盖边界已明确。未实现 Engine。L1：PASS。
