# 第一批真实实现工程包 V1

> 对应任务：START-02
> 目标：把未来第一个真实实施批次固定在最小只读闭环，避免一开始同时建设全部Agent、Executor和全部业务模块。

## 1. 批次目标

在一个授权产品上实现：

```text
外部真实只读数据
→ ProductIdentity
→ MetricSnapshot
→ BusinessState / Event
→ ProductStatusCardView
→ HomeCommandCenterView
→ 只读UI接口
```

目标成熟度：先到 `READ_MODEL_VERIFIED`，再到 `LIVE_DATA_VERIFIED`。

## 2. 工程包顺序

### P1｜基础工程骨架
- 数据系统实现目录/服务骨架；
- 对外连接实现目录/服务骨架；
- 测试与验收骨架；
- 配置、日志、Secret引用接口；
- CI与基础测试。

### P2｜身份
- ProductIdentity Store；
- IdentityResolution；
- ExternalIdentifier Mapping。

### P3｜Amazon只读连接
- SP-API read capability；
- Ads API read capability；
- auth/refresh/rate-limit/source trace；
- 无write capability。

### P4｜事实层
- Raw intake；
- MetricSnapshot Store；
- time/freshness；
- metric registry；
- profit estimation（允许partial/estimated）。

### P5｜最小状态事件链
- BusinessState最小规则；
- 一个可解释Signal Detector；
- Event Normalizer/Repository；
- ProductStage允许unknown，若业务字典尚未定稿不强行判断。

### P6｜读模型
- ProductStateAggregator runtime；
- HomeCommandCenterAggregator runtime；
- degraded/freshness。

### P7｜只读UI接口
- 首页读取；
- 产品卡读取；
- Event/Activity读取；
- 服务端scope权限。

### P8｜机器验收
- ProductIdentity映射证据；
- 数据source refs；
- exact deployment version；
- API/存储读取证据；
- read model evidence；
- LIVE_DATA_VERIFIED evidence。

## 3. 第一批明确不做
- Executor；
- Amazon Ads写操作；
- 自动审批；
- 全部Agent Runtime；
- 多产品扩容；
- 多站点；
- 高级预测算法；
- 全仓库目录迁移。

## 4. 第一批完成定义

第一批完成时，用户应该能够打开真实只读首页/产品卡，并确认：
- 这是正确的产品；
- 指标来自真实数据；
- 数据时间和新鲜度可信；
- 状态/Event有证据；
- 页面降级诚实；
- 系统没有任何未经授权的经营写能力。

## 5. L1结论

第一批真实实现范围已经压缩为“身份 + 数据 + 最小状态/Event + 读模型 + UI读取 + 验收”。L1：PASS。
