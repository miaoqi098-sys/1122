# 仓库可见性与敏感数据安全边界

## 目标

定义 1122 在 GitHub Repository（GitHub 仓库）、Cloudflare Runtime（运行环境）、Secret Manager（密钥管理）与业务数据层之间的安全边界。

本规则适用于全部 Agent、Skill、API Bridge、Task Center、GitHub Actions、前端 UI 与后续外部连接。

## 一、当前约束

1122 GitHub 主仓库已于 2026-09-01 切换为 Private Repository（私有仓）。

仓库私有化降低了源码和 Workflow 公开暴露风险，但不改变数据与密钥分离原则。任何 Secret 仍不得写入 Git，真实经营数据仍优先进入专用后端数据层。Web UI 尚未完成身份认证，因此经营明细仍不得通过未认证网页接口直接暴露。

## 二、数据分级

### PUBLIC（公开）
允许进入公开 GitHub / GitHub Pages：

- UI 结构
- 公共文档
- 非敏感架构说明
- API 是否在线
- 聚合产品数量
- 非敏感更新时间
- 不含内部映射的公共状态

### INTERNAL（内部）
不得进入公开仓：

- 内部任务
- Agent 决策细节
- 内部 SKU 经营标签
- 供应链计划
- 详细经营策略
- 内部审批状态

### CONFIDENTIAL（经营敏感）
只允许进入受控后端数据层：

- Seller SKU / FNSKU
- ASIN 与 SKU 内部映射
- 库存明细
- 广告经营数据
- 销售、费用、利润
- 订单相关数据
- 供应链成本
- 原始第三方经营响应

推荐存储：Cloudflare KV / D1 / R2 或后续专用数据库。

### SECRET（密钥）
只能进入 Secret Manager（密钥管理环境）：

- Password
- API Token
- Client Secret
- Refresh Token
- Access Key
- 私有签名密钥
- 内部执行令牌

推荐存储：Cloudflare Worker Secret / GitHub Actions Secret / 后续专用 Secret Manager。

## 三、强制规则

1. Secret 永不写入 Git tracked file（Git 跟踪文件）。
2. CONFIDENTIAL 数据永不写入 Public Repository。
3. Public UI 不得直接返回 CONFIDENTIAL 明细。
4. Browser（浏览器）不得长期保存 Amazon / Ads / Cloudflare 等长期密钥。
5. Origin Header（来源头）不能作为身份认证。
6. 隐藏 URL、按钮隐藏、路径随机化均不能作为权限控制。
7. 高影响写操作必须经过 Authentication（身份认证）+ Authorization（权限）+ Task Center Approval（任务审批）。
8. GitHub Actions 日志只输出必要验收摘要，不主动打印经营明细。
9. 即使未来仓库改为 Private，SECRET 与经营数据库仍必须与代码分离。

## 四、当前私有仓阶段的标准架构

```text
Private GitHub Repository
├── UI
├── Worker / Agent 工程逻辑
├── 文档
└── Workflow 定义
        │
        ↓ deploy
Cloudflare Runtime
├── Worker Secret       ← SECRET
├── KV / D1 / R2        ← CONFIDENTIAL
└── Workers
        │
        ↓ coarse response only
1122 Web UI（身份认证待建设）
└── 当前仍只展示低敏感度聚合状态
```

## 五、当前 Amazon ProductIdentity 实例

真实数据：

```text
Amazon SP-API
↓
Cloudflare Worker
↓
ProductIdentity 标准化
↓
Cloudflare KV
```

KV 可保存 Seller SKU、FNSKU、ASIN、产品名和库存等真实明细。

公开 UI 只允许显示：

- ProductIdentity 数量
- 更新时间
- Marketplace
- 数据源
- 非敏感连接状态

## 六、未来目标架构

长期推荐：

```text
Private Core Repository
├── Agent Runtime
├── Worker Backend
├── Task Center
├── Policy / Permission
└── CI/CD

Public Frontend Repository（可选）
└── 只保留公开 UI / 官网

Cloudflare
├── Access / Zero Trust
├── Workers
├── Secrets
├── KV / D1
└── R2
```

如果 1122 最终完全属于内部经营后台，可直接将全部核心源码迁移到 Private Repository，不必保留公开内部 UI 源码。

## 七、架构升级门槛

满足以下任意条件，应启动 Private Repository 或 Public/Private 分仓迁移：

- 接入 Orders / Finance；
- 接入真实 Ads API 数据；
- UI 开始展示完整产品经营明细；
- 接触客户个人信息；
- 开启价格、Listing、广告、库存等真实写操作；
- Task Center 获得真实执行权限；
- 系统进入多人内部使用。

其中“客户个人信息”“真实写操作”“Task Center 执行权限”属于强制门槛：完成身份认证与私有后端隔离前不得上线。

## 八、推荐迁移顺序

1. 继续保持 Secret / Data 与 Git 分离；
2. 建立 Cloudflare Access（身份控制）；
3. 将 Backend / Worker / Agent Runtime 迁移到 Private Repository；
4. 如需公开展示，再保留独立 Public Frontend；
5. 增加 GitHub Secret Scanning、Push Protection、Branch Protection；
6. 建立数据分级自动检查；
7. 再开启订单、财务和真实写操作。
