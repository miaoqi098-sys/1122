# 10 备份与恢复

## 目标

1122 的经营历史必须能够长期保留、验证和重建。

## 恢复优先级

```text
R2 原始档案
   ↓
D1 结构化历史
   ↓
KV 当前缓存
```

- KV 丢失：从 D1 重建；
- D1 逻辑表损坏：优先使用 D1 Time Travel / Backup，再从 R2 原始档案补重建；
- Parser（解析器）发现历史错误：读取 R2 原始文件，以新 parser_version 重算，不覆盖原始档案；
- R2 原始档案：原则上不做自动删除生命周期规则。

## 第一阶段备份策略

1. D1 使用 Cloudflare 原生迁移备份 / Time Travel 能力；
2. 后续增加定期 `D1 export → R2`；
3. R2 保持 Private；
4. 后续增加第二云或离线副本，避免单云平台成为唯一故障域；
5. 每次恢复演练记录到 `data_layer_audit`。

## 禁止

- 不允许把数据库导出提交到 Git；
- 不允许在 Actions 日志打印完整经营数据；
- 不允许为了降低存储成本自动删除关键历史；
- 不允许把 KV 当唯一真实来源。
