## 已实现

- `AccessTokenProvider` 可替换边界；
- `CachedLwaAccessTokenProvider`：基于 refresh token + client secret 的按需 LWA access-token 刷新；
- access token 仅以 `SecretStr` 驻留内存缓存，不写入 Git、普通日志、trace 或任务文件；
- refresh token / client secret 仅通过 `SecretRef + SecretProvider` resolve；
- 固定 LWA token endpoint allowlist：`https://api.amazon.com/auth/o2/token`；
- 基于 `expires_in` 与 refresh skew 的提前刷新；
- 并发刷新使用锁避免同进程重复刷新；
- OAuth 非 200、缺 access_token、缺/非法 expires_in、timeout 均 fail closed，并使用不包含 OAuth body/Secret 的 sanitized exception；
- `RefreshingAccessTokenSecretProvider` 将动态 token provider 适配到现有 Transport SecretProvider Contract；
- `ConnectorRateLimitError` 支持安全 `retry_after_seconds` 元数据；
- SP-API / Ads API 429 可解析数值型 `Retry-After`；
- `ExponentialRetryDelayPolicy` 支持 Retry-After 优先，否则 timeout/429 指数退避，并受 max-delay 上限保护；
- `AmazonReadConnector` 支持可替换 RetryDelayPolicy + Sleeper；
- 最终失败前仅在仍有下一次尝试时等待，不在最后一次失败后多睡眠；
- max attempts 仍固定受 `RetryPolicy` 1～5 次边界约束；
- 测试使用 fake LWA client / fake clock / fake sleeper / FakeTransport，不调用生产 Amazon 或 LWA。
