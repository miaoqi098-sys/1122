# 系统冲突问题库

## 定位
本目录与 `Agent库/` 保持根目录并列，用于集中记录在人工排查、自动任务、跨模块验收、跨Agent协作检查中发现的所有系统冲突问题。

本目录是**问题登记与闭环跟踪系统**，不是正式业务规则的权威来源。冲突最终仍应在其所属正式模块中修复；本目录负责记录问题从“发现 → 分析 → 修复 → 验证 → 关闭”的全过程。

## 核心规则
1. 发现冲突后先登记，不因暂时无法解决而丢失。
2. 每个冲突必须能追溯到实际文件或文件夹路径。
3. 冲突名称优先根据**问题所属正式文件夹路径**生成，而不是根据发现任务命名。
4. 一个冲突涉及多个模块时，以主要修复责任路径作为主名称，其余路径写入“关联路径”。
5. 不允许只写“有冲突”，必须说明冲突双方、影响、当前状态和验证方法。
6. 解决后不得删除记录，改为 `已解决`，并保留解决方法、修改文件、验证结果和日期。
7. 自动任务或人工排查以后发现的新冲突，统一进入本目录。
8. 历史自动化的“已完成/已验收”结论不能覆盖新的冲突事实；发现冲突后应重新登记并验证。

## 命名规范
标准格式：

`冲突-<问题路径层级>-<冲突主题>-<序号>.md`

例如：

`冲突-Agent-1-目标系统-目标层级-治理层级命名重叠-001.md`

`冲突-Agent-1-技能模块-S04_决策排序-DecisionItem-新增排序字段未进入Schema-001.md`

命名中的路径应尽量对应 `Agent库/` 内真实目录层级。若一个问题横跨多个目录，以主要修复责任目录作为主路径，并在文件内部记录所有关联路径。

## 状态枚举
- `待分析`：已发现，但尚未完成冲突定位。
- `已确认`：冲突成立，尚未开始修复。
- `处理中`：已确定修复方案并正在修改。
- `待验证`：已修改，等待跨模块/Schema/示例/测试验证。
- `已解决`：修改和验证均完成。
- `暂缓`：冲突成立，但因依赖、范围或阶段边界暂不处理。
- `非冲突`：复核后确认不是冲突，保留记录和判定依据。

## 单条冲突记录必须包含
- 冲突ID
- 冲突名称
- 当前状态
- 严重级别
- 发现来源
- 主要问题路径
- 关联路径
- 冲突描述
- 冲突双方/多方
- 影响范围
- 根因
- 解决方案
- 实际修改记录
- 验证方法
- 验证结果
- 解决日期
- 备注

## 严重级别
- `P0`：可能导致系统做出危险、越权或完全错误的核心决策。
- `P1`：会破坏核心对象、规则、Skill、Schema 或跨模块闭环一致性。
- `P2`：职责、命名、接口或流程存在明显错位，但短期仍可工作。
- `P3`：文档、引用、表达、示例等轻度一致性问题。

## 目录原则
当前先按实际冲突所属路径建立目录，不预建大量空目录。随着排查推进逐步形成：

```text
系统冲突问题库/
├── README.md
├── 冲突问题总表.md
└── Agent-1_运营总控智能体/
    └── ...按真实问题路径继续展开
```

未来 Agent-2～Agent-13、公共协议以及 Agent 间冲突均按相同规则进入本库。
