# 首页聚合与降级规则 V0

## 1. 六区数据来源固定
- 左侧导航：ModuleRegistry / Permission，独立加载；
- 今日经营概览：经营快照；
- 今日需要我处理：TaskCenter HumanTaskView；
- Agent今日动态：AgentActivity；
- 产品经营状态与今日操作：ProductStatusCardView；
- 重点异常与机会：Event 业务投影。

## 2. 聚合器不创造业务事实
HomeCommandCenterAggregator 只聚合已存在的结构化对象/读模型，不调用 Agent 临时“总结出”一个事实值，也不修改源对象状态。

## 3. 分区降级
每个区域单独记录 freshness/status。某一区域 error 时：
- 其余区域继续返回；
- view_status=degraded；
- missing_sections 标记受影响区域；
- UI 明确展示延迟/不可用，不使用旧值伪装最新。

只有核心身份/整体聚合无法建立时才 `unavailable`。

## 4. 更新时间
- generated_at：当前首页 View 生成时间；
- source_updated_at：本次聚合所引用源数据中的最新/基准更新时间；
- section_status：分别标注各区数据新鲜度。

## 5. 排序
- HumanTasks：按统一任务优先级、截止时间、阻塞影响排序；
- AgentActivities：importance 优先，再按 occurred_at；
- ProductStatusCards：未来由用户偏好/风险/经营优先级排序，V0不擅自固化；
- ImportantEvents：severity/importance + recency + business impact。

## 6. 点击追溯
首页所有重要条目必须保留真实对象 ID，使用户可以进入 Task/Event/Product/Activity 详情，而不是只看到不可追溯摘要。

## 7. 左侧导航边界
导航不由首页聚合器决定可见权限。ModuleRegistry/Permission 先判断后提供导航；聚合器不得越权暴露无权限业务数据。

## 8. 运行依赖
真实查询编排、缓存、刷新触发、API gateway、前端接口属于后续运行建设。
