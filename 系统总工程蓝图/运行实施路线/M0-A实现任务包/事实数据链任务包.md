# 事实数据链实现任务包 V1

> 覆盖：R-GP-004

## 1. 目标
把 Amazon/文件/成本来源的原始只读数据转换成可追溯、可修订、按 `product_id` 对齐的 `MetricSnapshot`。

## 2. 子任务

### DATA-01｜Raw Intake Contract
采集层必须保存：source、source_record/report_ref、collected_at、raw_window、seller/marketplace context。

### DATA-02｜Identity Binding
任何原始记录进入事实层前必须调用 IdentityResolution；ambiguous/unresolved 记录进入隔离队列，不得错误挂到产品。

### DATA-03｜Standardization
统一：
- 指标编码；
- 数值类型与单位；
- 币种；
- marketplace/business_date；
- window_start/end；
- effective_at。

### DATA-04｜MetricSnapshot Persistence
必须支持 append/revision，而不是覆盖历史。
建议每次修订保留：snapshot_id、revision、supersedes_snapshot_id、reason。

### DATA-05｜Data Quality
至少支持：complete、partial、suspect、invalid、unknown。
invalid 不进入正常聚合；partial/suspect 可降级显示但必须标记。

### DATA-06｜Lineage Query
未来必须能从首页指标反查：MetricSnapshot → standardized record → source report/API reference。

## 3. 幂等键建议

至少由以下语义组成：
`product_id + metric_code + business_date + window + source + source_record_ref`

实际存储键可不同，但不得因重复拉取产生重复事实。

## 4. 失败路径
- identity unresolved → quarantine
- 数据源延迟 → lagged
- 单位/币种无法标准化 → invalid
- 同源同窗口冲突 → suspect + revision review
- source缺失 → reject

## 5. 验收条件
- 重复采集不产生重复事实；
- 修订不覆盖旧版本；
- 每条快照都有数据血缘；
- product_id 必填；
- freshness/quality 可查询；
- Aggregator不需要读取Raw数据即可工作。

## 6. 静态L1
事实数据链的输入、身份绑定、标准化、持久化、血缘和失败路径已明确。未实施真实采集。L1：PASS。
