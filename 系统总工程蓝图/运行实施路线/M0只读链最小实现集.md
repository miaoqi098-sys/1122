# M0 只读链最小实现集 V1

> 对应任务：RI-02
> 目标：先证明系统能用真实、可追溯数据正确看懂一个产品，而不触发任何经营写动作。

## 1. M0范围

M0只允许：
- 建立/解析产品身份；
- 获取真实只读数据；
- 生成 MetricSnapshot；
- 生成 BusinessState / ProductStage；
- 生成或读取 Goal；
- 生成/规范化 Event；
- 生成 AgentActivity / Memory / StageSummary；
- 生成 ProductStatusCardView；
- 生成 HomeCommandCenterView；
- 通过受权限控制的只读接口展示。

M0禁止：
- 广告、价格、库存、Listing 等真实写操作；
- 自动审批；
- Executor 生产写权限；
- 用模拟数据声明 LIVE_DATA_VERIFIED。

## 2. 最小支持范围

第一版只要求：
- 1 个 seller account；
- 1 个 marketplace；
- 1 个明确授权的 product_id；
- 1 个币种；
- 业务日和时区统一；
- 销售事实；
- 广告花费事实；
- 利润可以先是标记完整度的估算值；
- 至少 1 类可解释 Event（推荐广告异常）；
- 首页和产品卡均可读取。

## 4. 最小数据链

```text
Amazon真实只读数据 / 授权文件
      ↓
IdentityResolution
      ↓
product_id
      ↓
MetricSnapshot
      ↓
BusinessState
      ↓
ProductStage + Goal + Event
      ↓
AgentActivity / Memory
      ↓
ProductStatusCardView
      ↓
HomeCommandCenterView
      ↓
只读UI
```

## 5. 必须保留的证据

每个真实指标至少保留：
- product_id；
- source；
- source_record/report reference；
- collected_at；
- effective_at；
- business_date；
- freshness_status；
- quality_status；
- calculation/version reference（如计算指标）。

每个 Event 至少能追溯至数据/证据引用。

## 6. 降级策略

- Ads 数据延迟：显示 lagged，不伪装 fresh。
- 成本数据缺失：利润显示 estimated/partial 并列缺失项。
- ProductStage 尚无正式规则：显示 unknown / not_evaluated，不由模型自由编造阶段。
- Goal 缺失：首页允许无主目标，但不得自动生成伪事实。
- Event Detector 不可用：其他只读区继续展示，异常机会区标 degraded。

## 7. M0验收门禁

必须全部满足：
1. product_id 与真实外部产品能唯一映射；
2. 至少一个 MetricSnapshot 来自真实授权数据；
3. 数据来源、时间、新鲜度可追溯；
4. ProductStatusCardView 可由真实对象聚合；
5. HomeCommandCenterView 可读取该产品状态；
6. UI读取链没有任何经营写权限；
7. 数据缺失时有明确降级；
8. 不依赖手工改 JSON 才能维持链路；
9. 有机器可验证的接口/存储证据后才可声明 READ_MODEL_VERIFIED；
10. 真实外部数据已授权读取并证明来源后才可声明 LIVE_DATA_VERIFIED。

## 8. 完成定义

M0完成不代表 Agent 自主运营完成。它只证明：

> 系统可以用真实数据、正确身份、统一对象和可追溯证据，稳定回答“这个产品现在怎么样”。

L1：PASS。
