# 实现启动门禁与工程落地清单 V1

> 对应任务：START-01
> 目的：明确何时可以从“静态总工程蓝图”切换到真实代码、数据库、Connector、Runtime 与受控执行建设。

## 1. 启动原则

真实实现启动不是“开始写更多文件”，而是开始承担：
- 数据持久化；
- 外部认证与连接；
- 运行服务；
- 部署与监控；
- 真实权限；
- 可能产生业务副作用的执行能力。

因此必须单独过门禁。

## 2. 静态蓝图已具备的前置

- 核心对象与Schema统一；
- Event Canonical边界明确；
- Task/Approval/Action/ExecutionResult等对象明确；
- TaskCenter V0、两个Aggregator V0已定义；
- 单产品纵向静态MVP已闭合；
- M0/M1实施路线、真值等级、依赖DAG已建立；
- M0-A/B/C、M1-A/B/C实现任务包已规格化；
- 大规模目录迁移明确不作为实现启动前置。

## 3. 进入真实实现前必须确认

### 工程环境
- 代码运行仓库/分支策略；
- CI测试入口；
- 配置管理；
- 日志/监控；
- Secret存储方式；
- 部署环境与回滚方式。

### 数据与身份
- 测试seller account / marketplace范围；
- 测试product_id；
- Amazon只读授权方式；
- 数据存储技术选型与备份策略；
- marketplace timezone。

### 安全
- 读取权限与写权限分离；
- Policy/Permission服务归属；
- 高风险动作默认禁止；
- 审批身份体系；
- Secret不得写入Git、Prompt或普通日志。

### 验收
- 明确首个M0验收产品；
- exact version/commit证据；
- 机器可验证读模型证据；
- 成熟度只按真值等级晋级。

## 4. 不需要等待的事项

以下不应阻塞第一批M0真实实现：
- 全部13个Agent运行化；
- 全部业务板块完成；
- 全仓库根目录迁移；
- 多站点/多账号；
- 自动经营写权限；
- 完整高级UI视觉实现。

## 5. 第一批启动范围

真实工程只应先启动：
1. ProductIdentity Store / Resolution；
2. Amazon只读Connector；
3. MetricSnapshot Store；
4. Time/Freshness/Metric Registry；
5. 一个最小ProductState读链；
6. ProductStateAggregator；
7. HomeCommandCenterAggregator；
8. 只读UI接口；
9. 测试与机器证据。

不在第一批启动：Executor、生产Ads写权限、自动审批。

## 6. 启动判定

只有当“工程环境 + Secret边界 + 测试账户/产品 + 只读授权 + 数据存储 + CI/验收”都有明确承载方式，才进入真实实现。

若其中任一项缺失，静态蓝图仍可视为完成，但真实实现应保持 WAITING_IMPLEMENTATION_PREREQUISITES，不通过猜测补齐。

## 7. L1结论

静态蓝图到真实实现的切换门禁与最小启动范围已明确。当前自动施工不越界触发真实实现。L1：PASS。
