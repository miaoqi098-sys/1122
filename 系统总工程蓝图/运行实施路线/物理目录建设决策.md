# 物理目录建设决策 V1

> 对应任务：RI-05
> 目的：明确进入真实实现时哪些目标工程域应建立正式物理目录，哪些仍不应因为蓝图存在就立即迁移旧仓库。

## 1. 当前决策

本阶段仍不执行全仓库根目录迁移、批量重命名或旧模块搬迁。

原因：
- 现有 Agent库、数据接口层、执行层、系统运行层等已有大量引用；
- 蓝图已能通过映射描述目标归属；
- 现在迁移不会增加 M0/M1 的验证能力，却会制造引用风险。

## 2. 真实实施前优先建立的工程域

当开始真实代码实现时，建议优先建立或明确以下正式工程域：

```text
数据系统/
任务中心/
政策边界/
对外连接/
记忆系统/
测试与验收/
```

建立条件：对应运行依赖进入真实实现任务，并有明确 README、职责和接口；禁止只创建空目录。

## 3. 可继续沿用现有目录的工程域

短期可沿用：
- `系统运行层/`
- `执行层/`
- `工具层/`
- `系统公共层/`
- `调度与自动化层/`
- `Agent库/`
- `UI界面设计板块/`

待真实接口稳定后再决定是否按目标编号目录迁移。

## 4. 需要拆分但不立即迁移的旧目录

### `数据接口层/`
未来语义拆分：
- 外部认证/Connector → 对外连接
- 标准化与入湖/事实对象 → 数据系统

### `记忆与数据层/`
未来语义拆分：
- Product/Metric事实 → 数据系统
- Memory/Timeline/StageSummary → 记忆系统

这些只是目标归属，不在当前无人值守批量搬文件。

## 5. 目录建立门禁

新一级正式目录建立前必须满足：
1. 有至少一个确认的真实实现任务；
2. 职责不能被现有目录完整承载；
3. README可定义输入/输出/边界；
4. 上下游引用已经明确；
5. 不需要同步大规模移动旧文件；
6. 创建动作可逆且不会破坏现有引用。

## 6. 大规模迁移触发条件

只有当：
- M0/M1关键服务接口稳定；
- 新旧目录映射明确；
- 有迁移清单和引用扫描；
- 有回滚方案；
- 用户明确授权高影响迁移；

才进入整体根目录重构。

## 7. L1结论

已确定“先实现能力、后迁移目录”的策略；不通过建空目录制造虚假工程进度。当前不触发高影响迁移。L1：PASS。
