# 产品运营中心 V1

## 目标

把“产品”从一个导航入口升级为 1122 的真实经营对象中心。用户进入一个产品后，应能从同一 ProductIdentity（产品身份）看到经营状态、异常、Agent 结论、任务和历史动作。

V1 先做只读，不直接执行 Amazon 写操作。

## 一、产品主对象

```text
ProductIdentity
├── product_id          1122 内部产品 ID
├── marketplace         US / CA / MX / BR ...
├── seller_id           Amazon Seller ID（后端）
├── parent_asin         父 ASIN，可空
├── asin                子 ASIN
├── sku                 Seller SKU
├── fnsku                FNSKU，可空
├── title
├── brand
├── status              active / inactive / suppressed / unknown
└── updated_at
```

任何销售、广告、库存、流量、利润、评价对象都必须能追溯到 `product_id + marketplace + asin/sku`，禁止仅靠标题关联。

## 二、产品运营中心首页

### 1. 产品清单
每行至少展示：
- 产品名
- ASIN / SKU
- Marketplace（站点）
- 当前经营阶段
- 当前目标
- 健康状态
- 待处理任务数
- 最近更新时间

### 2. 数据源状态
产品状态卡必须知道数据来自哪里：
- SP-API：第一方商品/库存/销售/价格
- Ads API：第一方广告
- Sif MCP：市场/关键词/竞品/流量
- Internal：成本/目标/供应链/人工输入

每个指标保留：`source`、`observed_at`、`freshness`，避免把不同时间的数据直接混算。

## 三、四个三级经营域

### A. 流量与转化
核心对象：
- Sessions / Page Views / Orders / Conversion
- Keyword Traffic
- Organic / Paid Traffic Mix
- Search Term / Keyword Signals
- Traffic Anomaly

主要来源：SP-API + Sif MCP + Ads API。

### B. 价格与促销
核心对象：
- Current Price
- Reference / Was Price
- Coupon
- Deal / Promotion
- Price History
- Promotion Conflict

主要来源：SP-API + Agent-10 + 内部活动计划。

### C. 利润与经营
核心对象：
- Revenue
- Amazon Fees
- Ad Spend
- FBA / Storage
- Product Cost
- Freight
- Contribution Profit
- Margin

主要来源：SP-API + Ads API + 内部成本数据 + Agent-6。

### D. 消费者体验
核心对象：
- Rating / Review Count
- VOC Themes
- Negative Experience Signals
- Return / Refund Signals
- Listing Content Issues

主要来源：SP-API/可用报告 + 评价数据源 + Agent-11。

## 四、状态卡统一结构

```text
ProductStatusCardView
├── identity
├── business_stage
├── current_goal
├── health
├── sales_snapshot
├── traffic_snapshot
├── ads_snapshot
├── price_snapshot
├── inventory_snapshot
├── profit_snapshot
├── experience_snapshot
├── active_events[]
├── agent_findings[]
├── pending_tasks[]
└── data_freshness[]
```

状态卡只聚合，不自己重新发明业务结论。专业判断来自对应 Agent，跨域最终结论来自 Agent-1。

## 五、真实数据接入顺序

### V1.1 产品身份
1. 从 Amazon 第一方数据建立 SKU / ASIN / Marketplace 清单；
2. 生成稳定 `product_id`；
3. UI 产品清单改用真实对象。

### V1.2 商品状态
接 Listing 状态、标题、价格、可售状态等基础字段。

### V1.3 库存 / FBA
接库存、在途、可售、补货风险。

### V1.4 Sif 市场信号
允许后端按授权产品或竞品调用预定义 Sif 工具，并将关键词/流量/竞品结果写入标准 Snapshot/Event，而不是把 MCP 原始响应直接塞给 UI。

### V1.5 Ads API
Ads API 审核完成后接自有 Campaign / Keyword / Spend / Sales，再升级广告域。

### V1.6 利润与任务闭环
成本数据 + 财务数据进入利润模型；Agent-1 产生 Task；执行器完成后回写 Validation。

## 六、安全边界

- 浏览器不保存 Amazon/Sif 长期密钥；
- 运营页面不开放任意 SP-API/MCP 代理；
- 只允许预定义业务查询；
- 写操作必须经过身份认证、权限和任务审批；
- 原始第三方响应进入数据层前先标准化并记录来源与时间。

## V1 验收标准

产品卡从“示例 UI”升级为“真实对象入口”的最低标准：
1. 至少一个真实 ProductIdentity 可被后端读取；
2. ASIN / SKU / Marketplace 可追溯；
3. 至少一个 SP-API Snapshot 与一个 Sif Snapshot 可挂到同一产品；
4. UI 能区分真实数据、待接入数据和示例数据；
5. 不存在前端长期密钥；
6. 不存在绕过 Task Center 的高影响写接口。
