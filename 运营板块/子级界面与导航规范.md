# 运营板块子级界面与导航规范

## 目标

运营驾驶舱负责“发现现在最值得处理的经营问题”，子级界面负责“深入某个经营域并完成分析、决策准备与任务发起”。

任何驾驶舱卡片都不应成为信息死胡同：只要某块内容未来需要深入查看，就必须存在明确的二级/三级入口。

## 二、导航原则

### 1. 驾驶舱只做总览，不承载完整明细
驾驶舱中的“库存与供应链”“流量与广告”“竞品与市场”等卡片必须提供“进入中心”入口。

### 2. 二级中心必须保留横向导航
所有二级中心顶部统一提供：

`运营驾驶舱 / 产品 / 库存物流 / 广告 / 竞品 / 站外推广`

用户进入任一子页后，可以直接横向切换，不要求层层返回。

### 3. 三级页必须有 Breadcrumb（面包屑）
例如：

`运营 / 产品 / 流量与转化`

并提供：
- 返回当前二级中心；
- 返回运营驾驶舱；
- 横向切换同级三级页。

### 4. 当前未接数据源的页面仍可建设
页面可以先展示：
- 目标指标；
- 数据来源；
- 当前接入状态；
- 后续 Agent；
- 当前阻塞原因。

但禁止使用虚假数字填充。

### 5. 真实数据与执行入口分离
子级页面可以展示真实数据与 Agent 结论，但高影响操作只能形成 Task，不允许页面直接绕过 Task Center 调用 Amazon 写接口。

## 三、数据与页面映射

| 页面 | 主要数据源 | 主要 Agent | 当前状态 |
|---|---|---|---|
| 产品/商品状态 | SP-API Listings / Pricing | Agent-2 | 已接第一阶段真实数据 |
| 产品/流量与转化 | SP-API + Sif + Ads API | Agent-5 | Sif 已连，第一方流量待补 |
| 产品/价格与促销 | SP-API + 内部活动计划 | Agent-10 | Listing Price 已接 |
| 产品/利润与经营 | Finance + Ads + Internal Cost | Agent-6 | 待接 Finance / 成本 |
| 产品/消费者体验 | Reviews/VOC/Returns | Agent-11 | 待接 |
| 库存物流 | FBA Inventory + Sales Velocity | 库存专业 Agent | 基础库存字段已接，V1.3 建模中 |
| 广告 | Amazon Ads API | Agent-4 | Ads API 待审核/授权 |
| 竞品 | Sif MCP + 1122-core D1 | Agent-3 | 批量竞品关键词工作台已接；通用竞品实体与自动投递待接 |
| 站外推广 | 官网/红人/内容/归因 | 站外运营流程 | 官网已上线，其他待接 |

## 四、UI 统一组件

每个二级中心至少包含：
1. Breadcrumb；
2. 运营横向导航；
3. 当前数据源状态；
4. 核心指标/状态卡；
5. 异常与机会区；
6. 对应三级入口；
7. Agent / Task 状态；
8. freshness（数据新鲜度）。

每个三级页面至少包含：
1. 二级中心返回入口；
2. 同级三级切换；
3. 指标定义；
4. 数据状态；
5. 诊断/异常区；
6. 决策/任务入口占位；
7. 数据来源与更新时间。
