# 运营驾驶舱 V2

## 一、定位

运营板块首页不是“模块目录”，而是 1122 的日常经营工作台。

实现上，运营驾驶舱已纳入 Web Console V2 的单一 Hash Router；广告工作台、连接设置和其他运营页面共享同一导航与路由注册表，不再作为并行网页维护。

用户进入运营板块后的第一屏必须回答 5 个问题：

1. 今天 / 最近经营结果怎么样？
2. 哪些产品、广告、库存或价格出现异常？
3. A1 与专业 Agent 认为现在最重要的事情是什么？
4. 哪些任务需要审批、执行或验证？
5. 当前数据是否完整、新鲜、可信？

因此首页按经营判断顺序组织，而不是按系统文件夹顺序组织。

## 三、首页展示原则

### 1. 真实数据优先

禁止把示例数字与真实数据混在一起。

每个指标必须有数据状态：

- `REAL`：真实数据
- `PENDING_SOURCE`：数据源未接入
- `STALE`：数据过期
- `DEGRADED`：降级数据
- `UNKNOWN`：无法判断

同时要分开呈现以下维度，不能用一个绿色状态替代全部维度：

- 路由 / 页面是否可用；
- 外部连接是否可达并完成授权；
- 数据是否为真实来源；
- 数据是否新鲜；
- 业务语义是否已经验证；
- 当前操作者是否通过会话鉴权；
- 该能力是只读还是允许写入。

### 2. 异常优先于平均值

运营首页不是 BI 报表墙。

首页更应突出：

- 发生了什么变化；
- 变化是否重要；
- 为什么重要；
- 下一步做什么；
- 是否需要审批。

### 3. A1 只显示最终经营决策

专业 Agent 的原始建议不直接占据首页最高优先级。

首页“今日经营重点”以 `FinalDecision` 为主，并标明：

- 来源事件；
- 影响产品 / Scope；
- 优先级；
- 风险；
- 当前状态；
- 下一动作。

### 4. Task 与 Decision 分离

页面必须区分：

- 已发现问题；
- 已形成决策；
- 已创建任务；
- 已执行；
- 已验证经营结果。

禁止“任务已执行”被展示成“经营目标已成功”。

### 5. 数据新鲜度必须可见

每个经营域都要显示 `freshness`。

数据过期时，系统应优先显示“数据不新鲜”，而不是继续展示看似精确的数字。

## 四、V2 当前可真实展示的数据

当前已具备：

### Amazon SP-API

- US ProductIdentity 数量；
- Listing 读取完成度；
- Title / Main Image / Price 读取完成度；
- FBA Inventory 基础数据已进入私有 KV；
- 数据更新时间。

### Sif MCP

- MCP 连接状态；
- 工具数量；
- 已验证真实 ASIN 数据查询能力。

### Amazon Ads API

- NA 区域已连接，已真实读取 4 个 Profiles；
- 当前真实 US Profile 返回 1 个 Campaign、2 个 Ad Groups；
- 当前仅开放 Profiles、Campaigns、Ad Groups 读取；
- Keywords、Targets、Search Terms、Reports 与全部广告写操作仍未开放；
- 数量属于最近一次真实读取快照，后续页面刷新必须同时显示检查时间、错误与新鲜度，禁止把旧值伪装为实时成功。

### Cloudflare 数据与部署

- D1 与 KV 可用；D1 可读不自动等于业务语义已验证；
- R2 未启用；
- Pages 当前从本地手工部署，不是 GitHub 自动发布。

### Email

- 当前状态为 `AUTH_REQUIRED`；
- 在认证配置完成并通过真实检查前，不计入健康连接。

### 订单 / 财务 / 利润

- 尚未正式接入；
- 首页显示数据源待接，而不是模拟销售额或利润。

## 六、当前阶段的展示策略

因为 1122 已改为 Private Repository（私有仓），源码公开风险已下降。

但当前网页运行层尚未完成内部身份认证，因此：

- Repository Private ≠ Web UI 已完成身份保护；
- SKU / ASIN / 库存 / 价格明细继续留在后端数据层；
- 当前运营首页先展示聚合真实状态；
- CORS allow-list 只控制浏览器跨域，不是登录鉴权；
- 待用户确认允许访问的身份后，再配置 Cloudflare Access 或等价会话鉴权；
- 完成会话鉴权后，再评估开放完整产品明细、价格、库存、广告与利润。

无论页面是否完成身份保护，当前生产写操作仍保持关闭。身份认证与写权限是两个独立安全门槛。
